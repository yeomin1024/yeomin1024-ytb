**한계 (솔직하게):**
1. **자막·썸네일을 받지 못했다.** 이 클라우드 환경의 네트워크 정책이 `www.youtube.com`·`i.ytimg.com`을 막는다 (ProxyError 403). 그래서 "대본 내용"은 자막 대신 **설명란·챕터·태그·댓글**로 봤다. 도입부 문장·말 속도·썸네일은 이번에 새로 세지 못했다 → 썸네일 규칙은 옛 판의 15개 직접 확인 결과를 그대로 쓴다 (`thumbnail_rules.md` v2.0). 자막을 받으려면 집 PC에서 `python3 tools/outlier_research.py stock` 을 돌리거나, 클라우드 환경 설정의 네트워크 허용 도메인에 두 주소를 넣는다 (6번).
2. **후보 목록(`candidates.csv`)이 지워졌다.** 성공 사례 수집 뒤에 돌린 `tools/run_analysis.sh` v1.0 이 `result/` 를 통째로 바꾸며 `result/outliers/` 까지 지웠다 (v1.1 에서 고침). 자세히 본 20개는 영상 ID로 다시 받았고(22단위, 숫자는 복구 시각 기준), 2-2·2-3의 비교 숫자는 지워지기 전에 같은 계산(`tools/outlier_stats.py` 와 같은 규칙 — 옛 후보로 결과가 같음을 확인)으로 낸 값이다. 다음 할당량에 `outlier_research.py stock --per-group 2 --top 20` → `outlier_stats.py stock` 으로 다시 확인한다 (6번).
3. **댓글 분류는 낱말 규칙이다** (`tools/outlier_stats.py` `COMMENT_CATS`). 한 댓글이 여러 갈래에 들 수 있고, '질문'에는 "왜 구제해주나요?" 같은 반문이 섞이며, AI를 다룬 영상(4·12위)에서는 'AI'가 비판으로 잘못 세진다. 그래서 갈래별 숫자는 방향만 보고, 결론은 인기 댓글을 직접 읽은 내용(3번 인용)으로 확인했다.
4. **"성공"은 조회수/구독자 배수다.** 구독자가 아주 적은 채널은 배수가 커진다 (1위는 구독자 5명·조회수 28.8만·좋아요 2·댓글 0 → 광고 의심으로 뺐다). 분석기의 "성공"은 같은 채널 최근 영상 중앙값의 3배라 정의가 다르다 (7번).
5. 표본이 작다 (요소마다 11~134개). 차이가 10%p 넘고 옛 자료와 같은 방향인 것만 규칙으로 만들었다.

## 9. 갱신 방법

1. `python3 tools/outlier_research.py stock --per-group 2 --top 20` (API 키, 약 3,700단위) → `result/outliers/`
2. `python3 tools/outlier_stats.py stock --skip-ranks <주제 밖·광고 의심 순위> --group …` → 2-2·2-3·3-1 표를 고친다. 사례 폴더 `comments.csv` 인기 댓글을 읽어 3-2~3-6 인용을 고친다.
3. `bash tools/run_analysis.sh stock` (v1.1부터 `result/outliers/` 를 지우지 않는다) → 7번 표.
4. 결론이 바뀐 항목만 4-1 표의 규칙 파일에 반영하고 각 파일 변경 이력에 "data_insights vX.Y 반영"으로 남긴다. 사용자 규칙과 부딪히면 4-2에 적는다.
5. 테스트 및 비교 결과는 `source/<영상ID>/titles.md`·`thumbnails/` 결과 칸에 적고, 쌓이면 5번에 요약한다.
