## 1. 쇼츠 자료 모으기 (웹 화면 v1.6 — `guides/pc_analysis.md` '쇼츠')

1. `powershell -ExecutionPolicy Bypass -File run_analyzer.ps1` (실행 명령은 같음 — 새 코드는 켤 때 저절로 받음. 켜 둔 창은 닫고 다시)
2. **4. 탐색** 제목 옆 **[롱폼 | 쇼츠]** 에서 **쇼츠** → 최근 N주(기본 8) → [탐색]
   - 검색어마다 **쇼츠 검색 1번**(4분 미만·조회수 순 — 100단위, 7일 캐시, 결과가 안 바뀌면 14·21일) + 추가한 채널의 **쇼츠 목록**(UUSH — 50개에 1단위) + 주소로 넣은 쇼츠
   - **쇼츠만 남김** = 3분 이하 + 세로·정사각 (화면비는 영상 정보와 같은 1단위 요청으로 받음). 가로 영상·3분 넘는 영상은 '뺀 것'에 수만
   - 검색어는 `<주제>/shorts_keywords.txt` 가 있으면 그것(한 줄에 하나), 없으면 롱폼과 같은 `keywords.txt`
3. **5. 쇼츠 목록** — 배수(조회수÷구독자) 높은 순, 추천은 체크만:
   - **성공 쇼츠** (올린 지 3~180일 · 구독자 5만 이하 · 조회수 5만 이상 · 조회수 ≥ 구독자×3) · **조회수 상위 20** (주제 관련) · 추가한 채널·주소
   - **'부풀림 의심'** 표시 = 조회수 5만 이상인데 좋아요 0.2% 미만 → 추천하지 않음 (광고로 샀거나 아주 짧은 쇼츠가 반복 재생된 조회수 — 2026-10-15 실측: '연금' 쇼츠 검색 위쪽을 6초짜리 7개가 덮었고 좋아요 0.03~0.06%)
4. **[쇼츠 승인]** → 자료 받기 → 채널 평소 쇼츠(채널 쇼츠 목록 최근 50개 — 채널 하나 약 2단위) → 쇼츠 분석 → **바로 GitHub** → 자막을 못 받은 쇼츠는 **음성인식을 뒤에서, 쇼츠 먼저** (3분 이하라 하나에 1~2분; 음악·화면 글자만 있으면 '말 없음'으로 끝 — 헛말 방지)
5. 6번 칸 **쇼츠 분석** 요약 · [쇼츠 성공 후보 체크] (자료를 받지 않은 성공 후보 — 4번 칸이 [쇼츠]일 때)

할당량 (하루 10,000 — 롱폼과 같은 키면 함께 씀): 쇼츠 탐색 = 검색어 수 × 100 (캐시는 0) + 영상 정보 50개에 1 · 승인 = 댓글 100개에 1 + 채널 하나 약 2. 모자라면 초기화(한국 오후 4~5시) 뒤 저절로 이어서.

## 3. 쇼츠 지시사항 만들기 규칙 (Claude)

- 근거는 **그 주제의 `shorts/analysis.md` 뿐** — 롱폼 결과(`../analysis.md`)나 다른 주제 결과를 빌려 규칙으로 만들지 않는다 (CLAUDE.md, 사용자 지시 2026-10-12). 롱폼 댓글 요청은 '주제 후보'로만 함께 본다
- **규칙으로 만들지 않는 것**: 표본 적음(묶음 15개 미만) 표시가 있는 차이 · 대본이 없는 사례로 센 첫 3초·끝맺음 · '부풀림 의심' 쇼츠 · '눈에 띔' 표시가 없는 작은 차이 → `shorts_insights.md` 에 "근거 없음"으로 적는다
- 숫자마다 근거 위치(절 번호·표 이름·n)를 적는다. 예: "첫 말 0.5초 안 — 6번 표, 성공 쇼츠 대본 23개 중앙값 0.3초 vs 나머지 1.2초"
- 같은 채널 기준선(1-2번)과 비교 집단(2·4·5번)이 서로 다르게 말하면 같은 채널 쪽을 먼저 믿는다 (채널 크기·구독층이 같음)
- 결과물 `<주제>/guides/shorts_insights.md`: ① 시청자가 가장 원하는 것(요청·질문 묶음 — 원문 인용) ② 쇼츠 주제 후보 표(요청 수·자동완성 틈·수요/공급 지수·성공 쇼츠 예) ③ 길이 범위 ④ 첫 3초 ⑤ 끝맺음·롱폼 연결 ⑥ 제목·해시태그 ⑦ 하지 말 것 ⑧ 근거 없음(자료가 더 필요한 것)

### 3-1. 빼는 쇼츠 — 돈 이야기가 아님 (v1.1)

- 조회수가 '사람·방송·운세' 덕인 쇼츠는 돈 정보 쇼츠의 근거가 못 된다. 주제마다 `<주제>/analysis_rules.toml` 에서 고친다 (코드 기본값 없음 — 설정은 주제마다 따로):
  - `[shorts_exclude]` 갈래별 정규식 — **운세·사주** · **연예·예능·드라마**(연예인·방송·영화 클립 — 돈 이야기를 해도 뺌) · **명언·인생조언**(제목에 돈 낱말이 있으면 남김 — `MONEY_RX`) · **정치**(해시태그 뺀 제목만) · **다른 뜻**('노후차'·'메달 연금'). 찾는 곳은 제목·설명 앞 300자·채널 이름 (영상 태그는 안 봄 — '#명언'·'#이재명' 태그가 붙은 주식 쇼츠까지 빠져서)
  - `[shorts_exclude_videos]` — 글자로 못 거른 것을 Claude 가 눈으로 보고 `"영상ID" = "갈래 — 까닭"`
  - `[shorts_needs] NOT_INFO_RX` — '더 알고 싶은 것'에서 뺄 정보 요청이 아닌 부탁 (띠·년생·재물복·로또·영입·노래·팬 …)
- 걸린 쇼츠는 성공·비교 집단·시장(수요와 공급)·같은 채널 기준선에서 모두 빠지고, 0번에 '돈 이야기 아님 — 갈래' 수, 1번 아래 '기준은 넘었지만 뺀 것'에 제목과 까닭이 나온다. **새 결과마다 1번 표를 훑어 새로 보이는 연예인 이름·운세 채널을 규칙에 더한다** (오탐도 확인 — 2026-10-15 '사주' 가 '자사주'·'사주신', '타로' 가 '단타로' 를 잡았었음)
- 10번 채널 유형은 채널 쇼츠 수를 모르는 채널을 비율에서 뺀다 (평소 쇼츠는 승인한 쇼츠의 채널만 받으므로 모르는 채널은 거의 다 성공이 아님)

### 3-2. 분석 결과가 옛 규칙일 때 — 다시 센다 (v1.2)

- `shorts/analysis.md` 첫 줄의 `shorts_analysis.py` 버전·규칙(`analysis_rules.toml`) 버전이 지금보다 옛것이면 그 숫자를 그대로 쓰지 않는다 (2026-10-15: v1.0 결과의 '노후·연금' 성공 15.6% 는 걸그룹·예능 클립 덕이었고, 지금 규칙으로 다시 세면 5.6%)
- PC 캐시(`.cache/shorts`)가 없는 클라우드에서는 `shorts/compare.csv` 에 지금 규칙(`shorts_analysis.off_kind`)을 덧대 다시 센다 — 설명은 받은 쇼츠(`S_*/description.txt`)에만 있어 근사다. `shorts_insights.md` 맨 위에 **다시 셌다는 것·근사인 곳**을 적고, PC 에서 다시 분석하면 새 숫자로 바꾼다

## 4. 롱폼으로 보내는 쇼츠 만들기 (v1.3 — 프롤로그형)

롱폼 하나에 쇼츠 하나. 쇼츠를 본 사람이 '관련 동영상' 링크로 롱폼에 들어오게 한다. 근거·숫자는 그 주제 `guides/shorts_insights.md` (재테크: 2026-10-15 노후 영상 4편 — `economic/source/<영상ID>/shorts/`).

1. **주제 = 롱폼의 돈 문제 하나** — 롱폼의 **가상 사례(예: A·B 부부)** 하나로 보여 준다 (v1.3 — 예전 v1.2 는 롱폼 결론(원칙)을 50초에 맞게 줄였다). '노후 준비' 같은 넓은 말 대신 금액이 붙은 한 장면 (재테크 근거: 작은 채널 노후·연금 쇼츠 성공 5.6%, 대상 낱말 −10%p ⚑)
2. **프롤로그형 — 핵심 정보는 롱폼에 둔다** (사용자 지시 2026-10-16): 롱폼이 답하는 '왜·어떻게(방법·기준 금액·할 일)'는 대본에도 화면에도 넣지 않는다. 순서는
   ① **메시지** — 첫 마디에 결과 숫자 (예: "같은 5억 원을 모았는데, 은퇴 첫해에 세금만 334만 원을 낸 부부가 있습니다.")
   ② **배경** — 같은 조건 한두 문장 (나이·국민연금·생활비)
   ③ **알게 된 경위** — 짧게, **롱폼 대본에 있는 사실만** 이야기 순서로 (예: '건보료 고지서는 다음 해에 나온다' → 다음 해 고지서로 알게 됨). 대본에 없는 장면(누구와 비교했는지 등)은 지어 넣지 않는다
   ④ **걸린 것** — 이대로 가면 얼마 (평생 숫자 등)
   ⑤ **질문** — "지금이라도 되돌릴 수 있을까요?" ⑥ **롱폼 안내** — "…아래 영상에서 확인하세요."
   - 이야기는 쇼츠 안에서 끝나게(결과·경위·걸린 것까지) 하고, 숨기는 것은 '왜'와 '고치는 법'뿐이다.
   - ⚠️ 근거와 반대 방향이다: 닮은 쇼츠 댓글 「본편에서 공개가 짜증나서 걍 안봄」 👍367 (재테크 `shorts_insights.md` 5번) → 제목·설명란이 '이유'를 약속하지 않게 하고(5번), 올린 뒤 관련 동영상 클릭·본 비율·'본편 공개' 불만 댓글을 `shorts_insights.md` 8번에 적어 확인한다.
   - (v1.2 의 '답을 쇼츠 안에서 다 말한다'는 2026-10-16 사용자 지시로 바뀜 — 사용자가 다시 정하면 되돌린다)
3. 숫자·사실은 **그 롱폼 `README.md` 숫자 근거 표에 있는 것만** (롱폼에서 오늘 시행 중인 법령 원문·계산 코드로 확인한 것). 조건이 붙는 말은 조건까지. `shorts.md` 5번 표에 숫자마다 롱폼 근거를 적는다
4. 대본: 진행자 목소리(H04) 하나, 3인칭 사례('두 부부'), 첫 마디가 숫자 비교, `script_guide.md` 0번 피드백(조사·기준 이름과 금액·숫자 근거·한 문장 한 뜻), 길이는 `shorts_insights.md` 의 범위(재테크 50~55초 = 약 285~315음절, 5.73음절/초). **끝 문장만** 롱폼 안내("…은 아래 영상에 있습니다"), 롱폼 끝인사("시청해주셔서 감사합니다.")는 넣지 않음
5. 제목은 R1(추천)·R2 두 개, `shorts_insights.md` 3번 모양·뺄 낱말을 따른다. 숫자는 대본이 말한다. 화면 글자는 `video_guide.md` 색(빨강 손해·청록 아낌·노랑 기준)
   - (v1.3) 프롤로그형이면 **'이유'를 제목에 쓰지 않는다** (쇼츠가 이유를 말하지 않으므로 약속하지 않음). 금액·말줄임·사연 꼴로 (예: 「같은 5억인데 첫해 세금 334만 원… 건보료 고지서까지」)
6. 설명란 = 상황·결과 한 줄(프롤로그형은 결론을 쓰지 않음) + '두 부부가 무엇이 달랐는지는 관련 동영상에서' + 고지(가상 사례·기준일·AI 음성·상담 아님) + 해시태그(`shorts_insights.md` 4번 개수·뺄 태그, 답을 내비치는 태그는 뺌)
7. 올리기: **롱폼이 공개된 뒤**, '관련 동영상' = 그 롱폼(쇼츠 설명란·댓글 주소는 눌리지 않음), 변경되거나 합성된 콘텐츠 = 예, 네 편이면 날을 나눠 하나씩. 올린 뒤 스튜디오 숫자(관련 동영상 클릭·본 비율)를 `shorts_insights.md` '근거 없음' 표에 채운다
8. 내레이션: 지금 `tools/tts_narration.py` 는 `<영상ID>/<영상ID>.txt` 만 읽어 `shorts/<영상ID>-shorts.txt` 는 저절로 만들지 않는다 — 쇼츠 오디오를 만들 때 도구에 붙인다 (사용자가 정함)

## 5. API 로 볼 수 없는 것 (한계)

- 쇼츠 알고리즘의 핵심 신호 — 피드에서 '본 비율 vs 넘긴 비율', 평균 시청 비율, 다시 재생 수 — 는 남의 영상은 볼 수 없다 (YouTube Studio 는 내 채널만)
- 쇼츠 조회수는 **2025-03-31 부터 '재생·다시 재생 횟수'** (시청 시간 하한 없음) — 그 전 숫자와 바로 비교하지 않는다. 아주 짧은 쇼츠는 한 사람이 여러 번 셀 수 있다
- 화면 글자(자막 띠·제목 카드)·음악·편집 속도 — 다른 사람의 영상 파일은 받지 않으므로(CLAUDE.md) 셀 수 없다. 표지 그림과 대본으로만 가늠한다
- 내 쇼츠를 올린 뒤에는 스튜디오의 '본 비율'·'평균 시청 비율'을 업로드 기록에 적어 다음 지시사항의 근거로 쓴다 (`guides/upload_guide.md` 7번처럼)
