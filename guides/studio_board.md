| 순서 | 단계 (db `gates` 의 stage) | 판 화면 | 다음 단계로 가는 조건 |

- **화면마다 그 단계에서 기다리는 편만** (v1.1): 1 주제 = 주제 · 2 = 대본·음성 · 3 = 제목 · 4 = 썸네일 · 5 = 코드 테스트·영상 · 6 = 업로드 (v1.11) (+ 준비 완료·올린 편은 기록·다시 올리기용으로 따로). 지금 단계 = 앞에서부터 아직 통과 안 한 첫 단계.
- **v1.3 단추 둘** (체크 상자 대신): **[✓ ○○ 통과 → 다음 단계]** = 지금 단계 `pass: true` → 편이 다음 단계로 가고 화면도 그 단계 칸으로 따라감 (같은 칸 안 단계 — 대본→음성·코드 테스트→영상 — 이면 그 칸에 그대로) · **[← 이전 단계 (○○)]** = 바로 앞 단계 `pass: false` → 편이 앞 단계로 돌아가고 화면도 그 칸으로 · 업로드 준비 완료 편은 [← 준비 취소]. 두 단계 뒤로는 그 칸에서 한 번 더.
- **판 체크가 늘 이김.** 판에서 체크하지 않은 편은 저장소 기준(이미 만든 것 — 제목·썸네일 파일·페르소나 기록·음성·장면 파일·video.json·youtube.json)이 기본값.
- 앞 단계가 통과가 아니면 뒤 단계 체크는 무효 (판이 막고, `gates.json` 의 `pass` 도 앞 단계까지 모두 통과일 때만 true).
- **Claude 는 `studio/state/gates.json` 에서 그 편의 앞 단계가 `pass: true` 인 것만 다음 단계 작업** (v1.11 대본 → 제목 → 썸네일 → 음성 → …). 판 후보(`episodes`)는 주제 통과 뒤 Claude 가 대본 폴더를 만듦 (영상ID = `<이름>-YYYY-MM-DD`).

- **이 동작은 판 설계다 (v1.4)** — 규칙 목록에 '통과를 누른 것만 다음 단계'를 규칙으로 적지 않는다. 판이 단계마다 그렇게 움직이고, Claude 는 `gates.json` 만 본다.

2. `python3 tools/studio_board.py sync <그 폴더>` → `studio/state/` 에

   - `gates.json` 단계 통과 (편마다 · 판/저장소 기준 표시)
   - `trends.json` 트렌드 검색어 — v1.3 주제마다 `groups`(판 링크와 같은 묶음) · `rows`(줄) · `time`·`gprop` · `csv`(올린 수/필요 수·완료) (PC `-TrendsWatch` 가 GitHub 에서 읽음)
   - **v1.3 판에서 올린 CSV** → `<주제>/result/next_topic/board_csv/r<줄>_p<링크>.csv` + `index.json` (지금 줄 단어·기간·대상과 같은 것만 · 다르면 `[TREND_CSV]` 경고로 빼고 판에 '다시 올리기') — 다음 주제 탐색(`tools/next_topic.py` 판단 · 기획안 `basis`)의 트렌드 근거

3. 로그 `[FEEDBACK]` (status=new) 마다 반영 (제목·썸네일 문구 → package.json·업로드 시트 / 대본 줄 → 대본 TXT — 바꿀 때마다 페르소나 반복 검증 `guides/persona_loop.md`) → 판 db 그 문서 `status: "done"`, `reply` 한 줄 (ArtifactData update, if_version)
4. 고정 채널(`channels` status=new) → 분석에 더한 뒤 `done`·`reply` (위기는 독립 분석이라 `crisis/code/crisis_lab.py` 쪽)
5. `git commit` · `git pull --rebase` · `git push` (main) → `build` → 같은 주소로 발행

## 4. 화면별 — 무엇을 어디서

- **v1.3 화면 꼴**: 단계 칸마다 위에 **[작업] · [규칙 · 결과]** — 하나를 골라 넓게 (판이 기억). 작업 = 편 카드·단추·피드백·체크 · 규칙 · 결과 = 그 단계 규칙(고치기·빼기·더하기) + 분석 결과(성공 사례·낱말·탐색 문서·트렌드 결과·업로드 기록). '공통' 칸은 없음 — 동기화 안 된 건수는 머리 띠 한 줄, 주제 켜기·끄기·단계별 편 수는 머리 띠 [주제 켜기·끄기].

## 4-1. 구글 트렌드 (1 주제 탐색 › 작업, v1.3)

1. 줄마다 단어 칸 **8개** (기본 = 그 주제 검색어를 8개씩 — 아직 저장 전) → **[링크 생성]** → 그 단어가 들어간 구글 트렌드 링크 (한국 · 기간 · 유튜브/웹 검색 — 위 고르기).
   - **판 링크 = 새 탐색 화면 `https://trends.google.com/explore?date=<기간>&geo=KR[&gprop=youtube]&hl=ko&q=<단어,…>`** (사용자가 준 주소 꼴 — 8개까지) → 줄 하나 = 링크 하나 (`studio_board.py` `trend_groups` · 판 `trendParts` 같은 규칙).
     - 옛 `trends.google.com/trends/explore?q=…` 는 5개까지만 열림 — 6개 넘게 넣으면 오류 화면('죄송합니다. 이 페이지를 표시하는 중에 문제가 발생했습니다', v1.7 에 겪음). v1.7.1 은 5개씩 둘로 나눴고, v1.8 에 새 주소로 하나.
     - 사용자가 준 주소의 q 는 주제 ID(`/m/…`)였지만 판은 낱말 그대로 넣음 · `gprop=youtube`(유튜브 검색)가 새 화면에서 먹는지는 열어 보고 확인 — 오류면 판 '대상'을 웹 검색으로.
   - PC `pc_trends.py` v1.5 (자동 받기)는 탐색 API 가 5개까지로 확인된 것만 쓰므로 8개 묶음을 [앞 5개] + [첫 단어 + 나머지] 로 나눠 받음 (`api_groups` — 낱말을 빼지 않음).
   - 저장 전 기본 줄은 처음 [링크 생성]·[줄 더하기] 때 모두 함께 저장 (db `trend_rows` `<주제>.r<…>`). [줄 지우기] = `deleted: true` + 그 줄 CSV 지움.
2. 링크 열기 → 그래프 오른쪽 위 ⤓ (CSV 다운로드) → 그 링크의 **[CSV 올리기]** (여러 개는 [CSV 여러 개 한 번에 올리기] — CSV 안 단어로 맞는 링크를 찾음).
   - 판이 CSV 머리 줄 단어를 링크 단어와 맞춰 봄 (띄어쓰기·대소문자 무시) — 다르면 저장하지 않음 · 200KB 까지 (db 문서 한도 256KiB) · db `trend_csv` `<줄 id>.p1` {q, time, gprop, file, text} (v1.8 부터 줄마다 p1 하나).
   - 새 탐색 화면 CSV 꼴도 읽음 (따옴표 칸 · 머리 '날짜'/'Date' · 단어 꼬리 ': (대한민국)'/'(대한민국)' · `<1` = 0.5).
   - 기간·대상을 바꾸거나 줄 단어를 바꿔 [링크 생성]하면 옛 CSV 는 'CSV 가 지금 단어·기간과 다름 — 다시 올리기'.
3. 줄의 링크 CSV 가 모두 오면 줄에 **완료** · 모든 줄이면 머리에 **완료 — CSV n/n**. 결과 표(평균·최근 4칸·앞 4칸 대비·선 그래프)는 링크 아래 '결과 보기'와 [규칙 · 결과] 칸.
5. **단어 고르는 법 (v1.5 — 규칙 topic.c16)**: 실제 검색어(`<주제>/keywords.txt` — 영상 태그에서 뽑음)에서 고름 · 한 줄 = 같은 갈래 + 비슷한 크기(`<주제>/tag_candidates.md` 태그 쓴 채널 수 — 검색 수의 대리 지표) · 기준 단어 = 중간 크기 대표 낱말을 모든 줄 첫 칸에 · 큰 말과 아주 작은 말을 한 링크에 섞지 않음 (작은 쪽이 0~1로 눌림). 재테크 예(2026-11-28): 기준 '연금저축'(채널 25) · ① 큰 말 38~99 ② 연금·노후 18~29 ③ 돈 모으기 17~32 ④ 투자 방법 20~33 ⑤ 배당·ETF(주식 태그) 6~17.
4. Claude 동기화 → `board_csv/` 로 저장소에 (3번) · PC `-TrendsWatch` 를 켜 두면 같은 묶음을 간격마다 저절로 받음(선택 — 접힌 'PC 가 간격마다 저절로 받기', 간격 고르기도 거기) · 새 분야(`new`) 주제면 전체 탐색 분류 번호 설정도 거기.
