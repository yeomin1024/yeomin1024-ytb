버전: v2.0 — 2026-10-12 — 사용자 지시: 작은 채널·최근 성공 사례와 댓글의 시청자 니즈 중심으로 다시, 주식에서 빌린 근거 정리 (v1.0 — 2026-10-11 — 최초 작성: 분석 실행 `20261011_120632`)

대본·제목·썸네일 지시사항이 "분석 근거"라고 적은 숫자는 모두 이 파일에서 온다.
이 파일은 **자기계발 주제의 자료로만** 쓴다 (`guides/pipeline.md` 2단계 2번). 다른 주제(주식 등) 결과는 빌리지 않는다. 자료가 없으면 "근거 없음 — 다음 수집 때 확인"이라고 적고 규칙으로 만들지 않는다.

## 0. 자료와 한계

**자료**
- 영상: 분석기 실행 `20261011_120632`(2026-10-11, 클라우드, 키워드 48개 중 13개)의 `result/data/videos.csv` 473개. 여기서 `tools/outlier_research.py --from-existing`(2026-10-12)이 작은 채널 성공 사례를 골랐다 → `result/outliers/` (`summary.md`, `outliers.csv`, `candidates.csv` 473개, 사례 폴더 5개).

- 썸네일: 성공 사례 9개 + 비교군 8개를 Claude가 직접 봤다 (사례 폴더 `thumbnail.jpg`, 나머지는 i.ytimg.com에서 받아 봤고 저장소에는 넣지 않음).

**한계 — 단정하지 말고 방향으로만 읽는다**

2. 수집 기준(`pipeline.md` 1단계 4번)은 "최근 180일"이지만, 이번 자료에서 180일 안 사례는 2개(2일·40일)뿐이라 730일로 넓혔다. 9개 모두 2025-09-21 이후 업로드다.
3. **자막(대본) 없음** — 클라우드 IP에서 막혀 건너뜀. 도입부 문장·말 속도·해결이 시작되는 시점은 모른다.
4. **설명란·챕터 없음** (`description.txt`가 비어 있음).
5. 댓글은 9개 중 6개만 있다 (A1·A2·A3·B1·B2·B3). A4 브레인바이츠·A5 강병준·B4 정세라는 댓글 자료가 없다.

7. 형식(그림 해설·얼굴 강의 등)은 영상이 아니라 썸네일·제목·채널명·태그·댓글로 짐작했다.
8. 새 수집(최근 180일 검색)은 YouTube Data API 키가 필요하다 → 다음 세션 `python3 tools/outlier_research.py selfdev`, 자막은 집 PC (6번).
9. 분석기의 `success_cases`(8개)는 쇼츠 4개와 구독자 135만·204만 채널이 섞여 있어 **근거로 쓰지 않는다** (7번 참고 통계로만).

### 4-3. 사용자 결정 필요

1. **제목 뒤 구절.** 작은 채널 성공 9개 중 5개가 "쉽고 빠른 변화 약속"(나머지 6%), 5개가 "방법·법·해법"(나머지 36%)이다. 공통 `title_guide.md` 6번("~하는 방법" 마무리 = 나쁨, 주식 피드백)과 채널 공식(손실 숫자 반전 + 결말 장치 4개)과 반대 방향이다. → 영상마다 T2나 T3 하나를 "손실 사연 + 쉬운 해결 약속"(예: "…사람들이 놓친 의외로 간단한 순서")으로 시험할지? 결정 전까지 기존 금지를 따른다.

3. **번아웃 주제.** 지금 보류. 작은 채널 성공 1개(B3, 채널 평소 4.3배), 전체 댓글 번아웃·무기력 97개(대부분 큰 채널, "쉬면 누가 돈 벌어요" 738). 의학 상담 영역이다. "그만둘 수 없는 사람" 전제로 열지?

## 5. 지난 판(v1.0)에서 고친 것

3. **댓글:** 단어 빈도 → 질문·고민·요청·칭찬·비판으로 나누고 좋아요를 같이 셈, 작은 채널 댓글과 큰 채널 댓글을 나눔. v1.0이 인용한 큰 숫자 댓글 상당수는 큰 채널이었다: "조용한 번아웃 8년째"(1,284)·"쉬면 누가 돈 벌어요"(738)·영양제(536) = 닥터프렌즈(143만), "숏폼이 없는 어린시절"(1,440)·"스크린타임 6시간따리"(1,332)·"21분짜리 영상을 끝까지 못 봄"(1,045) = EBS 컬렉션(135만), "재테크를 5년만 더 빨리"(239) = 뿅글이(48만), "삼십분만 일찍 일어나자"(101) = 책과삶(125만).

6. "롱폼 성공 10개 중 6개가 뇌·심리 연구"는 큰 채널(EBS·데일리어썸) 포함 숫자 → 작은 채널 9개 중 6개로 다시 셈 (같은 방향).
7. "~하는 나" 도입 근거는 EBS(135만) 제목이었다 → 작은 채널 댓글(3-4)로 바꿈.

## 9. 갱신 방법

1. `python3 tools/outlier_research.py selfdev` (API 키)로 `result/outliers/`가 바뀌면 1번 표를 새 사례로 바꾼다. 엄격 기준 사례가 10개를 넘으면 넓은 기준(B)은 뺀다.
2. 2-1 제목: 성공 사례 vs `candidates.csv`의 같은 기간 롱폼 나머지를 같은 요소로 센다. 2-3 썸네일: 사례 폴더 `thumbnail.jpg`와 비교군을 직접 본다.
3. 3번 댓글: 사례 폴더 `comments.csv`(+ `result/data/audience_comments.csv`)를 같은 갈래로 다시 센다. 작은 채널 댓글과 큰 채널 댓글을 나누고, 대표 인용은 직접 읽고 고른다 (60자 이내, 좋아요 함께).
4. 결론이 바뀐 항목만 4-1 표의 규칙 파일에 반영하고, 각 파일 변경 이력에 "data_insights vX.Y 반영"으로 남긴다. 4-3 사용자 결정이 나오면 그 결정을 규칙 파일에 적고 여기서 지운다.
5. 업로드한 우리 영상 성과(스튜디오 수치, 테스트 및 비교)는 쌓이면 새 절로 요약한다.
6. 분석기를 다시 돌리면(`bash tools/run_analysis.sh selfdev`) 7번 참고 통계만 고친다.
