## 0. 언제 쓰나 · 무엇이 먼저인가

- 주인공(가상 인물 — 설정 `stock/story/protagonist.md`)이 **1인칭으로 직접 말하는** 주식 영상의 대본에 쓴다.
- 읽는 순서: **이 파일** → `stock/guides/README.md` 5번(숫자 말하기 1~10 · 매수/매도) → `stock/guides/concept.md`(백테스트 규칙) → 공통 `guides/script_guide.md` 0번 피드백 1~21.
- 이 파일이 **다르게 정하는 것** (나머지는 위 문서 그대로):

| 항목 | 지금까지 주식·공통 규칙 | 이야기형 |
|---|---|---|
| 말하는 사람 | 진행자 · 사례는 3인칭('A 부부는…') | **주인공 '저'** (목소리는 진행자 H17 하나 그대로) |
| 도입 | 니즈 → 질문 → '백테스트로 확인해 보겠습니다' + 규칙, 20초(늦어도 30초) | **혼잣말, 목표 30초 · 마지노선 35초** (2-1) |
| 본문 | 경주(실시간 비교) 해설 | **방법마다 '첫 번째는 ~요.' → 내 문제 → 해결 → 근거** (2-2) |
| 끝 | 종합 → 결론 → 한계 → 끝인사 | **'정리해볼게요.' + 말 없는 정리 카드 → 다짐 → 응원 → 끝인사** (2-3) |
| 말투 | 합니다체·해요체 섞임 | **해요체 중심** (~요·~죠·~거든요·~더라고요) |

- 그대로 지키는 것: 숫자는 코드 출력·원문만 · 미래 정보 금지 등 백테스트 규칙 · 사다/팔다 → 매수/매도 · 티커는 처음에 무엇을 따라가는 ETF인지 · 개별 종목을 추천하지 않음 · 마지막 문장 "시청해주셔서 감사합니다."

## 1. 주인공 · 말투 · 낱말

### 1-1. 주인공 설정은 한 곳에서만
- 이름·나이·가족·직장·투자금·잃은 돈·연표는 `stock/story/protagonist.md` 의 값만 쓴다. 대본에서 새로 지어내지 않는다.
- 새 사건이 필요하면 **설정 파일 '연표'에 먼저 더하고** 그 값을 쓴다. 그래야 영상끼리 숫자가 어긋나지 않는다.
- 영상은 **종이인형극**이다 (일본 축제 영상과 같은 방식 — `video/render/puppet.js`). 주인공 인형은 `stock/story/puppet/` 의 7장만 쓴다 (설정 8번).
  - 인형은 **모두 표정이 있다** (오린 색종이 얼굴 — 설정 8번). 표정은 코드로 바꿀 수 없어 자세·표정마다 한 장이다.
  - 대본의 감정 문장과 그 장면 인형의 표정을 맞춘다: 절망 = PHONE · 답답함 = DESPAIR · 다짐 = RESOLVE · 깨달음 = BACK · 응원 = SMILE.
  - 마무리의 응원 문장('여러분의 투자도 …')에서는 SMILE 로 바꾼다.

### 1-2. 가상 인물이라고 밝힌다
- 설명란 첫 설명 바로 아래에 쓴다: "이 영상의 주인공은 개미 투자자 평균 통계로 만든 가상 인물이고, 이야기는 각색입니다."
- 진행자나 채널 운영자의 실제 경험처럼 말하지 않는다. 이 영상의 '저'는 주인공이다 (CLAUDE.md '진행자 경험을 지어내지 않는다'와 맞춤).
- '변경되거나 합성된 콘텐츠' = 예 (AI 음성·AI 그림) — 그대로.

### 1-3. 말투 — 친근하지만 공손하게
- 문장 끝: ~요 · ~죠 · ~거든요 · ~더라고요 · ~네요 · ~잖아요 · ~(이)에요 · ~(으)ㄹ게요.
  - 예: "또 파란불이네요." · "그때는 몰랐죠." · "제가 한 종목에 전부 넣었거든요."
- 도입의 혼잣말도 해요체로 끝맺는다. 반말(~다. ~야. ~지. ~어.)은 쓰지 않는다.
- 합니다체(~습니다·~입니다)는 끝인사와 꼭 필요한 곳만 (영상 하나에 5문장 이하).
- 시청자는 '여러분'이라고 부른다.
- 감탄사(하… · 휴…)는 영상 하나에 2번 이하. TTS 가 어색하게 읽을 수 있어 오디오로 확인한다.

### 1-4. 개미 투자자 낱말
- **풀이 없이 그대로 쓴다**: 매수 · 매도 · 손절 · 익절 · 수익률 · 원금 · 계좌 · 평단 · 상승장 · 하락장 · 반등 · 고점 · 저점 · 분할 매수 · 적립식 · ETF · 배당 · 레버리지 · 종목 · 주가.
- **처음 나오는 문장 안에서 뜻을 붙인다** (처음 시작한 개미도 알아듣고, 자막 번역이 뜻으로 옮겨진다):
  - 물타기 (떨어질 때 더 매수해서 평단을 낮추는 것) · 불타기 (오를 때 더 매수하는 것) · 몰빵 (한 종목에 전부) · 존버 (손해를 보고도 버티는 것) · 빚투 (빌린 돈으로 투자) · 신용 (증권사에서 빌린 돈) · 반대매매 (빌린 돈을 못 갚으면 증권사가 주식을 강제로 매도하는 것) · 리딩방 (종목을 찍어 준다는 유료 대화방) · 테마주 (소문과 이야기로 오르내리는 종목) · 상폐 (상장 폐지).
  - 예: "저는 떨어질 때마다 더 매수했어요. 평단을 낮추려는 물타기였죠."
  - `story_check.py` 가 이 낱말이 처음 나온 문장을 보여 준다 → 뜻을 붙였는지 사람이 본다.
- **쓰지 않는다**:
  - 떡상·떡락 (→ 급등·급락), 가즈아 같은 유행어 — 번역이 안 되고 공손한 말투와 맞지 않는다.
  - 자해·극단적 선택을 떠올리게 하는 말과 농담 (예: '한강'). 절망은 생활 장면으로 그린다 — "밤에 잠이 안 와요" · "계좌를 못 열겠더라고요".
  - 사다·팔다 → 매수·매도 (주식 README 5번). 장보기 같은 비유 속 '사다'는 그대로.

## 2. 구성

파트 라벨(`-` 로 시작하는 줄)은 이 순서로 쓴다: **`-도입` → `-방법1` … `-방법N` → `-정리` → `-마무리`**.
- 라벨에 '사연'이라는 낱말을 쓰지 않는다 (사연자 목소리 파트로 읽힘 — `srt_tool.STORY_WORD`).
- `-마무리` 라벨은 꼭 있어야 한다. `[장면]` 카드 문구는 다음 라벨이 나올 때까지 이어지기 때문이다(`srt_tool.parse_txt`). 라벨이 없으면 카드 뒤의 다짐·인사가 카드 글자로 먹혀 읽히지 않는다.
- 길이: 주식 규칙 그대로 **7~12분**. 진행자 H17 은 약 6.3음절/초라서 읽는 음절 약 2,400~4,100 (문장 사이 쉼 포함 추정).

### 2-1. 도입 — 목표 30초 · 마지노선 35초 (v1.7)

네 박자를 차례로 쓴다.

| 박자 | 하는 일 | 문장 수 |
|---|---|---|
| ① 상황 | 지금 처한 상황을 **혼잣말로, 절망적으로**. **첫 문장에 제목 맨 앞 낱말을 그대로** 넣는다(제목에 숫자가 있으면 같은 값도 도입에) — 제목을 보고 들어온 사람이 '맞게 왔다'고 바로 알게. **그 나이대(주인공 40대)가 흔히 하는 걱정**을 함께 — 회사 언제까지·아이 교육비·노후·집·가족에게 말 못 한 손실 (v1.4) | 2~4 |
| ② 답답함 | 답답한 심정 | 1 |
| ③ 다짐 | 마음을 다잡고, 처음부터 복기해서 올바른 방법을 찾겠다 | 1 |
| ④ 찾음 | 방법을 찾으려고 무엇을 했는지(무엇을 읽고, 무엇을 백테스트했는지) + 드디어 찾았다. **방법 이름과 결과는 말하지 않는다** (본론에서) | 1~2 |

- 길이: 문장 5~7개, 읽는 음절 200 이하. 추정 시간 = 음절 ÷ 6.3 + 문장 사이 0.45초 → **목표 30초, 마지노선 35초** (v1.7 — 사용자 지시 2026-10-23 "도입 마지노선 35초로해"; 사용자가 통과시킨 도입은 제작안에 `- 도입 통과: <날짜> 사용자` 줄 → 35초를 넘어도 경고만. 그 전 v1.4 — 사용자 지시 2026-10-22 "초반 30초로 하고 좀 더 그 또래 많이 하는 걱정, 공감되는 걱정으로 작성해 / 해결 방법도 자주하는 공통 문제 찾아서 해결하는걸로하고 / 화면 내용은 좀 빼고 눈에 잘 안들어와").
  - 오디오가 오면 `-방법1` 첫 문장의 실제 시각으로 다시 본다 (render check 도 35초). 35초를 넘으면 상황을 줄인다.
- 걱정은 시청자가 '내 얘기'라고 느낄 것으로 고른다 — 주식 분석 댓글에 많이 나오는 말(원금·손실 · 노후 · 은퇴·퇴직)을 먼저. 숫자를 붙이지 않는 생활 장면으로 ("딸 학원비는 매달 나가요").
- 첫 문장의 숫자(잃은 돈·%·연도)는 주인공 설정의 값이다.
- 화면: 도입에서는 방법 이름과 결과 숫자를 보여 주지 않는다 (주식 README 5번).
- 예 (제목이 「반토막 계좌, 6년 만에 찾은 매수 원칙 3가지」일 때 — 숫자는 예시):
  ```
  -도입
  반토막 난 계좌를 오늘도 열어 봤어요.
  6년 동안 넣은 돈의 절반이 사라졌죠.
  아내에게는 아직 말도 못 했어요.
  왜 나만 이럴까, 정말 답답하더라고요.
  그래도 처음부터 다시 복기해 보기로 했어요.
  책과 자료를 읽고 백테스트도 돌려서, 드디어 방법을 찾았어요.
  ```
  (6문장 · 101음절 · 추정 18.3초 — `story_check.py`)

### 2-2. 찾은 방법 — 방법 하나에 파트 하나

방법은 3~5개. 한 파트에 대략 1~2.5분.

**방법 = 개미들이 자주 겪는 공통 문제 하나를 푸는 것** (v1.4 — 사용자 지시 2026-10-22 "해결 방법도 자주하는 공통 문제 찾아서 해결하는걸로하고"). 주인공만의 특이한 사건이 아니라, 많은 시청자가 겪는 문제를 고른다.
- 근거: 연구·통계(자본시장연구원 잦은 매매 · 손실 계좌 비율 등)나 관심 많은 댓글(좋아요 수)로 '자주 겪는다'를 보인다.
- 순서: 방법 한 구절 → **"많은 개미가 …" 공통 문제** → "저도 그랬어요"(주인공의 그 사건, 짧게) → 해결(어떻게) → 근거.

파트마다 이 순서로 쓴다.

1. **첫 문장 = 방법 한 구절**: "첫 번째는 ○○예요." · "두 번째는 ○○이에요." … 마지막은 "마지막 ○ 번째는 ○○예요."도 된다.
   - 무엇을 어떻게 하는지가 그 문장에 들어 있어야 한다 (공통 피드백 — 애매한 말 금지).
   - ✗ "원칙을 지키는 거예요." → ✓ "한 종목에 계좌의 10%까지만 넣는 거예요."
2. **내 문제** 2~4문장: 그때 내가 무엇을 했고, 얼마를 잃었는지. 설정 연표의 사건과 숫자를 쓴다.
3. **해결**: 찾은 방법이 그 문제를 어떻게 막는지. 최대한 쉽고 짧게 쓴다.
   - 필요하면 구체적 예시를 든다 — 내 계좌 숫자로 "그때 이렇게 했다면".
   - 필요하면 익숙한 비유를 든다 (장보기·운전·다이어트·보험처럼 생활에 있는 것). 비유는 한 파트에 하나만.
4. **근거** 하나 이상 (3번 규칙):
   - ⓐ 백테스트 결과 (코드 출력)
   - ⓑ 최근의 믿을 만한 사례·연구
   - ⓒ 투자 대가의 말
5. (선택) 끝 문장으로 다음 방법을 궁금하게 이어 준다 — "그런데 이것만으로는 부족했어요."

### 2-3. 정리 및 마무리

```
-정리
오늘 찾은 세 가지, 정리해볼게요.
[장면] 정리
1 한 종목 10%
2 매달 같은 금액
3 빚투 없이
-마무리
이 세 가지만큼은 꼭 지켜 볼게요.
원금 회복, 그리고 파이어까지 포기하지 않을게요.
여러분의 투자도 꼭 성공하길 바랄게요.
시청해주셔서 감사합니다.
```

1. `-정리` 는 **"… 정리해볼게요." 한 문장만** 쓴다 (멘트만).
2. 바로 다음 줄에 `[장면] 정리` 카드를 둔다. 카드 문구 = 방법마다 한 줄(번호 + 짧은 말). **말로 읽지 않는다** — 화면으로만 정리한다.
   - 이 동안은 말이 없다. 쉼 길이 = 카드 글자 수 ÷ 7 + 1초 (4~8초, `srt_tool.parse_cards`).
   - 카드 글자는 공백을 빼고 **49자 이하** (넘으면 8초에서 잘린다). 한 줄은 12자 안팎.
3. `-마무리` 에 다짐 1~2문장을 쓴다 — 정리한 내용을 지키겠다 + 원금 회복·파이어 꿈.
   - 시리즈면 다짐 다음에 **다음 화 예고 한 문장** — 다음 화 제목의 핵심 낱말을 넣는다 (6번).
4. 시청자 응원 1문장 — "여러분의 투자도 꼭 성공하길 바랄게요."
5. 마지막 문장은 **"시청해주셔서 감사합니다."** (공통).

## 3. 근거 — 숫자 · 사례 · 대가 인용

### 3-1. 숫자는 어디서 왔는지 남긴다
- 주인공 숫자 → 설정 파일. 백테스트 숫자 → `stock/source/<영상ID>/backtest/` 코드 출력. 통계·연구 숫자 → 원문.
- 대본 옆에 `sources.md` 를 둔다: 문장 번호 → 출처(기관·제목·날짜·주소·원문 위치).
- 숫자를 말하는 방법은 주식 README 5번 '숫자 말하기' 1~10 그대로:
  - 숫자와 뜻을 한 문장에.
  - 금액은 어림 한 단위로 말하고, 정확한 값은 화면에.
  - 티커는 처음에 무엇을 따라가는 ETF인지 한 구절로.

### 3-2. 백테스트
- `stock/guides/concept.md` 그대로 지킨다:
  - 미래 정보 금지 — 그날 알 수 있던 값만 쓴다.
  - 총수익 — 배당을 다시 투자한 값.
  - 수수료·세금을 넣는다.
  - 여러 시작 시점 — '몇 번 중 몇 번'으로.
  - 생존 편향 — 지금 남아 있는 종목만 쓰지 않는다.
  - 자료는 고정한다 (`tools/backtest/data.py` meta).
- 결과 문장에는 조건, 숫자, 뜻이 한 문장에 함께 있어야 한다.
  - 예: "매달 같은 금액을 매수했다면, 10년 시작점 120번 중 ○번은 원금보다 많았어요."
- 주인공이 직접 확인하는 장면으로 말한다. 예: "AI가 짠 코드로 백테스트해 봤어요." (채널 컨셉 — AI 코드 백테스트)
- 주인공의 '그때 이렇게 했다면' 계산도 같은 규칙을 따른다.

### 3-3. 사례 · 연구
- 2020년대 자료를 먼저 쓴다. 1900년대 사건·자료는 쓰지 않는다 (CLAUDE.md).
- 1차 출처를 확인한다 — 기관 보고서, 감독기관 보도자료, 공시, 논문.
- 쓸 만한 곳 (쓰기 전에 원문으로 숫자 확인):
  - S&P 다우존스 SPIVA (액티브 펀드 vs 지수)
  - Morningstar 'Mind the Gap' (투자자가 실제로 번 수익률 vs 펀드 수익률)
  - 자본시장연구원 개인투자자 연구
  - 금융감독원 불법 리딩방 소비자경보
  - 한국예탁결제원 주식 소유자 현황

### 3-4. 투자 대가의 말
- 원문에서 확인한 말만 쓴다 — 주주 서한, 연례 총회 녹취, 본인 책, 공식 인터뷰.
- 인터넷 '명언 모음'의 출처 없는 말은 쓰지 않는다 (가짜 인용이 많다).
- **2020년 이후에 한 말·쓴 글을 먼저 쓴다** (예: 버크셔 해서웨이 주주 서한 2020~2025).
  - 그 전의 말은 2020년대 원문에서 다시 확인된 것만 쓴다.
  - 1900년대 일화는 쓰지 않는다.
- 대본에는 뜻을 옮긴 말을 쓴다. 직접 인용은 원문 연도를 같이 쓴다. `sources.md` 에는 원문 문장과 주소를 둔다.
- 대가의 말로 결론을 대신하지 않는다: 말 → 내 문제에 어떻게 맞는지 → (있으면) 백테스트.

### 3-5. 투자 권유가 아니게
- 개별 종목을 추천하지 않는다. 목표가, '지금 매수하세요'도 쓰지 않는다.
- 주인공이 잃은 곳은 업종·테마로 말한다 ('2차전지 테마주' · '미국 3배 레버리지 ETF'). 실제 회사 이름은 꼭 필요할 때만, 사실로 확인된 것만 쓴다.
- 방법은 원칙으로 쓴다 — 나누기, 정해진 금액, 비용, 손실 한도, 빚 없이, 기간.
- 설명란 '알려 드립니다'에 쓴다: "투자 권유가 아니며, 과거 결과가 미래 수익을 보장하지 않습니다."

## 4. 지금은 한국 시청자 — 전 세계로 넓혀도 되게

사용자 지시 2026-10-21 "한국 시청자 기준이긴 한데 전 세계로 했을 때 큰 문제 없이 넘어갈 수 있도록 해".

1. **한 문장에 한 생각**, 60자 안. 언어별 자막(CC) 대본이 문장 1:1 로 옮겨진다 (`tools/subs_tool.py`).
2. **말장난, 한국어로만 웃긴 말은 쓰지 않는다.** 주인공 이름의 뜻풀이도 대본에서는 하지 않는다.
3. 개미 낱말은 1-4대로 처음에 뜻을 붙인다. 그러면 번역도 뜻으로 옮겨진다.
4. **한국에만 있는 것**은 처음에 한 구절로 푼다. 예: ISA · 연금저축 · 코스피 하루 가격 제한 30% · 대주주 양도세 · 전세.
   - "세금 혜택이 있는 한국의 투자 계좌인 ISA"
5. 돈:
   - 주인공의 돈은 원화로 말한다. 어림 한 단위로 — '약 1억 2천만 원'. 화면에는 `₩120,000,000` 꼴 숫자.
   - 미국 ETF 백테스트는 달러로 말한다 (README 5번 4·9).
   - 한 문장에 원화와 달러를 섞지 않는다.
6. 화면 글자:
   - 자막은 굽지 않는다 (주식 규칙). 한국어 CC 를 올리고, 다른 언어는 그 언어 대본만 더하면 된다.
   - 화면 글자는 숫자·기호·티커·BUY/SELL·국기·그림만 쓴다. **한국어 글자는 화면 어디에도 쓰지 않는다 — 정리 카드도 방법마다 그림 한 줄** (v1.9 (사용자 지시 2026-10-23 "외국인 대상으로도 할거니까 그것도 고려해 영상에 한글 문구 사용하지 말고 최대한 이해 잘되도록")). 대본의 카드 줄은 말 없는 쉼 길이만 정한다.
   - 썸네일 문구도 쉬운 영어 낱말·숫자·기호만 (예: `−70%` / `DON'T QUIT`) — 한국어 없음.
   - 한국에만 있는 말(코스피·리딩방·학원비 등)은 언어별 자막 번역에서 처음 나올 때 짧게 풀어 쓴다.
   - 다른 언어판은 카드 문구만 바꿔 다시 렌더하면 된다.
7. 제목·썸네일은 이 파일 밖이다 — `stock/guides/README.md` 2·3번.

## 6. 시리즈 — 개미 재기 일지 (`stock/story/series.md`)

- **화마다 다른 경험 (v1.8)**: 1화의 전재산 70% 손실은 1화에서만 말한다. 2화부터는 연표의 다른 사건을 그 화의 경험으로 쓰고, 앞 화에 나온 경험·근거·숫자·결심·문장·도입 걱정을 다시 쓰지 않는다 (사용자 지시 2026-10-23 "70% 잃었다는건 처음 시리즈에서만 말하고 다른데서는 다른 경험으로 이야기해야지 중복되면 안돼 다른 내용도 마찬가지야"). 근거는 `story_kit facts --unused`, 점검은 `story_kit check` [DUP] (앞 화 도입 숫자 = 문제 · 거의 같은 문장 = 문제 · 같은 숫자 = 경고).

사용자 지시 (2026-10-21): "그리고 시리즈물이라는 것도 고려해"

1. **한 편만 봐도 이해되게** 쓴다.
   - 첫 문장은 늘 그 화 제목과 이어진다 (2-1 ①). '지난 화에서…'로 시작하지 않는다.
2. 주인공 소개는 도입 ① 안에서 숫자 하나로만 한다 ('전재산의 절반이 넘게' 등).
3. **지난 화 내용은 본문에서 한 문장까지만** 다시 말한다 ("1화에서 본 것처럼, …").
   - 같은 백테스트 숫자를 다음 화의 주된 근거로 다시 쓰지 않는다. 새 근거를 찾는다.
4. `-마무리` 순서는 이렇다: 다짐 → **다음 화 예고 한 문장** → 응원 → 끝인사 (`story_check` 3~5문장).
5. **한 화에 주된 실수 하나** (설정 연표의 사건 — `series.md` 2번 표). 다른 화의 사건은 한두 문장으로만 말한다 ("그날 이야기는 4화에서 자세히").
6. 주인공이 화마다 새로 정한 것은 다음 화에도 그대로 이어진다 (`protagonist.md` 5-1 재기 일지).
   - 대본을 쓰기 전에 5-1 을 읽는다. 새로 정한 것은 쓴 뒤 5-1 에 더한다.
7. 제작안 한 파일 = 그 화의 요약·제목 안(R1~ — 주제에서 벗어나지 않게, 댓글 근거)·**대본**·근거·한계.
   - **화면 메모는 넣지 않는다** — 대본이 눈에 잘 들어오게 (v1.4 — 사용자 지시 2026-10-22 "화면 내용은 좀 빼고 눈에 잘 안들어와"). 장면은 영상 단계에서 따로 짠다.
   - 꼴: 파트 머리(`==== 도입 ====` · `==== 방법1 · … ====` …) 아래에 한 줄 한 문장만 (1화 v2.0). 예전 꼴(장면 머리 + (화면) + (내레이션))도 plan_tool 이 읽는다.
   - 위치: `stock/story/<N>화_<줄인 제목>_제작안.txt`
   - 시각·검사: `python3 stock/story/calc/plan_tool.py <제작안> --write` → 문제 0 이어야 한다.
   - 승인되면 `--script-out stock/source/<영상ID>/<영상ID>.txt` 로 오디오용 대본을 뽑는다. 그 전에는 오디오를 만들지 않는다.
8. 숫자는 `stock/story/calc/series_calc.py` → `results.json` 의 값만 쓴다 (3-1).
9. **요약본 꼴** (v1.5 — 사용자 지시 2026-10-22 "야 테스트 요약본 올렸으니까 그거 보고 대본 만들어봐 없는 부분은 다시 만들고 요약본 내용 만들때 그냥 텍스트로하고 핵심만 요약해서 적어 내가 수정한것 처럼") — 표·머리말·버전 줄 없이 **텍스트로, 핵심만** (예: `stock/story/테스트 요약본`):
   ```
   ## 롱폼 제목
   (제목 한 줄)
   ## 도입
   - (첫 멘트) - (걱정 상황) … - (다짐·찾음)
   ## 문제 상황 → 해결 방법
   1. (방법 이름)
   - 문제: … - 좋은 안: … - 근거: (숫자 + 출처 짧게)
   ## 쇼츠 제목
   1. … 
   ## 쇼츠 대본
   - (첫 문장) - … - (아래 영상에서)
   ```
   - 예비안은 사용자가 달라고 할 때만 넣는다.
   - 사용자가 고친 요약본이 오면 그 문장·순서를 그대로 두고, **빈 곳만** 채운다. 제목만 바뀐 항목은 그 제목에 맞게 내용을 새로 쓴다.
   - 그 요약본으로 대본을 쓴다 (대본 파일 = 대본만 꼴, `plan_tool` 문제 0).
