## 1. 시청자 — 전 세계 (사용자 지시 2026-10-15)
- 주식 영상은 **전 세계 시청자**를 대상으로 한다.
- 화면·썸네일은 **언어 없이** 이해되게 만든다: 숫자·연도·%·화살표·색·아이콘.
- 근거 숫자(`data_insights.md`)는 한국어 작은 채널 분석 결과다.
  - 다른 언어 시청자에 대한 근거는 아직 없다 ("근거 없음").
  - 외국 영상 분석(`INCLUDE_FOREIGN`)을 켜면 그 결과로 보완한다.

**한국어 제목 규칙 (사용자 피드백 2026-10-16 — 공통 `title_guide.md`보다 먼저)**
- 피드백: "제목부터 명확하지가 않아 어디서 얼마나 떨어져야 사겠다는 건지 모르겠고, 졌다라는 것도 수익에서 졌다는 건지 모르겠어 … 제목은 결말을 말하지말고 그리고 맨 앞에 시청자 니즈 만족하는 핵심 단어 사용하라고 이거 economic 했을 때 했잖아 … 샀다는 매수, 팔다는 매도 단어를 쓰고 대본 내용도 처음에 결말을 말하지마 니즈를 파악해서 공감이 되는 백테스트로 알아보겠습니다 이런식으로 해서 결말 알아보는식으로 해" · "제목은 명확하게 호기심을 유발하도록"
1. **결말을 말하지 않는다.** 결과 숫자('117번 졌다'·'덜 남았다')를 쓰지 않고 **질문으로 끝낸다** → 호기심.
   - 공통 `title_guide.md`의 '해소 구절(결과)'은 주식에서 쓰지 않는다.
2. **맨 앞(첫 12자) = 시청자 니즈 핵심 낱말** — 재테크에서 '연금·노후'를 맨 앞에 둔 것과 같은 방법.
   - 그 영상의 가설이 답하는 댓글 질문 묶음에서 고른다 (예: '사는 때' 묶음 → '저점 매수'·'매수 타이밍').
   - 맨 앞 '주식'·'S&P'는 피한다 (−11·−9, `data_insights.md` 2번).
3. **명확하게**: 가설의 조건을 '어디서·얼마나'까지 쓴다 (예: '최고점보다 10% 떨어질 때만'). 비교 대상과 잣대도 쓴다 (예: '매달 매수보다 더 벌까' = 같은 돈을 넣고 10년 뒤 수익).
   - '졌다·이겼다'처럼 무엇에서 졌는지 모르는 말은 쓰지 않는다.
4. **사다 → 매수, 팔다 → 매도** (제목·대본·설명란·챕터).
5. 설명란·챕터 이름·고정 댓글·언어별 제목·설명에도 결말을 쓰지 않는다 (챕터는 진행 막대에 미리 보인다).
6. 길이: 위를 지키느라 30~44자보다 길어져도 된다. 60자는 넘지 않는다.

**만드는 법**
- 한국어 제목(R1)을 먼저 위 규칙, `title_guide.md`, `data_insights.md` 2번으로 만든다.
- 그 **뜻과 숫자를 그대로** 각 언어로 옮긴다.
  - 그 언어에서 자연스러운 말로 쓴다. 숫자는 대본과 같아야 한다.
  - 100자 이하로 쓴다 (YouTube 한도). 한국어 규칙(30~44자)에 맞추려고 뜻을 줄이지 않는다.
- 설명란도 언어마다 짧게 쓴다: **가설·질문·무엇을 백테스트했나** 두세 줄(결말 없이) + 자료 출처 + "투자 권유 아님".

**올리기**
- 업로드 시트 `upload.md`의 '언어별 제목·설명' JSON에 적는다.
- `tools/youtube_upload.py` v1.6이 유튜브 `localizations`로 올린다.
  - 시청자 언어 설정에 따라 그 언어 제목이 보인다.

## 3. 썸네일 — 글자 없이 그림으로만 (공통 `thumbnail_guide.md` 4번 '하단 2줄'을 쓰지 않음)
- **글자·숫자·로고를 하나도 넣지 않는다.**
  - 프롬프트에 "No text, no letters, no numbers anywhere"를 넣는다.
  - 그래프 눈금·화폐 숫자도 없다.
- **그림이 결말을 보여 주지 않는다 — 궁금하게 만든다** (사용자 지시 2026-10-16 "그래 결말 궁금해하도록 변경해", 제목·대본 도입과 같은 규칙).
  - 두 선택(가설 vs 비교 대상)을 **같은 크기·같은 높이**로 맞세운다. 결과는 닫힌 상자·가린 천처럼 **가린 물건**으로 둔다.
  - 이기거나 진 것을 말하는 그림(올라가 버린 계단, 하락선, 아쉬움·좌절·뽐내는 표정)을 쓰지 않는다 → 망설임·침착함.
  - 가설의 조건은 그림으로 보여 준다 (예: 최고점 별 + 그 아래 노란 점선 = '최고점보다 10%').
  - 색은 영상과 같은 **사람 표시**다: 빨강 = B(가설 쪽), 청록 = A(비교 쪽), 노랑 = 기준 — 이긴 쪽·진 쪽의 뜻으로 쓰지 않는다.
  - 예: `stock/source/eonje-maesu-2026-10/thumbnails/` v1.0 (B 규칙 아이콘 10개를 다루는 사람 vs A 자물쇠 상자 하나를 안은 사람, 결과는 빛이 새는 닫힌 상자) · 예전 1번 `stock/source/_old/tteoreojimyeon-sagi-2026-10/thumbnails/` v2.0.
- 디자인 근거 (`data_insights.md` 5번):
  - 그림·반실사 일러스트 23% vs 10%
  - 어두운 배경·빨강 요소 (이미지 수치)
  - 같은 채널에서 잘된 쪽: 대비 + 하락선 + 좌절 표정 → 대비만 쓰고, 결과를 말하는 하락선·좌절 표정은 쓰지 않는다
  - 다만 성공 사례의 '글자만' 썸네일(15%)과 하단 2줄은 사용자 지시로 쓰지 않는다.
- 본안 1 + 실험안 2는 공통과 같다. 실험안은 본안과 한 가지만 다르게 한다.
- 이미지 검수 (공통 10번):
  - 그림 속에 글자처럼 보이는 것이 하나도 없어야 통과한다.
  - 이미지 AI가 가짜 글자를 넣기 쉽다 → 검수에서 확대해 본다.

## 4. 영상 — 자막 없음 · 언어 없는 화면 · 실시간 비교 애니메이션 (공통 `video_guide.md`와 다른 것)

**자막·글자**
- **자막을 굽지 않는다** (공통 1번 2·3-5를 쓰지 않음). 장면 파일에 `EP.subtitles = false`.
- 업로드 때 자막 파일도 올리지 않는다 (`upload.md` '자막 올리기: 아니요').
  - 유튜브 자동 자막·자동 번역은 시청자가 켤 수 있다.
- **화면 글자는 언어 없이**:
  - 숫자, 연도(2000·2023), %, 배수(×1.4), 기호(▲▼ = vs →), 'A'·'B', 아이콘.
  - 한국어·영어 낱말을 쓰지 않는다.
  - **예외 (2026-10-16 사용자 지시 "buy, sell 문구 붙여서 표시하고")**: 매매 표시 `BUY`·`SELL` 은 쓴다. 지표 이름 `RSI`·`VIX` 도 `S&P 500` 처럼 고유 이름으로 쓴다 (`render.mjs` v1.4 낱말 검사에서 뺌). 계좌 칸의 참고값 이름 `BUY & HOLD`(처음에 사서 그대로 둔 계좌 — 투자 용어 'buy and hold' 그대로, 2026-10-16 확인)도 쓴다. 그 밖의 영어 낱말(CASH 등)은 쓰지 않고 색·아이콘으로.
  - 장 이름표(chip)·장 바뀜 카드에도 글자 대신 번호·아이콘을 쓴다.

**인물·아이콘**
- A·B는 사람 아이콘 + 글자 'A'·'B' 배지로 그린다.
- A = 청록, B = 빨강 — 영상 끝까지 같다. 아이콘은 영상의 가설에 맞춘다.
  - 예전 1번: A 달력(매달) · B 모래시계(기다림).
  - 1번 v2 (`eonje-maesu-2026-10`): A 자물쇠(사서 들고 있기) · B 규칙마다 아이콘 + 번호 배지 1~10 (화면 위에 지금 몇 번째 규칙인지 점 10개).

**핵심 장면 = 날짜가 흐르며 두 계좌를 실시간으로 비교하는 애니메이션** (사용자 지시)
- 화면 위 큰 날짜 카운터(YYYY.MM)가 한 달씩 흐른다.
- 두 계좌의 돈 선(A 청록·B 빨강)이 그 날짜까지 그려진다.
  - 숫자 카운터는 그 달의 실제 값이다 (`backtest/anim.js` ← `backtest/anim_data.py` — 코드가 낸 값만, `results.json`과 assert로 맞춤).
- B가 기다리는 동안 현금 더미(회색)가 쌓인다. 사는 달에 현금 더미가 주식으로 바뀌며 빛난다.
- 큰 하락(2000~02·2008·2020·2022)은 그 달에 배경이 잠깐 어두워진다. 글자는 쓰지 않는다.
- 163번 실험은 시작 달이 흐를 때마다 막대 하나가 생긴다.
  - 막대 색 = 이긴 쪽, 높이 = 차이.
  - 위쪽 점수판 `A 117 : 46 B`가 한 칸씩 오른다.
- 속도는 내레이션 시각(문장 시작·끝)에 맞춘다. 한 달 = 장면 길이 ÷ 달 수.

**매수 신호 시험 장면 (1번 v2 — 사용자 지시 2026-10-16 "buy and hold랑 비교하지말고 주가 차트에서 매수/매도 지점을 표시하는 걸로 하자 buy, sell 문구 붙여서 표시하고")** — 시안 `video/prototypes/stock-entry-2026-10-16/race3d.html` v1.0 · 한 장 `still_dip10_2023-09-29.png`
- 관망 곡선(A)을 그리지 않는다. 화면의 주인공 = **S&P 500 가격 차트** 하나.
- **Three.js(WebGL) 3D 가격 벽**: 가격 선 아래를 두께 있는 벽으로 세우고, **BUY~SELL 사이(주식을 든 날) = 초록**, 현금으로 기다린 날 = 회색. 바닥 격자·연도 글자·바닥에 비친 그림으로 깊이를 준다. 카메라는 살짝 위·오른쪽에서 (값을 읽을 수 있을 만큼만 기울임).
- 매매 핀: **BUY = 초록 점 + 선 아래 `BUY` + 산 지수 값**, **SELL = 주황 점 + 선 위 `SELL` + 그 거래 수익률**(+초록 / −빨강). SELL 다음 날 바로 BUY 여도 위·아래로 갈라 겹치지 않는다. 바닥 가까운 BUY 는 위로.
- 규칙이 보는 선을 같이 그린다 (예: 고점 ★ 노란 선 + 고점 −10% 노란 점선). 값 눈금은 오른쪽(미래 쪽 빈 곳), 노란 세로 막 = 오늘, 그 위에 오늘 지수 값.
- 머리: 규칙 번호 + 매수 조건 그림(예: `★ −10% → BUY`)만. **매도 조건(모든 규칙 같음)은 머리에 쓰지 않는다 — 도입에서 한 번 설명** (사용자 지시 2026-10-16). 오른쪽 위 = 큰 날짜 YYYY.MM.DD.
- 오른쪽 카드 2개 (v1.1 — 예전 'B÷A·주식/현금 막대·거래 수·손익 막대'는 사용자가 이해 못 함, '지금 상태' 카드도 뺌):
  1. 계좌: `$10,000 →` 이 규칙 계좌(번호 배지 + 큰 값 + 누적 %) · 아래 줄 **`BUY & HOLD`**(첫날 전부 매수 후 그대로 — 참고, 회색) 값 + 누적 % · 계좌 그래프(초록 = 규칙, 회색 = BUY & HOLD, 노란 점선 = $10,000). 숫자 = `run.py` v2.1 `anim.js` `bh`.
  2. 거래 기록: 그날까지 거래 전부(칸에 맞게 최근 8개, 더 있으면 머리에 `1~N ↑`) — 줄마다 번호 · `BUY` 날짜·지수 값 → `SELL` 날짜·지수 값 · 수익률 · 손익 $. 들고 있는 거래는 흐린 `SELL` + 📅 며칠/252 + 평가 수익. 아래 ▲ 이긴 수 ▼ 진 수.
- 매매 핀 글자가 겹치면 더 멀리 → 그래도 겹치면 오래된 글자부터 빼고 점만 둔다 (최근 거래 먼저 놓음 — 매달 매수처럼 거래가 촘촘한 규칙).
- 설명 장면(규칙 그림)도 Three.js 로 입체 장면을 만든다 (사용자 지시 "설명할 때 영상이 왤케 부실해 … 입체적으로 표현 하는 도구 없어?") — 렌더는 같은 Playwright 프레임 찍기 (헤드리스 Chromium WebGL = SwiftShader, 1080p 한 장 약 0.1초).

**(v1 — 쓰지 않음) 규칙 여러 개 vs 관망 — 실시간 대시보드** (사용자 지시 2026-10-16 "날짜, 주가 움직임, 투자 금액, 매수/매도 상태, 거래 수익, 총 누적 수익 등을 보기 편하게 날짜가 지남에 따라 변하는걸 표현해야" — 1번 v2 `video/episodes/eonje-maesu-2026-10/index.html`)
- 한 화면에 모두 — 위 가운데 큰 날짜(YYYY.MM), 왼쪽 위 = A·B 평가 금액 곡선(로그 눈금 — 32년 ×25 를 한 화면에), 왼쪽 아래 = 지수 가격(S&P 500) + 규칙이 보는 선(이평선 등, 노란 점선) + 매수 ▲(초록)·매도 ▼(주황), 오른쪽 = A·B 금액·처음 돈 대비 배수·B ÷ A·B 의 주식/현금 비율 막대·거래 수·마지막 거래 손익(+초록/−빨강)과 거래 손익 막대 모음.
- 시간 눈금은 **날짜(일)** 로 — 그 날까지 곡선을 잘라 보인다(clipPath). 대본이 말하는 날(폭락 바닥·가장 앞선 날)은 자료 점에 꼭 넣어(`anim_data.py` 핵심 날짜) 말하는 숫자와 화면 숫자가 같게 한다.
- 문장 시각 → 날짜 기준점(`SEG`)으로 흐름을 맞춘다. 말할 것이 없는 구간은 빨리 감는다.
- 큰 하락 구간 = 배경 띠 + 그 구간 A·B 낙폭 상자(어두운 상자 — 곡선을 가리지 않는 자리).
- 끝의 종합: 끝 값 막대(규칙 10 + A), 굴리는 기간 칸 지도(271칸 — 칸 색 = 이긴 쪽, 폭락이 든 기간 / 없는 기간으로 나눔), 최대 낙폭 막대, 다른 기간·다른 지수로 확인, 한계.
- GSAP 주의: 같은 대상에 이어지는 tween 은 `immediateRender:false` + 처음 상태를 직접 (안 하면 앞 장면에 마지막 값이 먼저 보임).

**장면 파일 (`video/episodes/<영상ID>/index.html`)**
- `K.init(window.EP, { subtitles: false, chip: false, noWords: true })` — 자막 띠·장 이름표를 만들지 않고, `render.mjs check`가 화면 글자에 낱말(한글·가나·한자·영어 2글자 이상)이 있으면 문제로 센다.
- 언어 없는 화면에서 쓰는 것:
  - 돈: `₩209,569,910` 처럼 ₩ + 숫자 전부 (억·만 같은 낱말 단위를 쓰지 않음). **미국 지수 백테스트는 `$259,164`** (1번 v2 — 자료가 달러, 환율을 섞지 않음). 날짜: `2006.10`.
  - 지수 이름 `S&P 500`·`NASDAQ`, 매매 표시 `BUY`·`SELL`, 지표 이름 `RSI`·`VIX` 는 쓴다 (낱말 검사에서 뺌 — `render.mjs` v1.4).
  - 코드 카드(`class="code"` — 실제 `tools/backtest` 코드·시험 이름)는 채널 컨셉이라 쓴다 (낱말 검사에서 뺌).
  - 글꼴에 없는 기호(✕ ↻ ⌛)는 SVG 아이콘으로 그린다.
- 장 바뀜 카드는 번호·아이콘만 (`K.chapters`의 `title`에 아이콘 HTML).
- 오디오 전에는 `node video/render/render.mjs sync stock <영상ID> --estimate`로 추정 시각을 넣고 `check`·`stills`로 배치만 점검한다.
  - 추정 시각으로는 `video`가 거부된다. 오디오가 오면 `sync`(진짜 시각) → `check` → `video`.

**숫자와 쉬는 시간**
- 숫자는 공통 규칙 그대로 결과 파일에서만 쓴다. 말하기 전에 보이지 않는다.
- 자막 띠가 없으니 아래쪽(y 900~1040)도 그림에 쓴다.
  - 단, 유튜브 진행 막대·자동 자막이 덮는 맨 아래 60px은 비운다.

## 5. 대본·내레이션
- 길이: **실제 오디오 9~12분** — 읽는 음절 약 3,100~4,200.
  - 진행자 H04 실제 속도는 약 5.8음절/초다 (재테크 isa-mangi 2,447음절 → 7:00.8).
  - 근거: `data_insights.md` 3-1. 공통의 7~8분은 재테크 지시다.
- 내레이션 언어는 지금 한국어(H04)다.
  - 전 세계 시청자는 유튜브 자동 번역 자막·자동 더빙으로 본다.
  - 다른 언어 오디오를 따로 만들지는 사용자가 정한다 (2026-10-15 질문함).
- 화면이 언어 없이 이해되도록, 대본은 숫자를 말할 때 화면에 같은 숫자가 나오는 순서로 쓴다.
- **규칙 여러 개 vs 관망 영상** (사용자 지시 2026-10-16 "대본 구성은 처음에 뭘할건지 15~25초 정도 간략하게 설명하고 바로 비교하는 영상으로 넘어가 … 대본은 부연 설명만 간략하게 하면 돼 … 마지막은 종합 통계내서 결론"):
  1. 도입 15~25초 — 무엇을(규칙 10개), 무엇과(사서 들고 있기), 같은 돈으로, 무슨 자료로 — 결과는 말하지 않음.
  2. 규칙마다: 규칙 그림 한 장(2~3문장) → 대시보드 경주. 대본은 화면을 따라가는 부연만 (폭락에서 무엇을 했는지, 끝 값·배수).
  3. 끝: 종합 통계(끝 값·여러 시작 시점 '몇 번 중 몇 번'·낙폭·다른 기간·다른 지수) → 결론 → 한계.
  - 예: `stock/source/eonje-maesu-2026-10/eonje-maesu-2026-10.txt` v1.0 (125문장, 도입 s1–5 약 22초).
- **도입에서 결말을 말하지 않는다** (사용자 피드백 2026-10-16 — 공통 `script_guide.md`의 '결론 먼저'를 주식에서는 쓰지 않음):
  1. 니즈·공감: 시청자가 하는 생각과 그 마음 (예: "최고점보다 10% 떨어지면 그때 매수하겠다며 현금을 들고 계신가요?" · "비싸게 매수했는데 바로 떨어지면 속이 쓰리니까").
  2. 질문: 무엇과 무엇을, 무엇으로 비교하는지 분명히 ("매달 꼬박꼬박 매수한 사람보다, 10년 뒤 수익이 더 많을까요?").
  3. 약속: "AI가 짠 코드로 백테스트해서 직접 확인해 보겠습니다" + 자료·함께 볼 실험(끝까지).
  4. 방법 → **결과 파트에서 처음 결과를 말한다**. 결과 전에 '이긴 쪽'의 뜻을 한 번 밝힌다 (예: "넣은 돈이 같으니, 10년 뒤 남은 돈이 더 많은 쪽이 수익도 더 많은 쪽입니다").
- 화면도 도입에서는 결과 숫자·점수판을 보여 주지 않는다 (`?`·`₩?`로).
- 사다 → 매수, 팔다 → 매도. 물건 세일 같은 비유 속 '사다'는 그대로 둔다.
