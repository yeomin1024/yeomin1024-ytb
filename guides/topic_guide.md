## 0. 재료와 원칙

**재료** (PC 가 올린 분석 결과, 할당량 0):
- `<주제>/result/outliers/analysis.md`·`analysis.json`·`compare.csv`
- 사례 폴더(`01_…`·`W_…`)의 `comments.csv`·`transcript.json`
- 다시 세는 도구 (`tools/content_research.py`):
  ```
  python3 tools/content_research.py audience <주제>     # 시청자층 (댓글에서 밝힌 나이)
  python3 tools/content_research.py needs <주제>        # 시청자가 원하는 정보 (질문 묶음)
  python3 tools/content_research.py all <주제> --out /tmp/research.md
  ```
- 주제마다 다른 낱말(질문 묶음, 핵심 시청자 맥락)은 `<주제>/research_rules.toml`에 있다 (예: `economic/research_rules.toml`).

**원칙**
1. **옛 지시사항이 아니라 분석 결과로 정한다.** 사용자 지시 2026-10-14: "분석 결과만 보고".
2. **분석 결과의 날짜와 한계를 먼저 적는다.**
   - `analysis.json`의 `generated`, 성공 사례 수, 대본이 있는 사례 수를 적는다.
   - `analysis.md` 0번 '한계'를 읽는다. 표본이 15개 미만이면 '표본 적음'으로 적고, 그 차이로 규칙을 만들지 않는다.
3. **결론은 시청자가 가장 많이 원하는 정보다.** 사용자 지시 2026-10-14: "시청자가 가장 많이 원하는 정보가 뭔지 먼저 파악하고 그걸 결론으로 하고 내용 전개하고 그게 제목에 담겨야지".
   - 주제 → 결론 → 제목 → 대본이 한 줄로 이어져야 한다.
4. **결론은 단순한 상식이면 안 된다.** 사용자 피드백 2026-10-14 "결론이 뭔데?". "아껴 쓰세요", "미리 준비하세요" 같은 말은 결론이 아니다.
   - 결론은 **숫자로 차이를 보여 줄 수 있는 구체적 행동**이어야 한다.
   - 예: "예금부터 쓰고, 연금계좌는 나중에, 부부가 나눠서 꺼낸다 → 같은 5억 원인데 평생 세금 약 2,100만 원 차이".
5. **바뀌는 것과 안 바뀌는 것을 나눈다.** 사용자 지시 2026-10-14: "빠른 시일 내로 변경될 수 있는 부분은 언급을 간단하게 해주고 변하지 않고 중요한 부분을 중심으로".
   - 영상의 중심은 제도가 바뀌어도 남는 **원칙**이다. 예: 기준은 한 사람·1년 단위.
   - 금액·비율·운영 방침은 근거로만 쓰고, "바뀔 수 있다"고 한 번 말한다.
6. 사례·연구는 되도록 최신(2020년대)을 쓴다. 1900년대 자료는 쓰지 않는다 (사용자 지시 2026-10-10).
7. 재테크 폴더에서는 경제 뉴스(금리·환율 해설)를 뺀다 (사용자 지시 2026-10-13). 개별 종목 추천도 하지 않는다.
8. 이미 만든 주제와 겹치지 않게 한다 (`<주제>/source/used_content.md`).

## 1. 순서

### 1-0. 시청자 페르소나부터 (2026-10-28)
- `<주제>/result/outliers/personas.md` 를 먼저 읽는다 — 분석(analyze)이 끝날 때마다 `tools/personas.py` 가 다시 만든다 (손으로 고치지 않음, 사전은 `<주제>/personas.toml`).
  - 0번 표: 페르소나 P1~Pn (연령·처한 상황·지식 수준·이미 아는 말·모르는 말·원하는 것·좋아함·불만) + '모든 댓글 (참고)' 칸.
  - 1번 표: 몇 명인가와 그 까닭 (큰 묶음부터 몫 8% 이상·누적 80%까지·2~6명 — 댓글이 정함).
  - 4번 '한계'를 먼저 본다: 나이·처지는 스스로 밝힌 댓글(1~4%)만이다.
- 후보마다 **대상 페르소나 하나**(P 번호)와 그 페르소나가 원하는 것(질문 속 용어·좋아요 많은 질문)을 적는다 (1-4 표).
  - 두 페르소나 이상이 함께 묻는 것(personas.md 3번 굵은 글씨) = 넓은 주제.
- 아래 1-1·1-2 는 페르소나 문서가 없거나, 원문을 더 읽어야 할 때.

### 1-1. 누가 보나 — 시청자층
- `content_research.py audience <주제>`로 댓글에서 나이를 밝힌 댓글을 센다.
- 가장 많은 나이대로 **예시 인물의 나이와 상황**을 정한다.
  - 재테크 2026-10-14: 50대 이상 73%, 60대 29%로 가장 많음 → 예시는 '65세 동갑 부부(국민연금 받기 시작)'.
- 나이가 많은 시청자를 '어르신'·'노인'이라고 부르지 않는다.
  - 근거: 60대를 어르신·노인 취급하는 데 반발한 댓글. "요즘 60대를 어르신이라하면서 노인취급" 👍45, "67세 어르신이라니요".
  - 대신 조건으로 부른다: "퇴직금이나 연금저축을 갖고 은퇴를 앞두고 계시다면".

### 1-2. 무엇을 가장 원하나 — 시청자 니즈
1. `content_research.py needs <주제>`
   - 질문·요청·'궁금' 댓글 중 **핵심 시청자 질문**(주제 묶음 영상에 달렸거나 나이·은퇴 맥락 말이 든 질문)을 묶음별로 센다: 질문 수·좋아요 합·영상 수.
2. 묶음끼리 겹치면 합집합(`NEED_UNIONS`)으로 본다.
   - 예: 연금계좌·배당·건보료·생활비 = '꺼내 쓰기' 63개·👍218·영상 27개 → 가장 큰 니즈.
3. **원문을 읽는다.** 정규식 분류는 엉뚱한 댓글이 섞인다(예: '자녀' 묶음에 가족 드라마 감상).
   - 원문에서 "구체적으로 무엇을 묻는지"를 한 문장으로 적는다.
   - 예: "65세쯤 되는 사람은 국민연금·연금저축·ISA를 어떤 순서로 꺼내 쓰나요?"
4. `analysis.md` 8-1(요청)·8-2(물음표 질문)·3-4(묶음별 질문)도 본다. 낱말로 직접 세어도 된다.
   - 예: ISA 질문 119개·영상 21곳, 퇴직 후 건보료 관련 댓글 362개·👍3,416, 기초연금 관련 댓글 232개·👍2,693.

### 1-3. 시장 — 수요와 공급, 성공 비율
| 볼 곳 | 무엇을 | 읽는 법 |
|---|---|---|
| `analysis.md` 3-1 | 주제 묶음별 수요/공급 지수 | 1보다 크면 영상에 비해 보는 사람이 많다. 재테크: 노후·연금 1.4, 절세·제도 0.5 |
| 3-2 | 검색어별 영상당 하루 조회수·작은 채널이 뚫은 비율 | 수요(예: '연금' 13.9)와 새 채널이 들어갈 틈(예: '노후자금' 29%)을 따로 본다 |
| 3-3 | 자동완성 말 중 최근 영상이 적은 말 | '틈'이 크면 후보. 웹 화면 [공급 확인]으로 직접 확인 |
| 2·2-2 | 주제 묶음·형식별 성공 비율 | 비교 집단(21%)과 견줌. 비교 집단은 조회수 순 검색이라 높게 나온다 |
| 1-2 | 같은 채널 안에서 잘된 영상 vs 평소 영상 | 채널 크기를 뺀 비교 → 2번보다 먼저 믿는다 |

### 1-4. 후보 표 (5개 안팎) → 추천
| 열 | 내용 |
|---|---|
| 주제 | 한 줄 |
| 대상 페르소나 | `personas.md` 의 P 번호 하나 + 그 지식 수준 (예: 'P1 은퇴해 연금 받는 6070 · 기초') |
| 시청자가 원하는 정보 | 질문 수·👍·영상 수 + 대표 원문 1개 |
| 시장 | 묶음 지수·검색어 수요·작은 채널 틈 |
| 결론 후보 | 숫자로 차이를 보여 줄 수 있는 행동 한 줄 (0번 원칙 4) |
| 오래가는 원칙이 있나 | 제도가 바뀌어도 남는 것 (0번 원칙 5) |
| 사실 확인 길 | 법령(law.go.kr)·공식 기관에서 지금 날짜로 확인할 수 있나 (`script_guide.md` 3번) |
| 겹침 | 이미 만든 주제와 겹치는 부분 |

- 추천은 '원하는 정보가 크고, 결론을 숫자로 증명할 수 있고, 사실 확인 길이 있는' 순으로 고른다.
- 이유를 한 줄씩 남긴다.
- 사용자가 주제를 맡기면 Claude 가 고르고 이유를 남긴다.

### 1-5. 결론과 '바뀌는 것' 나누기
결론을 정했으면 대본 README 의 '주제 선정' 절에 아래를 적는다.
1. 결론 한 줄: 시청자가 원하는 정보에 대한 답이다.
2. 결론을 증명할 계산 예시:
   - 누구(나이·재산·소득)가 두 가지 방법으로 하면 얼마가 다른가.
   - 숫자는 대본에서 계산 코드로 낸다 (`script_guide.md` 4번).
3. 오래가는 원칙 2~3개: 대본의 중심이다.
4. 바뀔 수 있는 것: 금액 기준·비율·운영 방침 → 대본에서는 한 번만 언급한다.
