## 1단계 — 분석 결과 만들기

0. **기본은 집 PC 실행 (사용자 지시 2026-10-13, `guides/pc_analysis.md`):** 사용자가 PC에서 `run_analyzer.ps1`을 한 번 실행하면 `tools/pc_analysis.py`가 회차마다 ① 성공 사례(아래 4번, `--per-group 2 --top 20`, 할당량 4,000) ② 분석기(`QUOTA_BUDGET` 6,000) ③ GitHub `<주제폴더>/result/` 푸시를 하고, 할당량 때문에 남은 일(검색·영상 정보·댓글·이월 검색어·네트워크로 못 받은 자막)이 있으면 **할당량 초기화(태평양 자정 + 10분 = 한국 16:10, 겨울 17:10)** 뒤 남은 부분만 새로 받는다 (캐시 재사용).
   - **여러 주제를 동시에 (2026-10-13):** `run_analyzer.ps1 -Folder economic,health` — 주제마다 `<주제>/keywords.txt`(검색어, 한 줄에 하나)·`<주제>/.env`(키, PC에만, 비우면 맨 위 `.env`). 같은 키를 쓰는 주제는 하루 할당량을 N등분. 할당량을 늘리려고 프로젝트를 여러 개 만드는 것은 YouTube API 정책 위반이므로 권하지 않는다 (`pc_analysis.md` "여러 주제를 동시에"). 새 주제 요청("<주제> 검색어 만들어줘")을 받으면 Claude가 `<폴더>/analyzer_config.toml`·`keywords.toml`(관련어)·`keywords.txt`(검색어)를 만들어 main에 올린다.
   - **회차 순서 (2026-10-13):** ① 성공 사례·조회수 상위(검색어 + 잘된 영상의 태그 검색어, 자막·썸네일·댓글) → ② 그 결과를 먼저 올림 → ③ 분석기(`--no-video --defer-whisper` — 영상 파일 안 받음, 음성인식 미룸) → ④ 남은 할당량 보충 → ⑤ 올림 → ⑥ 음성인식 대기열(자막 없는 영상을 하나씩, 끝날 때마다 바로 올림). 어떤 영상을 받았고 무엇이 성공했는지: `<주제폴더>/result/outliers/downloads.md`.
   - Claude는 GitHub의 `<주제폴더>/result/pc_progress.json`(`complete`·`left`·`next_round_kst`)과 `result/outliers/status.json`으로 진행을 확인한다. `complete: true` 전에는 2단계 근거를 "수집 중"으로 적는다.
   - 클라우드에서는 자막·썸네일이 막혀 있다(아래 4번). 클라우드 실행은 사용자가 요청할 때만, 분석기 결과(검색·댓글)만 필요할 때 쓴다.
1. `<주제폴더>/result/README.md`가 없으면 분석기를 돌린다. 있어도 사용자가 "다시 분석"을 요청하거나 30일이 지났으면 다시 돌린다.
2. 명령 (저장소 최상위, 클라우드):
   ```
   bash tools/run_analysis.sh economic       # 주제 폴더 이름
   ```
   - 키: 환경변수 `YOUTUBE_API_KEY` (아래 "처음 한 번 할 일" A). 없으면 멈추고 사용자에게 알린다.
   - `--no-push --no-video`로 돌린다. 결과는 `<주제폴더>/result/`로 복사되고, Claude가 main에 커밋한다.
   - 성공사례 **영상 파일은 받지 않는다.** 공개 저장소에 남의 영상을 올리지 않기 위해서다.
3. 한계: 검색 할당량 때문에 하루에 키워드 일부만 수집될 수 있다(2026-10-09 주식: 90개 중 40개). 남은 키워드는 다음 날 같은 명령으로 이어서 수집한다.
   - 클라우드 IP에서는 자막·영상 받기가 막힐 수 있다. 막히면 `run_log.txt`에 남는다. 이 경우 성공사례 대본 분석은 PC 실행 결과를 쓴다.
4. **작은 채널 성공 사례 수집 (사용자 지시 2026-10-12 — 지시사항의 근거는 이것)**: `python3 tools/outlier_research.py <주제폴더> [다른 주제…]`
   - 기준: **최근 180일**(모자라면 365일) · **구독자 5만 명 이하** · **조회수 ≥ 구독자 × 3** · 조회수 1만 이상 · **4분 이상(쇼츠 제외)** · 채널당 2개까지 → 배수 순 `--top`개(PC 실행 20)를 자세히(설명·챕터·자막·썸네일·**댓글 전부**).
   - **조회수 상위 (사용자 지시 2026-10-13 — 구독자 수 상관없음):** 같은 후보에서 주제 관련(keywords.toml 관련어, 분석기와 같은 규칙)·4분 이상·최근 365일 → 조회수 순 `--popular`개(기본 20), 채널당 2개 → 같은 방법으로 자세히 (폴더 `P01_<영상ID>`, `popular.csv`).
   - **댓글은 전부 (v1.3):** 최상위 댓글(시간순, 100개씩)과 답글(5개 넘으면 comments.list)을 쪽마다 저장해 할당량이 끝나도 다음 실행이 이어 받는다. `comments.csv`에 답글 여부·채널 주인 댓글 표시, 작성자 이름은 저장하지 않음. 할당량 ≈ 영상마다 (최상위 댓글 수 ÷ 100) + 답글 많은 댓글 수.
   - 분석기의 `result/success_cases/`(8개)는 쇼츠·대형 채널이 섞여 있다(점수의 35%가 조회수). **지시사항의 근거로 쓰지 않는다** (참고만).
   - 키: `YOUTUBE_API_KEY`(클라우드 환경 변수 또는 집 PC의 `.env`). 할당량: 검색어 수 × 2(4~20분·20분 넘음) × 100단위 (재테크 검색어 40개 = 80번 = 8,000 + 잘된 영상 태그 10번. 하루 10,000 — 분석기와 같은 키면 나눠 쓰고, 넘으면 다음 날 이어서).
   - **검색어 = 실제 영상 태그 (사용자 지시 2026-10-13):** `python tools/tag_keywords.py <주제폴더> --write-keywords` — 씨앗 검색(`tag_rules.toml`의 TAG_SEEDS, 약 800단위) + 받은 영상 중 주제 관련 영상의 태그에서 빼는 말(경제·뉴스·금리·종목 이름 등)을 빼고 채널 5곳 이상이 쓴 것을 채널 수 순으로 40개 → `<주제폴더>/keywords.txt`를 다시 씀 (표 `<주제폴더>/tag_candidates.md`, 있던 것은 `.bak`).
   - 검색어는 **`<주제폴더>/keywords.txt`**(한 줄에 하나, 그룹 없음 — 분석기와 같은 파일)의 검색어 **전부** (없으면 `keywords.toml`의 묶음). 사용자가 GitHub 에서 고치면 PC(`pc_analysis.py` v1.7)가 회차마다 받아 쓰고, 검색어가 바뀌면 분석기도 다시 돈다 (사용자 지시 2026-10-13). **다시 돌리면 이어서 (v1.2):** 검색 결과 7일·영상 정보 24시간·구독자 7일 캐시, 이미 받은 자막·댓글은 다시 받지 않음. 할당량이 끝나면 캐시로 결과를 만들고 남은 일을 `status.json`의 `pending`에 적는다(종료 코드 3).
   - **자막은 클라우드 IP에서 막힌다**(2026-10-12 확인). 도입부·말 속도 분석이 필요하면 집 PC에서 같은 명령을 돌린다. 못 받으면 설명·챕터·댓글로만 분석하고 "자막 없음"이라고 적는다.
   - 키가 없을 때 임시로: `--from-existing`(분석기 결과에서 같은 기준으로 고름 — 분석기 검색이 최근만 본 것이 아니라 사례가 적을 수 있다).
   - 결과: `<주제폴더>/result/outliers/` — `outliers.csv`·`popular.csv`·`candidates.csv`·`summary.md`·`status.json`은 항상 올림. 사례 폴더(자막·댓글 전부·썸네일)는 **저장소가 비공개일 때만** 올린다 (PC 실행 분석기 v2.5.0이 공개 여부를 확인하고 `git add -f`. .gitignore 는 공개일 때를 막으려고 그대로).
   - **숫자 다시 계산 (2026-10-12):** `python3 tools/outlier_stats.py <주제폴더> --skip-ranks <주제 밖 순위> --group "이름=순위,…"` — 제목 요소·길이·채널 크기별 성공 비율(`candidates.csv`)과 댓글 갈래(사례 폴더 `comments.csv`)를 `data_insights.md` 표 모양으로 낸다.
   - **같은 날 분석기와 함께 돌리면** 둘 다 같은 키의 하루 10,000단위를 나눠 쓴다 (2026-10-12 주식: 성공 사례 `--per-group 2` 3,653 + 분석기 5,833). `tools/run_analysis.sh` v1.1부터 `result/outliers/`를 지우지 않는다 (v1.0은 지웠다).

## 2단계 — 지시사항 만들기·고치기, 주제 탐색

## 4단계 — 오디오가 생기면 렌더·비공개 업로드

**오디오 경로:** `<주제폴더>/source/<영상ID>/narration.mp3` (또는 `.wav`, `.m4a`)
- **만드는 법:** 위 3-6 (Kaggle 셀 하나 → 대본 폴더마다 자동으로 올라감). 직접 녹음해서 그 경로에 올려도 된다.
- 내레이션은 대본 TXT와 같은 문장이어야 한다. 고지 카드 자리(`[장면]` 바로 앞 문장 뒤)에서 **3.5초 이상** 쉰다.
- mp3·m4a를 권한다. wav는 크다 (GitHub 웹 업로드는 파일당 25MB까지).
- 저장소가 공개라서 올린 오디오는 누구나 들을 수 있다.

**진행:** 사용자가 "오디오 올렸어" / "4단계 진행해"라고 하면 Claude가 실행한다. **사용자 승인을 기다리지 않는다** (사용자 지시 2026-10-10: "오디오 만들어지면 그냥 영상 만들어").
```
git pull origin main          # Kaggle이 올린 오디오(narration.mp3·tts_narration.json·tts_report.md) 받기
bash tools/publish.sh --dry-run    # 대상 확인: 영상 코드가 없는 영상, 옛 대본으로 만든 오디오는 건너뜀으로 나온다
python tools/tts_narration.py check <주제폴더> <영상ID>   # 오디오가 지금 대본으로 만든 것인지 (publish.sh 도 확인)
bash tools/publish.sh          # 오디오가 있고 아직 안 올린 영상 → 최대 3개
```
영상마다:
0. **영상 코드가 없으면 Claude가 먼저 만든다** — `video_guide.md` 6번(장면 구성·연출 규칙), 추정 SRT 타이밍으로. Claude가 still 몇 장으로 겹침·글자 잘림·색 규칙을 스스로 점검하고 바로 다음으로 간다. 스토리보드 문서·사용자 승인은 없다. (점검용 still은 저장소에 올리지 않는다.)
1. `npm run align-audio` — 오디오는 고치지 않고 SRT를 오디오에 맞춘다. 고지 카드 자리의 쉼이 3.5초보다 짧으면 멈추고 사용자에게 알린다 (재녹음 또는 그 자리만 편집).
2. 타입 검사.
3. 완성 영상 렌더 → 길이·오디오 트랙 확인. 4코어 기준 8분 영상에 약 10~15분.
   - 3-1. **음량 맞춤** (사용자 지시 2026-10-11): `tools/loudnorm.py` → -14 LUFS·트루 피크 -1.5 dBTP 이하. 영상 하나에 약 1분. 유튜브는 작은 소리를 키워 주지 않아서다 (`video_guide.md` 2번).
4. `tools/youtube_upload.py` — **비공개** 업로드 + **예약 공개(렌더가 끝난 시각 + 1시간)**. 영상 하나마다 다음을 등록한다.
   - 예약 공개: 비공개로 올리고 `publishAt`을 넣는다. 그 시각에 유튜브가 공개로 바꾸고 구독자 알림도 그때 간다. 그 1시간 동안 사용자가 스튜디오에서 영상·자막·썸네일·자동 더빙을 확인한다.
   - 바꾸기: `--publish-delay 3h`(다른 간격), `--no-schedule`(예약 없이 비공개만)
   - 채택 제목, 설명란(챕터를 맞춘 SRT로 다시 계산), 태그, 카테고리 교육, 언어 한국어, 아동용 아님, **변경되거나 합성된 콘텐츠: 예**(AI 음성 내레이션, 사용자 지시 2026-10-11)
   - 한국어 자막(SRT 그대로)
   - 썸네일 1개: 채택 제목의 짝. `source/<영상ID>/thumbnails/thumbnail_N.png`(또는 .jpg·.webp)가 있으면 1280×720·2MB 이하 JPG로 맞춰 올린다. 없으면 건너뛴다.
5. `source/<영상ID>/youtube.json` 기록(영상 ID·스튜디오 링크) → 요약 문서 갱신 → main에 커밋·푸시.
- 한 번에 **최대 3개**. 업로드 할당량 때문이다. 나머지는 다음 실행에서 한다.
- 이미 올린 영상(`youtube.json` 있음)은 다시 올리지 않는다.

**예약 공개를 멈추려면:** 예약 시각 전에 스튜디오 → 해당 영상 → 공개 상태를 "비공개"로 바꾼다 (예약이 취소된다).

**API로 할 수 없는 것 (사용자가 스튜디오에서):**
- 썸네일 **"테스트 및 비교"(3개)**: API는 썸네일 1개만 등록한다. 테스트 및 비교는 **비공개 영상에는 쓸 수 없다**. 공개(또는 일부 공개)로 바꿀 때 썸네일 3개를 넣는다. 제목 테스트를 지원하면 titles.md의 T2·T3도 넣는다.
- 자동 더빙: 유튜브가 한국어 음성을 영어·인도네시아어로 더빙한다. 스튜디오 → 언어에서 확인·게시한다.
- 최종 화면.

**⚠️ 업로드 주의 — 비공개 잠금:** Google 감사(audit)를 받지 않은 API 프로젝트로 올린 영상은 **비공개로 잠겨 공개로 바꿀 수 없다**. 예약 공개를 걸어도 감사 전에는 공개되지 않는다.
- 공개하려면 둘 중 하나다.
  - ① Google에 "YouTube API Services 감사·할당량 확장" 신청 (심사 기간 수 주)
  - ② 비공개 업로드는 검수용으로 쓰고, 공개할 영상은 스튜디오에서 mp4를 직접 올린다
- mp4는 git에 없으므로 Claude에게 "<영상ID> 영상 파일 보내줘"라고 하면 받을 수 있게 보내 준다 (용량이 크면 압축본).

4. 만든 키의 "키 수정"에서 제한을 건다.
   - API 제한사항: "키 제한" → **YouTube Data API v3**만 선택
   - 애플리케이션 제한사항: **없음** (클라우드 서버 IP가 바뀌므로 IP 제한을 걸면 막힌다)
5. 키 값(`AIza…`로 시작)을 E의 방법으로 `YOUTUBE_API_KEY`에 넣는다.
- PC에서 분석기를 돌릴 때는 지금처럼 `.env` 파일에 넣는다. 클라우드에서는 `.env`가 필요 없다.

### B. 업로드용 OAuth `YOUTUBE_CLIENT_ID` · `YOUTUBE_CLIENT_SECRET` · `YOUTUBE_REFRESH_TOKEN` (4단계)
분석용과 **다른 프로젝트**로 만든다. 할당량이 프로젝트마다 따로라서, 업로드가 분석 할당량을 쓰지 않게 하기 위해서다.
1. 새 프로젝트를 만든다. 이름 예: `ytb-upload` → **YouTube Data API v3** 사용 설정 (A의 2번과 같음)
2. **OAuth 동의 화면** ("Google 인증 플랫폼"이라고 나올 수 있음)
   - 앱 이름(아무거나, 예: ytb-uploader), 지원 이메일 = 내 메일, 대상 = **외부**
   - "대상(Audience)"에서 **앱 게시 → 프로덕션**으로 바꾼다.
     - 테스트 상태로 두면 리프레시 토큰이 **7일 뒤 만료**된다.
     - 나 혼자 쓰므로 Google 검토 없이 쓸 수 있다. 로그인할 때 "확인되지 않은 앱" 경고가 나오면 "고급" → "(앱 이름)(으)로 이동"을 누른다.
3. **클라이언트** ("사용자 인증 정보" → "OAuth 클라이언트 ID") → 애플리케이션 유형 **데스크톱 앱** → 만들기
   - 클라이언트 ID와 클라이언트 보안 비밀번호를 복사한다.
4. **내 PC에서** 토큰을 한 번 발급한다 (Python 3 필요).
   ```
   python youtube_auth.py --client-id <클라이언트 ID> --client-secret <클라이언트 보안 비밀번호>
   ```
   - `youtube_auth.py`는 https://raw.githubusercontent.com/yeomin1024/yeomin1024-ytb/main/tools/youtube_auth.py 에서 받는다.
   - 브라우저가 열리면 **영상을 올릴 채널의 구글 계정**으로 로그인한다. 브랜드 계정 채널이면 그 채널을 고른다. → 허용
   - 터미널에 3줄이 나온다: `YOUTUBE_CLIENT_ID=…`, `YOUTUBE_CLIENT_SECRET=…`, `YOUTUBE_REFRESH_TOKEN=…`
5. 3개를 모두 E의 방법으로 넣는다.
6. 확인: 다음 세션에서 Claude에게 "유튜브 키 확인해줘"라고 하면 `python tools/youtube_upload.py --check-auth`로 채널 이름만 확인한다 (업로드 안 함).

### C. 채널 설정
- 맞춤 썸네일을 올리려면 채널 **전화번호 인증**이 필요하다: https://www.youtube.com/verify
- 비공개 잠금을 풀려면 B 프로젝트로 감사 신청: Google의 "YouTube API Services - Audit and Quota Extension Form" (4단계 "업로드 주의")

### D. 썸네일 이미지 (영상마다)
1. `summary.md`의 "썸네일 3개"에서 [A] 프롬프트를 이미지 AI(ChatGPT, Gemini 등)에 넣는다.
   - thumbnail_3(검은 배경 제목형)은 글자만 있어서 이미지 AI 없이 캔바 등에서 [B] 안내대로 바로 만들어도 된다.
   - 한글이 틀리게 나오면 [B] 글자 없는 프롬프트로 만들고 편집기로 문구를 얹는다.
2. 이미지를 `<주제폴더>/source/<영상ID>/thumbnails/thumbnail_1.png`(2·3도 같은 규칙)로 저장해 GitHub에 올린다.
   - 크기는 맞추지 않아도 된다. 업로드할 때 1280×720·2MB 이하로 자동 변환한다.
   - 업로드 때는 채택 제목의 짝 1개만 등록된다. 3개는 공개 전환 때 테스트 및 비교에 쓴다.

### E. 키를 넣는 곳 (Claude Code 클라우드 환경)
1. 세션 화면 위쪽 제목 줄의 **클라우드 환경 이름**(환경 메뉴)을 누른다 → **편집(Edit)**
2. **Network secrets**(앱 버전에 따라 "API credentials") 칸이 있으면 그곳에, 없으면 **환경 변수(Environment variables)** 칸에 한 줄에 하나씩 넣는다.
   ```
   YOUTUBE_API_KEY=AIza...
   YOUTUBE_CLIENT_ID=....apps.googleusercontent.com
   YOUTUBE_CLIENT_SECRET=GOCSPX-...
   YOUTUBE_REFRESH_TOKEN=1//...
   ```
3. 저장 → **새 세션**을 시작한다 (지금 세션에는 반영되지 않는다).
- GitHub 토큰(`GITHUB_TOKEN`)은 클라우드에서는 필요 없다. Claude가 세션의 git으로 main에 푸시한다.
