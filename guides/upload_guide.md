## 1. 절대 규칙

1. **설명란·태그·고정 댓글의 숫자와 사실은 대본·README에 있는 것만** 쓴다. 새 숫자를 만들지 않는다.
2. **제목·썸네일·설명란 첫 줄이 같은 약속**을 한다. 영상에 없는 내용을 설명란에서 약속하지 않는다.
3. 주제 규칙이 요구하는 고지(예: 주식의 투자 유의 사항, 재구성 사연 문구)를 설명란에 **화면 카드와 같은 문장으로** 넣는다.
4. 챕터 시간은 **손으로 계산하지 않는다.** `tools/srt_tool.py upload`가 SRT(= 영상 시간)에서 문장 번호로 계산한다 (3번).
5. 자막 타이밍이 바뀌면(내레이션 녹음 후 `npm run align-audio` 등) 영상을 다시 렌더하고 챕터도 다시 계산한다.

## 2. 설명란 구조

YouTube는 설명란 첫 2줄(약 100자)만 "더보기" 전에 보여 준다. 그래서 순서를 고정한다.

| 순서 | 내용 | 규칙 |
|---|---|---|
| ① 첫 2줄 | 사연의 숫자 반전 + 영상이 알려 주는 것 | 제목을 그대로 반복하지 않는다. 핵심 검색어(예: 물타기, 손절)를 자연스럽게 넣는다 |
| ② 다루는 내용 | 문제 N가지·방법 N가지를 한 줄씩 | 대본 항목 이름 그대로. 사례 이름(연구자·사건)은 대본에 나온 것만 |
| ③ 챕터 | `0:00 제목` 형식 | 3번 규칙 |
| ④ 재구성·예시 고지 | 주제 규칙의 문구 | 사연이 재구성이면 반드시 |
| ⑤ 출처 | README의 출처 링크 | 숫자마다 어디서 왔는지 알 수 있게 |
| ⑥ 고지 | 화면 고지 카드와 같은 문장 | 주제 규칙 |
| ⑦ 해시태그 | 3개 | 처음 3개가 영상 제목 근처에 표시된다. 그 이상은 쓰지 않는다 |

- 설명란 전체는 5,000자를 넘지 않는다.
- 이모지·과장 표현("무조건", "필수 시청")은 쓰지 않는다.

## 3. 챕터

- YouTube 챕터 조건: **첫 챕터 0:00, 챕터 3개 이상, 각 챕터 10초 이상, 시간 순서.** 하나라도 어기면 챕터가 표시되지 않는다.
- 챕터는 대본 파트와 항목 시작마다 하나씩 둔다: 사연 / 진행자 / 문제 01~N / 방법 첫째~N / 정리.
  - 고지 카드는 별도 챕터로 만들지 않는다 (보통 10초 미만). 앞 챕터 끝에 붙는다.
- 제목은 그 구간에서 시청자가 얻는 것을 짧게 쓴다 (번호 타이틀 문구와 같게).
- 계산 명령 (저장소 최상위에서):
  ```
  python tools/srt_tool.py upload <주제폴더>/source/<영상ID>/<영상ID>.txt <주제폴더>/source/<영상ID>/<영상ID>.srt \
      --chapters "1=사연 …;15=…;24=…"
  ```
  - `문장번호=챕터 제목`을 `;`로 잇는다. 숫자는 **대본 문장 번호**다 (SRT 번호 아님). 첫 항목은 `1=`.
  - 출력된 챕터 줄을 설명란 ③에 붙인다. "✅ YouTube 챕터 규칙 통과"가 나와야 한다.
  - SRT는 영상 시간과 같으므로(고지 공백이 SRT 안에 있음) **SRT 파일을 그대로 업로드**한다. 업로드용 SRT를 따로 만들지 않는다.

## 4. 태그와 해시태그

- 태그: 10~15개, 합계 500자 이하. 순서 = 핵심 검색어 → 넓은 주제어 → 사례 이름.
- 해시태그(설명란 끝): 3개. 핵심 행동(예: #물타기) + 주제(예: #주식) + 해결(예: #손절).
- 제목·설명란에 없는 낚시성 태그(유명인 이름 등)는 넣지 않는다.

## 5. 고정 댓글

업로드 직후 채널 계정으로 댓글을 달고 "고정"한다.

1. 영상의 핵심 행동 1~2가지를 체크리스트로 (마무리 파트의 권유와 같은 내용)
2. 시청자 경험을 묻는 질문 1개 (예: "이런 적 있나요? 그때 기준이 있었나요?")
3. 주제 규칙의 짧은 고지 한 줄

- 3~6줄로 짧게. 링크는 넣지 않는다.

## 6. 업로드 설정

| 항목 | 값 |
|---|---|
| 제목 | `titles.md`의 채택 제목 (100자 이하) |
| 썸네일 | 채택 제목의 짝 썸네일을 기본으로 올린다 (API 업로드 때 자동). **테스트 및 비교**에는 공개(또는 일부 공개)로 바꿀 때 3개 모두 넣는다 — 비공개 영상은 테스트 불가 |
| 자막 | `<영상ID>.srt` 그대로 "타이밍 포함 파일"로 업로드, 언어 한국어 (SRT = 영상 시간. 화면에 자막이 이미 있으므로 검색·자동 번역용) |
| 카테고리 | 교육 (주제 규칙이 다르게 정하면 그쪽) |
| 동영상 언어 | 한국어 |
| 시청자층 | 아동용 아님 |
| 유료 프로모션 | 없음 (협찬이 있으면 "예") |
| 변경되거나 합성된 콘텐츠 | **예** (사용자 지시 2026-10-11). 내레이션(사연자·진행자)이 실제 사람처럼 들리는 AI 합성 음성이고, 재구성 사연을 실제 고백처럼 읽기 때문이다. `tools/youtube_upload.py`가 업로드 시트의 이 줄을 읽어 `status.containsSyntheticMedia`로 등록한다 (줄이 없으면 예) |
| 최종 화면 | 마지막 5~20초에만 넣을 수 있다. 마무리 요약을 가리면 넣지 않거나, 영상 끝에 빈 화면을 5~10초 더해 다시 렌더한다 |

## 7. 업로드 뒤 기록

- 48시간 뒤와 7일 뒤에 스튜디오 수치를 본다: 노출 클릭률, 평균 시청 지속 시간, 시청 지속 그래프에서 크게 떨어지는 구간(챕터·자막 번호로 적기).
- "테스트 및 비교" 결과는 `titles.md`, `thumbnails/thumbnail_N.md`의 결과 칸에 적는다.
- 크게 떨어지는 구간은 다음 대본에 반영할 점으로 `upload.md` 끝 "결과"에 적는다.

## 9. API 자동 업로드 (비공개) — `guides/pipeline.md` 4단계

오디오가 생겨 렌더가 끝나면 `bash tools/publish.sh`가 영상마다 `python tools/youtube_upload.py <주제폴더> <영상ID>`를 실행한다.

| 항목 | 값 (upload.md에서 읽음) |
|---|---|
| 공개 상태 | **비공개 + 예약 공개**: 렌더가 끝난 시각 + 1시간 (`publish.sh` 기본, `--publish-at +1h`). 예약 없이 비공개만: `--no-schedule` |
| 제목 | 1번 코드 블록 |
| 설명란 | 2번 코드 블록. "■ 챕터" 줄은 3번 `--chapters` 명령으로 **지금 SRT(오디오에 맞춘 것)**에서 다시 계산해 바꿔 넣는다 |
| 태그 | 4번 코드 블록 (쉼표 구분, 합계 500자 이하 검사) |
| 카테고리·언어 | 교육(27) · 한국어 · 아동용 아님 |
| 자막 | `<영상ID>.srt` 그대로 (한국어) |
| 썸네일 | titles.md 채택 제목의 짝 `thumbnails/thumbnail_N.*` 1개 — 1280×720·2MB 이하로 자동 변환. 없으면 건너뜀 |
| 기록 | `source/<영상ID>/youtube.json` (영상 ID, 스튜디오 링크, 업로드 시각, 예약 공개 시각 `publishAt`, 챕터, 경고) — 있으면 다시 올리지 않음 |

- 먼저 `--dry-run`으로 읽은 값과 규칙(제목 100자, 설명란 5,000자, `< >` 금지, 태그 500자)을 확인한다. 문제가 있으면 올리지 않는다.
- 키: 환경변수 `YOUTUBE_CLIENT_ID`·`YOUTUBE_CLIENT_SECRET`·`YOUTUBE_REFRESH_TOKEN` (`guides/pipeline.md` "처음 한 번 할 일" B). 확인만: `--check-auth`
- 한 번에 최대 3개 (업로드 할당량).
- **API로 안 되는 것:** 테스트 및 비교(썸네일 3개·제목), 최종 화면, 자동 더빙 확인 → 스튜디오에서 사용자가 한다. 예약 공개 전 1시간 안에 확인한다.
- ⚠️ Google 감사를 받지 않은 API 프로젝트로 올린 영상은 비공개로 잠긴다. 공개하려면 감사를 신청하거나, 스튜디오에서 mp4를 직접 올린다.

## 10. 올린 영상 줄이기 — 스튜디오 컷 (사용자 지시 2026-10-12)

올린 영상은 오디오·영상 파일을 바꿀 수 없다(바꾸려면 새 영상으로 다시 올려야 하고 조회수는 0부터). 대신 스튜디오 → 편집기 → **자르기 및 컷 → 새 컷**으로 가운데 구간을 빼면 URL·조회수·댓글이 그대로다 ([YouTube 고객센터 '동영상 자르기'](https://support.google.com/youtube/answer/9057455)).

1. 뺄 문장을 정한다 (예: 사연 20~30초 규칙에 맞추기 — `archive/script_guide_v1.md` 0-1의 13번 — 사연 파트가 있을 때). 제목이 약속한 숫자와 마지막 자책 한 문장은 남긴다. 처음·마지막 문장은 이 방식으로 빼지 않는다.
2. `python tools/studio_trim.py plan <주제폴더> <영상ID> --drop 2-8,10 --preview 미리보기.mp4` — 자를 시각(원본 영상 시간, 0.1초 단위)을 계산한다.
   - 컷 시작 = 앞 문장 소리가 끝난 뒤 + 빼는 문장 화면이 바뀌기 전, 컷 끝 = 뒤 문장 화면이 바뀐 뒤 + 그 문장 소리가 시작되기 전.
   - 0.1초 단위가 창 안에 없으면 소리를 자르지 않는 쪽을 고르고 '빼는 문장 화면 N프레임'으로 알려 준다.
   - 렌더한 영상(`<주제>/out/<영상ID>/final_1080p.mp4`)이 있어야 화면 프레임·미리보기를 정확히 잰다 (없으면 `narration.mp3`로 소리만).
3. 미리보기를 사용자가 확인하면 `apply` → 대본·SRT를 잘라 낸 영상 기준으로, `upload.md` 설명란 챕터·3번 명령(문장 번호), `youtube.json`(`chapters`, 옛 값 `chaptersBeforeTrim`, `studioTrim`), 사용자용 작업 순서 `<영상ID>/studio_trim.md`를 만든다. 영상 코드·`narration.mp3`·`tts_narration.json`은 원본 렌더 기록이라 그대로 둔다(다시 렌더하지 않음).
4. 사용자가 스튜디오에서 컷을 **뒤에서부터** 넣고 미리보기로 듣고 저장 → 처리가 끝나면 설명란 '■ 챕터'를 `studio_trim.md` 3번으로 바꾼다.
- ⚠️ 저장한 편집은 '원본으로 되돌리기'가 안 된다 (2025년 6월부터). 조회수 10만이 넘은 영상은 파트너 프로그램이 아니면 저장이 막힐 수 있다.
- 자막은 화면에 박혀 있어 함께 잘린다. 유튜브 자막 파일을 따로 올렸다면 잘라 낸 SRT로 다시 올린다.

사용자 지시: "영상 만들었으면 각 영상 압축해서 저장소에 올리고 실행하면 해당 영상 유튜브에 자동 예약으로 1시간 후 업로드하는 colab 코드 전체 하나로 알려줘".

1. **Claude** — 렌더가 끝나면 영상마다 압축본을 저장소에 올린다: `python tools/compress_video.py <주제> <영상ID>` (또는 `--all`)
   → `<주제>/source/<영상ID>/final_1080p.mp4` + 기록 `final_1080p.json`.
   - 영상 H.264 CRF 23·medium·tune animation, 소리 AAC 96 kbps 단일 채널. 원본(CRF 18)과 SSIM 0.999 이상, 음량 -14 LUFS·트루 피크 -1.5 dBTP 이하 그대로 (넘으면 소리는 원본 복사). 8분 영상 약 20MB (GitHub 한 파일 한도 100MB, 95MB 넘으면 멈춤).
   - 업로드 시트 `upload.md`(8번)도 같이 올린다. 제목은 시트 1번 코드 블록 — 바꾸려면 GitHub 에서 그 줄만 고친다.
2. **사용자** — Colab 에 아래 셀 하나를 붙여 실행한다. 처음 한 번만 왼쪽 🔑(보안 비밀)에 `GITHUB_TOKEN`(Kaggle 과 같은 토큰)·`YOUTUBE_CLIENT_ID`·`YOUTUBE_CLIENT_SECRET`·`YOUTUBE_REFRESH_TOKEN`(`pipeline.md` '처음 한 번 할 일' B, 클라우드 환경에 넣은 값과 같음)을 넣고 **노트북 액세스**를 켠다.
3. 셀이 하는 일 (`tools/colab_youtube.py`):
   - 저장소에서 `tools`·`economic/source`만 받는다 (비공개 저장소도 — 토큰을 git 머리글로, 값은 출력하지 않음).
   - 준비된 영상(시트·영상 파일이 있고 `youtube.json`이 없는 것)마다 `youtube_upload.py`로 **비공개 업로드 + 실행 시각 + 1시간 예약 공개**, 자막(SRT)·썸네일(있으면)·합성 콘텐츠 '예'.
   - 영상 하나가 끝날 때마다 `youtube.json`을 main 에 올린다 → 셀을 다시 실행해도 같은 영상을 두 번 올리지 않는다.
   - 끝에 표: 영상 · 결과 · 유튜브 주소 · 공개 시각(한국).
   - 할당량: 영상 하나 약 2,050단위, 하루 10,000 → **하루 최대 4개** (`--max 4`). 넘으면 멈추고 다음 날 같은 셀을 다시 실행.
   - 영상 여러 개를 같은 시각에 공개하지 않으려면 `GAP = "24h"` (하루에 하나씩).
   - 먼저 확인만: `DRY_RUN = True` (키 없이도 된다).

```
# 유튜브 예약 업로드 — Colab 셀 하나 (guides/upload_guide.md 11번)
# 처음 한 번: 왼쪽 🔑(보안 비밀)에 GITHUB_TOKEN · YOUTUBE_CLIENT_ID · YOUTUBE_CLIENT_SECRET · YOUTUBE_REFRESH_TOKEN 을 넣고 '노트북 액세스'를 켠다
DELAY = "1h"      # 예약 공개 = 실행 시각 + 1시간
GAP = "0m"        # 영상이 여러 개일 때 공개 간격 ("24h" = 하루에 하나씩)
IDS = ""          # 비우면 준비된 영상 전부 · 하나만: "isa-mangi-2026-10"
DRY_RUN = False   # True = 올리지 않고 확인만

import os, sys, base64, subprocess
from google.colab import userdata
for k in ("GITHUB_TOKEN", "YOUTUBE_CLIENT_ID", "YOUTUBE_CLIENT_SECRET", "YOUTUBE_REFRESH_TOKEN"):
    try:
        os.environ[k] = userdata.get(k)
    except Exception as e:
        raise SystemExit(f"보안 비밀 {k} 를 읽지 못함 ({type(e).__name__}) → 왼쪽 🔑에 넣고 '노트북 액세스'를 켠 뒤 다시 실행")
os.environ.update(GIT_CONFIG_COUNT="1", GIT_CONFIG_KEY_0="http.https://github.com/.extraheader",
                  GIT_CONFIG_VALUE_0="AUTHORIZATION: basic " + base64.b64encode(("x-access-token:" + os.environ["GITHUB_TOKEN"]).encode()).decode())
R = "/content/yeomin1024-ytb"
def sh(*cmd):
    print("$", " ".join(cmd), flush=True)
    subprocess.run(cmd, check=True)
if not os.path.isdir(R):
    sh("git", "clone", "-q", "--depth", "1", "--filter=blob:none", "--sparse", "https://github.com/yeomin1024/yeomin1024-ytb.git", R)
sh("git", "-C", R, "sparse-checkout", "set", "tools", "economic/source")
sh("git", "-C", R, "fetch", "-q", "--depth", "1", "origin", "main")
sh("git", "-C", R, "reset", "-q", "--hard", "origin/main")
args = [sys.executable, f"{R}/tools/colab_youtube.py", "--delay", DELAY, "--gap", GAP] + (["--ids", IDS] if IDS else []) + (["--dry-run"] if DRY_RUN else [])
print("종료 코드", subprocess.run(args).returncode)
```

- ⚠️ 예약 시각 전에 스튜디오에서 영상·자막·썸네일을 확인한다. 썸네일 파일이 없으면 유튜브가 고른 장면이 쓰이니 스튜디오에서 바꾼다.
- ⚠️ Google 감사를 받지 않은 API 프로젝트로 올린 영상은 비공개로 잠겨 예약 공개가 되지 않을 수 있다 (`pipeline.md` '업로드 주의'). 그때는 압축본(저장소의 `final_1080p.mp4`)을 스튜디오에서 직접 올린다.
- 업로드를 취소하려면 스튜디오에서 그 영상을 지우고, 저장소의 `youtube.json`도 지운다 (다시 올릴 수 있게).
