# 사연형 설명 영상 — 썸네일 지시사항 (공통)

버전: v1.0 — 2026-10-09 — 최초 작성: 영상 하나당 썸네일 시안 3개의 프롬프트 파일, 제작 방법(Remotion Still / 이미지 AI), 분석 결과 반영

이 파일은 **모든 주제에 공통인** 썸네일 규칙이다. 아래 파일을 함께 읽는다.

| 파일 | 내용 |
|---|---|
| `<주제폴더>/guides/thumbnail_rules.md` (예: `stock/guides/thumbnail_rules.md`) | 주제 전용 규칙: 색의 의미, 숫자 표기, 금지 요소, 인물 사용 여부. **이 파일과 다르면 주제 규칙을 따른다.** |
| `<주제폴더>/guides/data_insights.md` 6번 | 성공 영상 썸네일 관찰 결과 |
| `<주제폴더>/source/<영상ID>/titles.md` | 그 영상의 제목 3개 (썸네일과 짝) |
| `<주제폴더>/source/<영상ID>/<영상ID>.txt` | 대본. 썸네일 숫자 = 사연 숫자 |
| `guides/video_guide.md` 3번 | 디자인 시스템(색·폰트) — 썸네일도 같은 것을 쓴다 |

---

## 0. 목표와 출력

- **목표:** 목록에서 스쳐 지나가는 시청자가 1초 안에 "내 얘기다 + 결과가 궁금하다"를 느끼게 한다. 영상 안에서 실제로 보여 주는 장면만 약속한다.
- **영상 하나당 시안 3개**를 만든다. 업로드 뒤 YouTube 스튜디오 **"테스트 및 비교"**(썸네일 최대 3개)로 시험해, 시청 시간 기준으로 이긴 것을 남긴다.
- **출력**
  - 프롬프트 파일 3개: `<주제폴더>/source/<영상ID>/thumbnails/thumbnail_1.md`, `thumbnail_2.md`, `thumbnail_3.md` (6번 형식)
  - 완성 이미지 3개 (제작 후): `<주제폴더>/out/<영상ID>/thumbnails/thumbnail_1.png` ~ `_3.png`

## 1. 절대 규칙

1. **썸네일 숫자 = 대본 사연 숫자 = 제목 숫자.** 하나라도 다르면 만들지 않고 알린다.
2. **문구는 제목을 반복하지 않는다.** 제목이 다 못 보여 주는 핵심 숫자 반전, 결정적 장면, 감정 한 마디 중 하나만 보탠다.
3. **문구는 2줄 이하**로 쓴다. 한 줄 10자 안팎, 전체 20자 이내다. 가장 중요한 숫자 하나를 가장 크게 쓴다.
4. **한 썸네일에 한 메시지만** 담는다. 요소(텍스트 덩어리·그림)는 3개 이하다.
5. **영상에 없는 장면·숫자를 넣지 않는다.** 썸네일이 약속한 장면은 영상 1분 안에 나와야 한다 (대본 지시사항 0-1의 13번).
6. **넣지 않는 것:**
   - 실존 인물 사진·얼굴
   - 실제 기업·서비스 로고와 실제 앱 화면 캡처
   - 실제 화폐 도안
   - 이모지
   - 특정 행동(주식: 매수·매도)을 권유하는 것처럼 보이는 연출
   - 인물·캐릭터 사용 여부는 주제 규칙을 따른다.
7. **오른쪽 아래 구석(약 220×70px)은 비운다.** 영상 길이 표시가 덮는다.
8. **작게 봐도 읽혀야 한다.** 가로 320px로 줄였을 때 문구와 핵심 숫자가 읽히는지 확인한다 (모바일 목록 크기).

## 2. 규격

| 항목 | 값 |
|---|---|
| 크기 | 1280×720 (16:9), PNG 또는 JPG, 2MB 이하 |
| 바깥 여백 | 48px (글자는 이 안에) |
| 핵심 숫자 | 글자 높이 150~230px, Noto Sans KR 900, 숫자 `tabular-nums` |
| 보조 문구 | 70~110px, Noto Sans KR 900 |
| 글자 외곽선 | 8~12px. 밝은 배경에는 잉크(#1E1E1E), 어두운 배경에는 흰색 또는 잉크 |
| 그림자 | 작은 그림자 허용 (정지 이미지라 렌더 부담 없음) |

## 3. 디자인 (영상과 같은 시스템)

- 색·폰트는 `guides/video_guide.md` 3-1·3-2를 그대로 쓴다. 채널을 처음 보는 사람도 영상과 썸네일이 같은 채널로 보이게 하기 위해서다.
  - 배경: 크림 #F2EBDD, 위기 장면이면 다크 네이비 #14213D
  - 글자: 잉크 #1E1E1E / 네이비 배경에서는 #F7F3EA
  - 노랑 강조 #FFD400는 **한 곳만**. 형광펜 위 글자는 배경과 상관없이 잉크 #1E1E1E로 쓴다 (흰 글자는 노랑 위에서 안 읽힘)
    - 크림 배경: 글자 아래쪽 절반에 형광펜 (영상과 같음)
    - 네이비 배경: 글자 **전체 높이의 노랑 상자**를 깐다 (절반만 칠하면 잉크 글자 윗부분이 네이비에 묻힘 — 미리보기로 확인함)
  - 수익·손실 색의 의미는 주제 규칙을 따른다 (주식: 수익 빨강 #E63B2E, 손실 파랑 #2D6CDF)
- 영상에 나오는 대상(예: 사연 주인공의 계좌 카드)을 썸네일에 쓰면 **영상과 같은 모양·같은 색**으로 쓴다.
- 장식용 도형·효과는 넣지 않는다.

## 4. 시안 3개 만드는 법

시안마다 **시험하는 가설(축)이 달라야** 테스트에서 배울 것이 생긴다. 기본 3축은 이렇다.

| 시안 | 축 | 만드는 법 | 짝 제목 (기본) |
|---|---|---|---|
| thumbnail_1 | **숫자 반전** | 사연의 시작 숫자 → 끝 숫자 (계좌 카드·카운터·화살표) | 숫자 반전이 강한 제목 |
| thumbnail_2 | **결정적 장면·비유** | 문제 행동의 순간을 오브젝트 하나로 (예: 버튼, 저울, 덫) + 짧은 문구 | 장면·계기 훅 제목 |
| thumbnail_3 | **대비** | 화면 분할. 왼쪽 = 나쁜 쪽, 오른쪽 = 좋은 쪽 (또는 기대 vs 결과) | 짧은 변형 제목 |

- 짝 제목은 `titles.md`의 T1~T3과 맞춘다. 다만 **어느 썸네일이든 3개 제목 모두와 어울려야** 한다. 테스트에서 제목·썸네일이 섞여 보일 수 있기 때문이다.
- 주제 규칙이 다른 축을 정하면 그것을 따른다.

## 5. 제작 방법 (둘 중 하나)

### 방법 1 (권장) — Claude Code가 Remotion `Still`로 렌더
한글 문구가 정확하고, 영상과 같은 공통 컴포넌트(계좌 카드 등)를 그대로 쓴다.
1. 저장소 최상위 `video/` 프로젝트를 쓴다 (`guides/video_guide.md` 2번).
2. `video/src/episodes/<영상ID>/thumbnails/Thumb1.tsx` ~ `Thumb3.tsx`를 만든다.
3. `video/src/Root.tsx`에 `<Still id="<영상ID>-thumb-1" component={Thumb1} width={1280} height={720} />`처럼 3개를 등록한다.
4. 렌더 (`video/` 폴더에서):
   `npx remotion still <영상ID>-thumb-1 ../<주제폴더>/out/<영상ID>/thumbnails/thumbnail_1.png`
5. 렌더한 3장을 직접 열어 7번 검수표를 통과시킨다. 그다음 `out/<영상ID>/thumbnails/index.html`(3장을 나란히, 320px 축소본도 함께)을 만들어 사용자에게 보여 준다.

### 방법 2 — 이미지 생성 AI(ChatGPT 등)로 배경·오브젝트를 만들고 글자는 따로 얹기
- 프롬프트 파일의 [B] 영문 프롬프트를 쓴다. 이미지 안에는 **글자·숫자를 넣지 않는다.** 이미지 AI는 한글을 자주 틀린다.
- 만든 이미지를 방법 1의 `Still` 배경으로 깔거나, 편집 프로그램(캔바, 포토샵 등)에서 프롬프트 파일의 문구 사양대로 글자를 얹는다.
- ※ 영상 지시사항의 "이미지 금지"는 **영상**에 대한 규칙이다. 썸네일은 이 방법을 써도 된다. 단, 1번 절대 규칙(인물·로고 등)은 그대로 지킨다.

## 6. 프롬프트 파일 형식 (`thumbnails/thumbnail_N.md`)

````markdown
# <영상ID> 썸네일 N — <축 이름>

버전: v1.0 — <날짜> — 대본 <영상ID>.txt vX.Y 기준

| 항목 | 값 |
|---|---|
| 시험하는 가설 | (예) 손실 금액이 10배로 커진 숫자 반전이 가장 클릭을 부른다 |
| 짝 제목 | titles.md T1 (다른 제목과도 어울리는지 확인함) |
| 숫자 근거 | 대본 자막 번호와 문장 (예: 자막 5 "-200만 원", 자막 10 "-2천만 원") |
| 배경 | 크림 / 네이비 |

## 화면 구성 (1280×720)
- 위치·크기를 적은 배치 설명 (왼쪽/가운데/오른쪽, 위/아래, px)

## 문구 (그대로 사용)
| 줄 | 문구 | 크기 | 색 | 강조 |
|---|---|---|---|---|

## [A] Claude Code 지시 (방법 1 — Remotion Still)
- 만들 파일, 쓸 공통 컴포넌트, 요소별 좌표·색, 렌더 명령

## [B] 이미지 AI 프롬프트 (방법 2 — 글자 없음)
```
(영문 프롬프트 — 스타일 문구 + 장면)
```
- 생성 후 [문구]를 편집에서 얹는다.

## 검수
- [ ] 7번 검수표 항목

## 결과 (업로드 후)
| 날짜 | 테스트 및 비교 결과 (시청 시간 비율) | 메모 |
|---|---|---|
````

## 7. 검수표 (시안마다)

- [ ] 숫자가 대본 사연·제목과 같은가 (자막 번호로 확인)
- [ ] 문구가 2줄 이하, 20자 이내이고 제목을 그대로 반복하지 않는가
- [ ] 320px로 줄여도 핵심 숫자와 문구가 읽히는가
- [ ] 노랑 강조가 한 곳뿐인가. 색의 의미가 주제 규칙과 영상과 같은가
- [ ] 오른쪽 아래 구석이 비어 있는가. 글자가 48px 여백 안에 있는가
- [ ] 인물·실제 로고·실제 앱 화면·화폐 도안·이모지·권유 연출이 없는가 (주제 규칙의 허용 범위 안인가)
- [ ] 3개 시안의 축(가설)이 서로 다른가
- [ ] 1280×720, 2MB 이하인가

## 8. 결과 반영

- "테스트 및 비교" 결과가 나오면 각 프롬프트 파일의 "결과" 칸과 `titles.md` 결과 칸에 적는다.
- 영상이 3개 이상 쌓이면 이긴 축(숫자 반전/장면/대비)을 `<주제폴더>/guides/data_insights.md`에 요약하고 주제 규칙의 기본 축 순서를 고친다.
