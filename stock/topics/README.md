## 사용자가 하는 것
- 평가판에서 좋음·나쁨을 누름 (또는 Claude 에게 'T003 좋아, T007 별로' · 또는 GitHub 에서 `평가.txt` 에 줄을 더함). 까닭을 적으면 다음 후보를 쓸 때 참고.
- 주제를 골라 Claude 에게 "T003 으로 요약본 만들어" → 그 주제는 작성중.

## Claude 가 하는 것 (순서)
1. **평가 가져오기**: `ArtifactData list` (url = 위 주소, collection `marks`) → 결과를 스크래치 파일에 그대로 저장 → `python3 tools/topic_ideas.py stock import <파일>` → `평가.txt` 에 바뀐 것만 더함 → 점수·문서 다시. 채팅 평가는 `python3 tools/topic_ideas.py stock mark T003 좋음 "까닭"`.
2. **쓰기 시작**: 요약본에 `주제 ID: T003` 한 줄 (저절로 작성중) 또는 `… use T003 <영상ID>` · 다 쓰면 `… done T003`.
3. **갱신**: `… status` 가 '갱신 필요'(이번 20개가 모두 작성중·작성함·나쁨)면 → `… material` → `material.md` 를 읽고 **새 후보 25개 안팎**을 `pool/<날짜>.json` 에 (배운 것의 좋은 갈래 쪽으로, 나쁜 갈래는 줄임) → `… add pool/<날짜>.json` → 새 20개 (대기 후보와 함께 겨룸) → 평가판을 같은 주소로 다시 올림 (Artifact publish `url`).

## 후보 한 개 (pool JSON — 칸은 `material.md` 머리 표)
- **결론 = 예상 결론 한 문장, 숫자·판정으로** ('…보다 …가 더 남았다', 'N년 이상이면 손실 0%'). 애매한 말(상황에 따라·~일 수도·신중·장단점…)이 있으면 도구가 뺀다.
- **판정 규칙** = 자료가 어느 쪽으로 나와도 결론이 하나로 정해지는 기준 ('A가 B보다 높은 구간이 50% 넘으면 A, 아니면 B'). 기준(보다·이상·%·비율…)이 없으면 뺀다.
- **자료** = 실제 미국 주가·지수·재무제표·법령 + 기간(연도). 2000년 이후 (1900년대 자료 ✗).
- 이미 쓴·쓰는 주제와 같으면 뺀다: 낱말 닮음 ≥ 0.40 또는 글자 겹침 ≥ 0.50 (올린 영상 · 옛 대본 · `stock/source/*/요약본.txt` 방향·항목·사례·제목 · 앞서 낸 주제).

## 점수와 배우기
- 처음 점수 = 댓글 니즈 👍 · 주제 묶음 성공 비율 · 페르소나 몫 · 공급 틈 · 성공 사례 제목 닮음 (무게는 `settings.toml [score]`).
- 배운 점수 = 갈래(페르소나·형식·주제 묶음·시장·자료·니즈)마다 log((좋음+1)/(나쁨+1)) 평균 + 가장 닮은 좋음 주제 − 가장 닮은 나쁨 주제.
- 평가가 5개를 넘으면 새 20개 중 3자리는 아직 평가 없는 갈래에서 (좋은 쪽만 파다 새 좋은 쪽을 놓치지 않게).
- 2026-10-28 시험 (복사본에서): 좋음 3·나쁨 3을 넣자 '주가 백테스트·실험형' 주제가 오르고 '배당 테스트형'이 내려감 · 다 쓴 묶음은 대기 후보로 갱신되고 탐색 자리 3개가 채워짐.

## 한계
- 주제 글은 Claude 가 쓴다 — 도구는 거르고·점수 매기고·뽑고·배운다. 결론은 계산 전 예상이며, 판정 규칙으로 계산 뒤 하나로 정해진다.
- 겹침은 글자·낱말 닮음 — 같은 실험을 아주 다른 말로 쓰면 못 잡을 수 있어 '가장 닮은 쓴 주제'를 문서에 함께 보인다.
- 평가가 적을 때 배운 점수는 흔들린다 (평가 1~2개로 갈래 하나가 ±0.69).
