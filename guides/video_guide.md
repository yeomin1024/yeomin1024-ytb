# 주식 유튜브 모션그래픽 영상 제작 지시사항 (Claude Code용, 범용)

버전: v3.0 — 2026-10-06 — 특정 영상 전용 내용을 걷어내고, 어떤 대본이든 같은 품질로 만들 수 있는 범용 지시사항으로 개정

이 지시사항은 대본이 바뀌어도 그대로 쓴다. 영상마다 달라지는 것(데이터 시트, 장면 구성표)은 Claude Code가 대본을 읽고 이 문서의 규칙에 따라 직접 만든다.

---

## 0. 목표와 입력 파일

**목표:** 주식을 시작한 지 얼마 안 됐거나 손실을 본 시청자가, 자막을 읽는 동시에 화면만 봐도 내용이 한눈에 이해되는 고품질 Vox 스타일 설명 영상을 만든다. 단, 제작과 렌더에 시간이 과하게 들지 않게 한다.

**입력 파일 (이 폴더에 있음)**
| 파일 | 용도 |
|---|---|
| 대본 SRT 파일 1개 | 자막 텍스트와 타이밍의 기준 |
| 대본 TXT 파일 1개 | 파트 라벨(`-사연 파트` 등), `[장면]` 화면 지시와 그 문구 확인용 |
| `narration.mp3` 또는 `narration.wav` (선택) | 내레이션. 있으면 넣고, 없으면 무음으로 만든다 |
| `bgm.mp3` (선택) | 배경음악. 있으면 내레이션보다 -18dB 정도 낮게 깐다 |

SRT나 TXT가 여러 개면 어떤 파일을 쓸지 먼저 묻는다.

**출력 (영상마다 `out/<영상ID>/` 아래)**
1. `scene_plan.md` — 장면 구성표 (5번 규칙으로 작성)
2. `storyboard/` — 장면별 샘플 이미지와 확인용 페이지 (**전체 렌더 전에 반드시 먼저 보여 준다**)
3. `final_1080p.mp4` — 1920×1080, 30fps (사용자 승인 후 렌더)

`<영상ID>`는 SRT 파일명을 영문 소문자·하이픈으로 바꾼 것으로 한다. (예: `molppang-2026-10`)

## 1. 절대 규칙

1. **이미지를 쓰지 않는다.** 사진, PNG/JPG, AI 생성 이미지, 스톡 영상, 이모지 모두 금지. 모든 시각 요소는 코드로 그린 벡터(SVG, CSS 도형)와 텍스트로만 만든다. 사람 얼굴·인물 그림도 그리지 않는다.
2. **실제 기업 로고를 그리지 않는다.** 기업은 이름이나 티커 텍스트로 표시한다.
3. **숫자는 데이터 시트(4번)의 값만 쓴다.** 새 숫자를 지어내지 않는다. 실제 데이터가 아닌 개념 그래프는 축 눈금 숫자를 넣지 않고, 구석에 작게 "개념도"라고 쓴다.
4. **자막 문장은 SRT 그대로 쓴다.** 대본 내용을 바꾸거나 추가하지 않는다.
5. **장면 적합성 (가장 중요):** 화면의 모든 요소는 그 순간 나오는 자막의 말을 그림으로 보여 주는 것이어야 한다.
   - 자막에 없는 내용을 화면에 넣지 않는다. 장식용 아이콘, 분위기용 도형, 맥락 없는 효과를 넣지 않는다.
   - 어떤 요소도 그 내용을 말하는 자막보다 먼저 나오지 않는다.
   - 시청자가 "왜 갑자기 이게 나오지?"라고 느낄 만한 요소가 하나라도 있으면 뺀다.
   - 이미 나온 대상(예: 사연 주인공의 계좌 카드)을 다시 쓸 때는 같은 모양·같은 색으로 써서 같은 것임을 알아보게 한다.
6. **화면 텍스트는 핵심 키워드와 숫자만** 쓴다. 자막 문장을 화면에 그대로 반복하지 않는다. 한 화면의 텍스트 덩어리는 3개 이하로 한다.
7. **색의 의미를 영상 전체에서 고정한다.** (3-1) 수익·상승은 빨강, 손실·하락은 파랑이다. 국내 증권 앱 관례를 따른다.
8. **한 화면에 한 메시지.** 그래픽은 자막 영역을 침범하지 않는다.
9. **매수·매도를 권유하는 것처럼 보이는 연출을 하지 않는다.** (예: 특정 종목에 "BUY" 강조, 화살표로 매수 유도)
10. 모르는 값(채널명 등)은 변수로 두고 작업을 멈추지 않는다. 마지막 보고에서 알린다.

## 2. 기술 설정과 속도 규칙

- **프레임워크:** Remotion (React + TypeScript, blank 템플릿). 프로젝트 폴더는 `./video` 하나를 계속 쓴다. 이미 있으면 새로 만들지 않는다.
- **Remotion Agent Skills:** `npx skills add remotion-dev/skills`로 설치하고 따른다. (이미 설치돼 있으면 건너뛴다)
- **폴더 구조 (영상이 쌓여도 공통 부분은 재사용)**
  ```
  video/src/design/        ← 색·폰트·크기·모션 상수 (모든 영상 공통)
  video/src/components/    ← 공통 컴포넌트 (모든 영상 공통, 3-5의 패턴)
  video/src/episodes/<영상ID>/subtitles.ts   ← SRT 파싱 결과
  video/src/episodes/<영상ID>/facts.ts       ← 데이터 시트
  video/src/episodes/<영상ID>/scenes/S01.tsx …
  video/src/episodes/<영상ID>/Episode.tsx
  video/src/Root.tsx       ← 영상마다 컴포지션 하나씩 등록 (ID = 영상ID)
  ```
  - 새 영상은 `episodes/`에 새 폴더만 만들고, 공통 폴더는 그대로 재사용한다.
  - 공통 컴포넌트를 고칠 때는 이전 영상의 컴포지션이 깨지지 않게 한다.
- **컴포지션:** 1920×1080, 30fps. 길이 = SRT 마지막 자막 끝 + 화면 고지 카드 길이 합 + 여유 1초.
- **폰트:** `@remotion/google-fonts`로 Noto Sans KR(500, 700, 900)과 Noto Serif KR(700, 900)을 로드한다. 숫자는 `tabular-nums`.
- **타이밍:** 장면의 시작과 끝은 SRT 자막 번호로 계산한다. 초를 하드코딩하지 않는다.
- **화면 고지 카드 (`[장면]`)**
  - TXT에서 `[장면]` 줄 바로 뒤의 문장들(다음 파트 라벨 전까지)이 카드 문구다. 문구는 그대로 쓴다.
  - 카드는 TXT에서 `[장면]` 바로 앞에 오는 문장의 자막이 끝난 직후에 넣는다.
  - 카드 길이 = 문구 글자 수 ÷ 7 + 1초 (최소 4초, 최대 8초). 카드 뒤 자막과 내레이션은 그만큼 뒤로 민다. 내레이션 파일이 있으면 그 지점에서 오디오를 나눈다.
- **속도 규칙 (제작·렌더 시간을 줄이기 위해)**
  - 최종 렌더는 1080p 30fps로 한다. 4K는 사용자가 요청할 때만 `--scale=2`로 렌더한다.
  - 프레임마다 계산되는 무거운 효과를 쓰지 않는다. `filter: blur`, SVG `feTurbulence`, 큰 그림자, 큰 요소 전체의 실시간 필터는 금지한다. 종이 질감은 가벼운 CSS 그라데이션이나 고정된 작은 점 패턴으로 만든다.
  - 3-5의 공통 컴포넌트를 먼저 만들고 장면마다 재사용한다. 장면마다 새로 그리지 않는다.
  - 전체 렌더 전에 스토리보드로 검수해서, 전체 렌더를 여러 번 하지 않는다.
- **렌더 명령:** `npx remotion render <영상ID> out/<영상ID>/final_1080p.mp4 --codec=h264 --crf=18`
- 수정할 때마다 `CHANGELOG.md`에 날짜, 영상ID, 바뀐 장면이나 공통 컴포넌트를 기록한다.

## 3. 디자인 시스템 (모든 영상 공통, 1080p 기준)

### 3-1. 색 (의미 고정)
| 의미 | 색 | HEX |
|---|---|---|
| 기본 배경 | 크림 종이 | #F2EBDD |
| 위기·손실 구간 배경 | 다크 네이비 | #14213D |
| 해결·희망 구간 배경 | 밝은 크림 | #FAF6EE |
| 글자·선 | 잉크 | #1E1E1E (네이비 배경에서는 #F7F3EA) |
| 수익·상승 | 빨강 | #E63B2E |
| 손실·하락 | 파랑 | #2D6CDF |
| 핵심 강조 (한 화면에 한 곳만) | 노랑 형광펜 | #FFD400 |
| 비교 대상·보조 정보 | 웜 그레이 | #9A968E |

### 3-2. 크기와 위치
| 요소 | 크기 |
|---|---|
| 핵심 숫자 | 160–220px, Noto Sans KR 900 |
| 장면 헤드라인·번호 타이틀 | 72–88px, Noto Serif KR 900 |
| 라벨 | 36–44px, Noto Sans KR 700 |
| 출처·"개념도" 캡션 | 24px, 웜 그레이 |
| 화면의 모든 글자 | 최소 28px |

- 바깥 여백 96px. 그래픽은 세로 120~800px 영역에만 놓는다.
- 핵심 숫자나 핵심 그래픽은 화면 중앙 또는 중앙에서 약간 위에 둔다.
- 비교는 항상 왼쪽 = 나쁜 쪽, 오른쪽 = 좋은 쪽으로 배치한다.

### 3-3. 자막
- 화면 하단 중앙, 아래 여백 72px, 최대 너비 1500px, 46px Noto Sans KR 700.
- 크림 배경: 잉크 글자 + 크림 띠(불투명도 92%, 모서리 12px). 네이비 배경: 밝은 글자 + 네이비 띠(불투명도 85%).
- SRT의 줄바꿈을 그대로 쓴다. 자막 하나에 한 문장만 보이고, 자막 사이에 빈 화면이 없다.
- 등장·퇴장은 4프레임 페이드.

### 3-4. 모션
- 등장 12–18프레임, 퇴장 8–10프레임, spring 기반 ease-out. 과한 바운스 금지.
- 여러 요소는 4–6프레임 간격으로 순차 등장한다.
- 장면마다 1.00 → 1.03 정도로 천천히 줌인한다.
- 핵심 단어·숫자는 노랑 형광펜이 왼쪽→오른쪽으로 10프레임 동안 그어진다.
- 선과 차트는 `stroke-dashoffset`으로 그려지는 애니메이션을 쓴다.
- 금액과 %는 20–30프레임 동안 카운트업·카운트다운한다.
- 장면 전환은 찢어진 종이 와이프(가벼운 폴리곤 clip-path)와 컷을 번갈아 쓴다.
- 각 요소는 그 내용을 말하는 자막이 시작될 때 등장한다. 자막마다 최소 하나의 변화(요소 등장, 숫자 변화, 강조)가 있어서 화면이 멈춰 보이지 않게 한다.

### 3-5. 시각화 패턴 (대본 내용 → 쓸 컴포넌트)
대본의 각 문장이 어떤 유형인지 보고 아래 패턴 중 가장 직접적인 것을 고른다.

| 대본 내용 유형 | 패턴 (공통 컴포넌트) | 규칙 |
|---|---|---|
| 사연 속 계좌·투자금 | 계좌 카드 (잔고, 평가손익, 종목 비중 막대) | 같은 사연은 영상 끝까지 같은 카드로 재등장 |
| 금액·비율의 변화 | 숫자 카운터 + 막대 길이 변화 | 시작값 → 끝값, 수익 빨강 / 손실 파랑 |
| 두 선택의 비교 | 화면 분할 | 왼쪽 나쁜 쪽, 오른쪽 좋은 쪽, 두 숫자 동시 카운트 |
| 확률·비율 (N%) | 10×10 와플 그리드 | 100칸 = 전체, N칸 색칠. "열 중 여섯" 같은 말은 한 줄 10칸 |
| 여러 사례 (기업, 사건) | 사례 카드 나열 + 하락·상승 막대 | 카드마다 연도·원인·수치, 자막 순서대로 하나씩 채움 |
| 주가 흐름 설명 | 라인 차트 | 실제 데이터가 아니면 "개념도", 눈금 숫자 없음 |
| 기간·연도 | 타임라인 | 시작·끝 연도만 표시 |
| 연구·통계 인용 | 큰 숫자 + 출처 캡션 | 캡션은 대본에 나온 연구자·기관 이름만 |
| 사람들의 생각·혼잣말 | 생각 말풍선 | 핵심 구절만, 생각 하나에 말풍선 하나 |
| 심리·감정 | 천칭 저울, 달력, 단순 아이콘 | 자막에 나온 감정·행동만 |
| 문제·방법 N가지 목록 | 번호 타이틀 카드 ("01", "첫째") | 같은 목록은 같은 디자인, 항목 시작마다 등장 |
| 뉴스·사건 | 텍스트 헤드라인 카드 | 날짜가 대본에 있으면 표시 |
| 경고·손실·위기로의 전환 | 네이비 배경 + 찢어진 종이 전환 | 위기 구간에만 |
| 해결책·희망으로의 전환 | 밝은 크림 배경 | 해결 파트 시작에 |
| 마무리 요약 | 두 열 키워드 정리 | 앞에서 다룬 항목 이름만 |
| 시청자 행동 권유 | 스마트폰 화면 | 자막에서 권한 행동만 |
| 화면 고지 `[장면]` | 노랑 띠 카드 | TXT 문구 그대로, 한 줄씩 순서대로 |

맞는 패턴이 없으면 자막의 말을 가장 직접적으로 보여 주는 단순한 도형을 새로 만들고, 공통 컴포넌트로 추가한다. 장식은 넣지 않는다.

## 4. 데이터 시트 만들기 (`facts.ts`)

1. SRT의 모든 숫자·금액·%·연도·기업명·연구자·기관명을 빠짐없이 뽑아 넣는다. 항목마다 값, 자막 번호, 구분(대본 수치 / 계산 / 예시)을 적는다.
2. 화면에 대본에 없는 숫자를 써야 하면, 대본 숫자로 계산한 값만 허용한다. 계산식을 함께 적는다. (예: 7,000만 → 5,000만 원 = -29%)
3. 출처 캡션은 대본에 나온 연구자·기관 이름만 쓴다. 대본에 출처가 없으면 캡션을 넣지 않는다.
4. 대본 숫자끼리 계산이 맞지 않는 곳을 발견하면 고치지 말고, 스토리보드 보고 때 자막 번호와 함께 알린다.

## 5. 장면 구성표 만들기 (`scene_plan.md`)

### 5-1. 장면 나누기
- 파트 라벨과 내용 전환(새 사례, 새 항목, 새 주장)을 기준으로 나눈다.
- 한 장면은 자막 1~6개, 5~40초. 목록의 한 항목은 한 장면으로 묶는다.
- 영상 전체에서 장면 수는 대략 자막 수 ÷ 3 안팎이 되게 한다.

### 5-2. 구성표 형식
| 장면 | 자막 | 배경 | 연출 (자막 번호별로 무엇이 등장·변화하는지) | 화면 텍스트 | 패턴 | 연결 근거 |
|---|---|---|---|---|---|---|

- **연결 근거:** 화면 요소마다 그 요소가 나온 자막 번호와 자막 속 말을 적는다. (예: "자막 3의 '전 재산 7천만 원을 몰빵' → 계좌 카드 100% 한 종목")
- **연속성:** 같은 대상이 다시 나오면 처음 나온 장면 번호를 적는다. (예: "S02의 계좌 카드")
- **배경:** 기본은 크림. 손실이 드러나는 순간부터 그 위기를 설명하는 구간까지만 네이비. 해결 파트 시작부터 밝은 크림.

## 6. 작업 순서

1. **입력 확인:** SRT·TXT가 각각 하나인지 확인한다. 없거나 여러 개면 멈추고 묻는다.
2. **프로젝트 준비:** `./video`가 없으면 만들고, 있으면 재사용한다. Agent Skills를 확인한다. 영상ID를 정한다.
3. **자막 파싱:** `subtitles.ts`를 만들고, 화면 고지 카드의 위치와 길이를 계산한다. 자막 개수, 고지 카드 수, 전체 길이를 콘솔에 출력한다.
4. **계획 작성:** `facts.ts`(4번)와 `scene_plan.md`(5번)를 쓴다.
5. **구현:** 필요한 공통 컴포넌트를 만들거나 재사용하고, 장면을 구현한다.
6. **스토리보드를 만들고 여기서 멈춘다.**
   - 장면마다 모든 요소가 다 나온 시점(장면 끝 10프레임 전)의 still을 `out/<영상ID>/storyboard/S01.png`처럼 렌더한다. 한 장면 안에서 그림이 크게 바뀌면 자막 단위로 1장씩 더 만든다. (`S25-66.png`처럼)
   - `out/<영상ID>/storyboard/index.html`을 만든다. 장면마다 이미지, 장면 번호, 자막 번호, 자막 원문, 연결 근거를 카드로 보여 준다.
   - 보여 주기 전에 still을 직접 열어 7번 검수표를 통과시킨다.
   - 그다음 index.html 경로, `scene_plan.md` 경로, 장면별 한 줄 요약, 4번의 숫자 이상 여부를 보고하고, **사용자의 승인이나 수정 지시를 기다린다. 승인 전에는 전체 렌더를 하지 않는다.**
7. **수정:** 사용자가 고칠 장면을 말하면 그 장면만 고치고, 그 장면의 still만 다시 만들어 보여 준다.
8. **렌더:** 승인되면 `final_1080p.mp4`를 렌더한다.
9. **결과 보고:** 출력 경로, 영상 길이, 렌더에 걸린 시간, 사용자가 채워야 할 값을 알린다.

## 7. 스토리보드 검수표 (still마다 확인)

- [ ] 화면의 모든 요소가 그 시점 자막의 말에서 나왔는가 (연결 근거로 설명되는가)
- [ ] 자막에 없는 내용, 장식용 요소, 맥락 없는 효과가 없는가
- [ ] 핵심 숫자가 한눈에 보이는 크기와 위치인가, 노랑 강조가 한 곳뿐인가
- [ ] 수익은 빨강, 손실은 파랑인가. 같은 대상이 같은 모양·같은 색인가
- [ ] 화면 숫자가 데이터 시트와 일치하는가. 개념 그래프에 "개념도" 표시가 있는가
- [ ] 글자 잘림, 겹침, 자막 영역 침범이 없는가. 모든 글자가 28px 이상인가
- [ ] 같은 유형의 내용에 같은 패턴을 썼는가 (3-5)
- [ ] 이미지, 이모지, 로고, 인물 그림, 매수 권유처럼 보이는 연출이 없는가
