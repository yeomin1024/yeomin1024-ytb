## 1. 재료
```
python3 tools/content_research.py style <주제>      # 성공 사례 대본(음성인식 앞 5분): 말투·문장 길이·시점·전개 장치
python3 tools/content_research.py feedback <주제>   # 성공 사례 댓글: 내용·전달에 대한 칭찬·불만 + 원문
python3 tools/content_research.py measure <새 대본.txt> [--compare <옛 대본.txt>]   # 새 대본을 같은 규칙으로 잼
```
- **시청자 페르소나** `<주제>/result/outliers/personas.md` (분석마다 자동 — `tools/personas.py`): 요약본 [페르소나] 칸의 대상 P 번호의 **지식 수준**에 말을 맞추고(기초면 고급 용어는 처음 나올 때 한 마디로 풂), **원하는 것**에 답하고, **불만 갈래**(길다·광고·틀림·AI 목소리)를 피한다.
- 대본 지표는 음성인식 '앞 5분'(1차)만 있다. 도입부·초반 구성의 근거로만 쓴다.
- '많이 쓰인다'는 '그래서 잘됐다'가 아니다. 성공 사례 대부분이 쓰는 것을 기본값으로 삼고, 소수가 쓰는 장치는 내용에 맞을 때만 쓴다.
- 성공 사례 몇 개(배수 큰 것, 같은 주제 묶음)의 대본은 **처음부터 끝까지 읽는다** (`W_<영상ID>/transcript.json`).
  - 재테크 예: #43 기초연금(×32.5) — 대상 부르기 → 숫자 → 미리 보기 3가지 + '끝까지' → 질문 → 예상 반론 → 바로 할 일.
  - 재테크 예: #47 연금저축 순서(×30.1) — 흔한 믿음 뒤집기 → 빠른 답 → 시청자 확인 질문 → 비유 → '정리하면 한 줄' → '2026년 7월 기준'.

## 2. 구성 (전개)

| 순서 | 챕터 (파트 라벨) | 할 일 | 근거 |

- **챕터 끝 전환 멘트:** "먼저 ~를 통해 알아보겠습니다." · "~는 세 가지 원칙에서 나옵니다. 하나씩 보겠습니다." · "그럼 이 원칙으로 ~를 정해 보겠습니다." · "이렇게 ~한 두 부부의 결과는 얼마나 달라졌을까요?" · "그런데 이미 ~하고 계신 분들도 계실 텐데요. 그럼 어떻게 해야 할까요?"
- 호칭: '여러분'·조건 부르기만 쓴다. '어르신·어머님·아버님'은 쓰지 않는다. 성공 사례 노후 46%가 쓰지만, 60대 시청자의 반발 댓글이 있다.
- 진행자 개인 경험을 지어내지 않는다("저도 처음엔…" 금지). 예시 인물은 '계산용 예시'라고 README 에 적는다.

## 3. 사실 확인 — 오늘 날짜로

### 3-1. 법령 원문 (기본)
```
python3 tools/law_text.py 소득세법 --out /tmp/law --article 제14조
python3 tools/law_text.py "국민건강보험법 시행규칙" --out /tmp/law --grep "1천만원"
python3 tools/law_text.py 국민연금법 --source mirror --out /tmp/law --article 제62조   # law.go.kr 이 막힐 때 (v1.1)
```
- 기본(`--source auto`)은 law.go.kr 을 두 번 시도하고, 막히면 GitHub 의 법령 저장소 legalize-kr 에서 **오늘 시행 중인 판**을 받는다 (main 은 시행 전 최신판일 수 있어 개정 이력을 거슬러 고름). 확인표에 'legalize-kr 커밋'도 적는다. 별표(PDF)는 legalize-kr 에 없을 수 있다 → 본문 조문 + 올해 운영 자료로.
- 시행일·법률 번호를 기록한다. 예: "[시행 2026. 7. 1.] [법률 제21221호]".
- 조문의 실제 문장을 확인표에 짧게 옮긴다.
- 시행령·시행규칙·별표(PDF)까지 본다. 예: 건보 피부양자 기준은 시행규칙 별표 1의2.
- 개정 예정(부칙의 시행일)도 확인한다. 예: '2026년 1월 1일 이후 받는 분부터'.

### 3-2. 운영 (법에 적히지 않은 관행)
- 올해 공식 발표·보도로 확인한다. 날짜를 적고, 작년 것은 '작년'이라고 밝힌다.
- 공단·국세청의 챗봇·전화 답변은 사용자가 확인해 준 내용만 근거로 쓴다. 답변 원문을 확인표에 옮긴다.
  - 예: 건보공단 챗봇 "사적연금 1,500만 원 초과로 종합과세되면 피부양자 소득에 포함".
- 이 클라우드에서 nhis.or.kr·nts.go.kr 등은 막혀 있다(2026-10-14). 막히면 '확인 필요'로 넘긴다.

## 4. 계산 — 코드로, 가정은 드러나게
1. **계산 코드** `calc.py`를 대본 폴더에 둔다. 맨 위에 `VERSION` 줄과 바뀐 내용을 적는다.
   - 예: `economic/source/eunte-kkeonaeseugi-2026-10/calc/sim4.py`.
   - 가정 표를 README 에 둔다: 나이·금액·금리·물가·과세 몫 등.
2. **세법·제도의 상호작용을 점검한다.**
   - 예: 2026-10-14에 찾은 오류 — 아내가 연금저축을 종합과세로 신고하면 남편이 배우자 공제를 잃는 점을 빼먹어, '나눠 꺼내면 69만 원'이 실제로는 78만 원이었다.
   - 끝나는 조건도 점검한다. 예: 기준 때문에 돈이 남았는데 '끝'으로 잡히던 것.
3. **민감도:** 모르는 가정은 범위로 돌려 결론이 그대로인지 본다. 대본 숫자는 범위의 안전한 쪽으로 반올림한다.
   - 예: 국민연금 과세 몫 50~100% → 평생 차이 2,016~2,193만 원 → "약 2천만 원".
4. **현금과 미래 세금을 구분한다.**
   - 예: '10년 동안 월 15.9만 원'은 그 기간에 실제로 낸 세금 차이다.
   - 나중에 낼 연금계좌 세금까지 넣으면 월 12.0만 원이다. 대본·README 에 어느 쪽인지 적는다.
5. **중간에 고치기**도 계산한다. 예: 65세 말 → 1,300만 원·1년, 67세 → 1,700만 원, 70세 → 줄지 않음.
6. 건보료처럼 사람마다 크게 다른 것은 숫자에 넣지 않고 "넣지 않았다"고 말한다.

|---|---|
| 길이 | 읽는 음절 ÷ 5.1 = **7~8분** (srt_tool 추정은 문장 쉼을 넣어 0.6~0.8분 더 김) |
| 문장 길이 | 중앙값 20~24글자, 50자 넘는 문장은 나눈다 (srt_tool 경고) |
| 말투 | 합니다체 50~65% · 해요체 20~40% · 질문 3~8% (성공 52/37/6, 노후 60/21/5) |
| 시점 | 결론 먼저 40초 안, '끝까지' 약속 50초 안 (기준 날짜는 설명란) |
| 장치 | 대상 부르기·숫자 시작·질문·결론 먼저·확인 질문·예상 반론·비유·'한마디로' 정리·'끝까지' — 내용에 맞으면 |

- 댓글 피드백으로 점검한다 (재테크 2026-10-14):
  - '틀림·부정확' 불만이 많다 → 정확한 기준 이름·금액을 쓰고, 기준 날짜는 설명란에.
  - '길다·반복·뻔함' 불만 → 같은 말을 두 번 하지 않는다.
  - '현실적·공감'·'숫자·계산' 칭찬이 가장 많다 → 구체적 계산을 보여 준다.
  - 'AI 목소리' 불만은 적지만 있다 → 말하듯 쓴다.

## 4-5. 최종 대본 페르소나 검사 (`tools/persona_review.py`, 2026-10-28)
```
python3 tools/persona_review.py <주제> <대본.txt>      # → 대본 폴더 persona_review.md
```
- 페르소나마다: ① 원하는 것(질문 속 용어·두 번 넘게 나온 질문 낱말)을 대본이 다루는지 ② **풀이 없이 처음 나온 말**(그 페르소나가 '…가 뭔가요'로 물은 말 + 초급·기초면 고급 용어 전부, 문장 번호) ③ 한 문장에 고급 용어 2개 이상 ④ 불만 갈래에 걸리는 곳(50자 넘는 문장·반복·구독 유도·겁주기 말).
- 고칠 때: 풀이 없이 나온 말은 그 문장이나 다음 문장에 '쉽게 말해 …' 한 마디. '안 다룸'은 영상 주제와 맞는 것만 더하고, 나머지는 다음 주제 후보로.
- 숫자·법은 보지 않는다 (3번·4번이 따로). ChatGPT 듣기 검토(`<주제>/guides/viewer_review.md`)는 이 검사를 고친 뒤에.

## 5. 파일과 검사 (영상·내레이션 도구와 맞춤)
- 폴더: `<주제>/source/<영상ID>/` (영상ID = 영문 소문자·하이픈, 예: `eunte-kkeonaeseugi-2026-10`).
- **대본 `<영상ID>.txt`**
  - 챕터 = 파트 라벨 `-챕터 이름` (예: `-원칙 하나, 기준은 한 사람씩`). 라벨에 '사연'을 넣으면 사연자 목소리가 된다 — 사연이 아니면 넣지 않는다.
  - **한 줄에 한 문장.** 작성용 메모는 지운다.
- **자막 SRT**:
  ```
  python3 tools/srt_tool.py build economic/source/<ID>/<ID>.txt economic/source/<ID>/<ID>.srt
  python3 tools/srt_tool.py check economic/source/<ID>/<ID>.txt economic/source/<ID>/<ID>.srt
  ```
  - '✅ 이상 없음'이어야 한다. 문장 수·자막 수·추정 끝 시각을 README 에 적는다.
- **README.md**:
  1. 주제 선정(`topic_guide.md` 2번)
  2. 버전 기록(사용자 피드백 원문 → 바꾼 것)
  3. 예시 인물·가정
  4. 계산 결과(숫자 → 대본 문장)
  5. 측정(`measure`)
  6. 검사(srt_tool)
  7. "연구·교육용, 세무·투자 권유 아님"
- **checklist.md** (3-3), **calc/** (4번), **titles.md** (`title_guide.md`).
- `<주제>/source/used_content.md`에 한 줄을 추가한다.
- 대본이 바뀌면 SRT·제목·확인표·README 를 같이 고친다.
- 그다음(썸네일 프롬프트·업로드 시트·내레이션·영상)은 `pipeline.md` 3~4단계.
