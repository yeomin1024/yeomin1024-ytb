## 0. 목표·순서·입출력
- **목표:** 50~70대 시청자가 내레이션을 들으면서 화면만 봐도 바로 이해한다. 화려함보다 **이해**가 먼저다.
- **순서 (사용자 지시 2026-10-15 "오디오를 먼저 만들고나서 영상"):**
  1. 대본 → 2. **오디오** (Kaggle, 진행자 H04 목소리 하나 — `guides/tts_guide.md`) → 3. **오디오가 생긴 뒤에만** 영상
  - 오디오 없이 무음 영상이나 추정 시각으로 영상을 먼저 만들지 않는다. 장면 시각은 오디오에 맞춘 자막 시각이다.
- **입력** (`<주제폴더>/source/<영상ID>/`):
  | 파일 | 쓰는 곳 |
  |---|---|
  | `<영상ID>.txt` | 문장·파트 라벨(장 이름표)·`[장면]` 고지 카드 |
  | `<영상ID>.srt` | 자막 문장·시각 — `align-audio`로 오디오에 맞춘 것 (2-2) |
  | `narration.mp3`·`tts_narration.json` | 내레이션과 문장별 시각 |
  | `README.md`·`checklist.md`·`calc/` | 화면에 쓰는 숫자 (계산 코드 값) |
  | `thumbnails/thumbnail_N.md` | 색의 뜻·시청자층 낱말을 썸네일과 맞춤 |
- **출력:**
  - `video/episodes/<영상ID>/index.html` — 장면·타임라인 한 파일. 브라우저에서 바로 재생된다 (확인용으로 사용자에게 보여 줄 수 있음). git에 올린다.
  - `<주제폴더>/out/<영상ID>/final_1080p.mp4` — 1920×1080, 30fps, 자막을 구운 완성 영상. 용량 때문에 git에 넣지 않는다.
  - 점검용 still은 저장소 밖 임시 폴더에 둔다.

## 1. 절대 규칙
1. **숫자는 대본·계산 코드의 값만** 쓴다. 새 숫자를 만들지 않는다.
   - 아직 말하지 않은 숫자 자리는 `???`로 비운다. 아무 숫자나 돌리는 연출(룰렛 숫자)은 쓰지 않는다 — 가짜 숫자로 읽힌다.
   - 숫자가 올라가는 연출(카운트)은 내레이션이 그 숫자를 말하는 순간 시작해 그 값에서 멈춘다.
2. **자막을 화면에 굽는다** (사용자 지시 2026-10-15). 자막 문장은 SRT 그대로다 (3-5). 업로드 때 같은 SRT를 유튜브 자막으로도 올린다.
3. **장면 적합성:** 화면의 모든 요소는 그 순간 내레이션이 말하는 것을 그림으로 보여 준다.
   - 말보다 먼저 나오지 않는다. 자막에 없는 장식·분위기용 그림을 넣지 않는다.
   - 이미 나온 것(부부·우산·바구니)은 다시 나올 때 **같은 모양·같은 색**으로 쓴다.
4. **그림은 코드로 그린다:** SVG·CSS 도형과 글자만. 사진·AI 이미지·스톡 영상·실제 로고·실제 화폐 도안·이모지를 쓰지 않는다.
5. **예전 스타일 금지:** 크림 종이 배경, 작은 카드에 라벨이 빽빽한 인포그래픽, 표를 그대로 옮긴 화면.
6. 특정 상품 가입·매수를 권하는 것처럼 보이는 연출을 하지 않는다.
7. 내레이션 오디오는 고치지 않는다 (자르기·늘이기·쉼 넣기 금지). 자막을 오디오에 맞춘다.

## 2. 이해를 돕는 장치 (근거: 멀티미디어 학습 원칙 — Mayer · 고령 시청자 가독성)
| # | 장치 | 하는 법 | 원칙 |
|---|---|---|---|
| 1 | **한 화면에 생각 하나** | 지금 말하는 것 하나만 크게. 앞 장면의 요소는 지우거나 흐리게(투명도 0.12) | 일관성 |
| 2 | **말하는 순간에 나온다** | 요소·숫자는 그 낱말을 말하는 문장의 시작(또는 그 낱말 위치)에 맞춰 나온다 | 시간 근접 |
| 3 | **색 = 뜻** | 빨강 = 손해·넘침, 청록 = 아낌·안전, 노랑 = 기억할 기준·방법 (3-2). 영상 전체와 썸네일이 같다 | 신호 주기 |
| 4 | **모든 기준은 노란 점선** | 1,000만·1,500만·2,000만 원 같은 기준은 모두 같은 노란 점선. 넘는 순간 넘은 쪽이 빨강으로 바뀐다 | 신호 주기 · 사전 학습 |
| 5 | **어려운 말 = 그림 하나** | 제도·개념은 처음 나올 때 그림 하나로 정하고 끝까지 같은 그림 (예: 피부양자 = 자녀 건강보험 우산, 기준 = 사람마다 따로 있는 바구니) | 구체적 예시 · 반복 |
| 6 | **큰 글자·충분히 머묾** | 3-3 크기, 핵심 숫자는 다 나온 뒤 2초 이상. 왼쪽 위 장 이름표로 지금 어디인지 | 분할 · 가독성 |
| 7 | **구운 자막** | 아래 띠에 SRT 문장 (3-5). 화면 글자는 핵심 낱말·숫자만, 자막과 같은 문장을 화면 가운데에 또 쓰지 않는다 | 중복 원칙 + 사용자 지시 |

## 3. 디자인
### 3-1. 무대
- 1920×1080 고정 좌표. 배경: 짙은 남색 원형 그러데이션 (`#17243D` → `#0C1424` → `#070C17`).
- 바깥 여백 96px. 왼쪽 위 장 이름표 (top 60px). **아래 자막 띠 자리 y 900~1040은 비운다** — 그림·글자는 y 880 위에 둔다.

### 3-2. 색 (뜻 고정 — 썸네일 `guides/thumbnail_guide.md`와 같은 뜻)
| 뜻 | 색 |
|---|---|
| 손해·넘침·나쁜 상황, 손해 본 쪽(예: A 부부) | 빨강 `#FF4D3D` |
| 아낌·안전·기준 안, 아낀 쪽(예: B 부부) | 청록 `#22C7B0` |
| 기억할 기준·방법·장 이름 | 노랑 `#FFD400` |
| 기본 글자 | 흰색 `#F4F6FA` |
| 보조 글자·눈금 | 회청 `#9AA7BF` |
| 뜻 없는 금액 블록(돈의 구성, 국민연금 등) | 남색 계열 `#2E4470` · `#3C5788` · `#4A69A2` · `#5B7DB8` |
- 한 화면의 노랑은 기준·방법에만 쓴다. 빨강·청록은 비교하는 두 쪽에만 쓴다.

### 3-3. 글자 (Noto Sans KR 500·700·900)
| 요소 | 크기 (1080p) | 굵기 |
|---|---|---|
| 핵심 숫자 | 190~230px | 900 |
| 장면 제목·결론 | 64~84px | 900 |
| 라벨·설명 | 40~60px | 700 |
| 보조·눈금 | 36~40px (최소 36px) | 500 |
| 자막 | 52px | 700 |
| 장 이름표 | 36px | 700 |
- 숫자는 쉼표를 넣고(`1,010만 원`), 대본과 같은 단위로 쓴다. 대본이 '약 2천만 원'이면 화면도 '약 2천만 원'.

### 3-4. 움직임 (GSAP 3.12.5)
| 움직임 | 값 |
|---|---|
| 등장 | 0.5~0.6초, 아래 40px → 제자리, 투명 → 선명, `power3.out` |
| 퇴장 | 0.3~0.45초, 위로 30~60px, 투명 |
| 장면 바뀜 | 0.35초 겹쳐 사라지고 나타남 (`scene(start, end)`) |
| 숫자 카운트 | 1.2~1.8초 `power2.out`, 말하는 순간 시작 |
| 막대 자람 | 0.9~1.8초 `power2.out`, 실제 비율 (눈금이 있으면 같은 축) |
| 지우는 줄 | 빨강 사선 0.35초 (오답·'넘은 만큼?' 같은 틀린 생각) |
- 흔들기·번쩍임·빠른 깜빡임·화면 전체 확대를 쓰지 않는다. 반복 움직임(비)은 그 장면 안에서만 짧게.
- 무거운 효과(큰 `filter: blur`, SVG 잡음 필터, 큰 그림자)는 쓰지 않는다 — 렌더가 느려진다.

### 3-5. 자막 (굽기 — 사용자 지시 2026-10-15)
- 자리: 아래 가운데, 아래 끝에서 44px 위. 둥근 띠 배경 `rgba(5,9,18,.82)`, 글자 흰색 52px 700, 줄 간격 1.3, 띠 최대 너비 1600px.
- 내용: SRT 자막 하나를 그 시작~끝 동안 그대로 (SRT의 줄나눔 그대로, 한 번에 최대 2줄). 글자를 바꾸거나 줄이지 않는다.
- 색 강조를 넣지 않는다 (자막은 흰색만 — 색의 뜻은 화면 그림이 맡는다).
- 고지 카드 자리(`[장면]`)는 SRT에 자막이 없으므로 띠도 없다.

### 3-6. 그림 부품 (시안 `storyboard.html`에 있는 것 그대로 다시 쓴다)
| 부품 | 쓰는 곳 | 모양 |
|---|---|---|
| 사람·부부 | 사례 인물 | 원 + 둥근 몸통(회백), 아래 배지(`A 부부` 빨강 · `B 부부` 청록) |
| 돈 블록 쌓기 | 같은 돈의 구성 (예금 2억·연금저축 1억·퇴직금 2억) | 남색 계열 블록, 높이 = 금액 비율 |
| 금액 카운터 + 막대 | 두 쪽 금액 비교 | 큰 숫자 + 같은 축의 막대 (길이 = 금액) |
| 기준선 | 모든 기준 | 노란 점선 + 이름표('이자·배당 기준 1,000만 원') |
| 쌓는 막대 | 합계가 기준을 넘는지 (1,050 + 1,320 = 2,370 > 2,000) | 한 줄 막대에 차례로 이어 붙이고, 기준선은 합계가 나온 뒤 내려온다 |
| 우산 | 피부양자 (자녀 건강보험) | 노란 테두리 우산, 밖으로 나가면 비 |
| 바구니 | 사람마다 따로 있는 기준 | 바구니 둘(남편·아내) + 노란 점선, 동전 = 100만 원 |
| 동전 | 한 달 금액·작은 단위가 쌓여 큰돈 | 동전 쌓기, 손해면 빨강 |
| 달력 카드·봉투 | 시간 순서 (올해 → 다음 해, 고지서) | 카드 두 장 + 봉투 이동 |
| 번호 카드 | 결론·순서 | 노란 번호 + 2줄 글자 |
| 장 이름표 | 파트 라벨 | 왼쪽 위 알약 모양, 원칙이면 점(●○○) |

## 4. 대본 내용 → 장면 모양
| 대본이 말하는 것 | 장면 |
|---|---|
| 같은 조건의 두 사례 | 부부 둘 + 같은 돈 블록 + 노란 `=` |
| 두 금액의 차이 | 카운터 둘 + 같은 축 막대 (빨강·청록) |
| 기준·한도 | 노란 점선 기준선, 넘으면 빨강 |
| 넘으면 전부 (절벽) | 넘은 조각을 '넘은 만큼?'으로 보여 주고 지운 뒤, 막대 전체를 빨강으로 |
| 합계 | 쌓는 막대 + '= 합계' 카운터 |
| 작은 돈이 쌓임 | 동전 쌓기 → 큰 숫자 하나 |
| 제도 자격 | 그 제도의 그림 하나(우산 등) 안·밖 |
| 순서·결론 | 번호 카드 |
| 시간이 걸리는 일 | 달력 카드, 연도 칸(1·2·3·4·5) |
| 물음 | 큰 '왜?' → 오답 지우기 → 답은 노랑 |

## 5. 장 이름표와 구성
- 대본의 파트 라벨(`-원칙 하나, 기준은 한 사람씩`)이 장 이름표다. 앞부분 = '도입', 원칙이면 '원칙 1' + 점 표시.
- 장이 바뀔 때 0.3초 이름표를 바꾼다. 대본에 장 전환 멘트가 있으면 그 문장 동안 다음 장 이름을 크게 한 번 보여 준다.

## 6. 도구 — HTML·SVG + GSAP + Playwright
- **장면 파일:** `video/episodes/<영상ID>/index.html` — 시안 `video/prototypes/storyboard-2026-10-15/storyboard.html`의 구조를 그대로 쓴다.
  - 무대 `#stage` 1920×1080, 장면 `scene(start, end)`, 요소 `$()`·`pop()`·`counter()`, GSAP 타임라인 하나(멈춘 상태), `window.SB.seek(t)`
  - `?render`를 붙이면 무대만 보이고 렌더기가 `seek`으로 장면을 만든다.
  - 장면 시각은 오디오에 맞춘 SRT 시각을 페이지 안 자막 목록에서 읽어 쓴다 (문장 n의 시작 = 그 문장 첫 자막의 시작). 숫자를 손으로 적지 않는다.
- **렌더:** Playwright가 1/30초마다 `seek` → 찍은 장면을 ffmpeg로 이어 H.264, `narration.mp3`를 붙인다 → `tools/loudnorm.py`로 -14 LUFS·트루 피크 -1.5 dBTP 이하.
  - 렌더는 `<!doctype html>`을 붙인 파일로 한다 (없으면 quirks 모드라 클래스 대소문자가 섞인다 — 시안에서 겪음).
  - GSAP·폰트는 로컬 파일로 넘긴다 (렌더 환경은 CDN이 막혀 있을 수 있음). 폰트: `video/public/fonts/NotoSansKR-500·700·900.ttf` (`node video/scripts/get-fonts.mjs`).
  - 시안 기준 속도: 1280×720에서 초당 약 29장 (2분 7초 영상 3,819장에 131초).
- **렌더기 `video/render/` (v4.1):** 공통 부품 `kit.css`(무대·자막 띠 52px·부품)·`kit.js`(`K.S(n)`·`K.E(n)` 문장 시각, `K.W(n, 낱말)` 낱말 시각, `K.scene`·`K.pop`·`K.counter`·그림 부품·`K.chapters`·`K.cut`), 장면 파일 맨 위 데이터 칸 `/*EP-DATA:BEGIN*/…/*EP-DATA:END*/` 는 손으로 쓰지 않는다. 처음 한 번 `cd video/render && npm ci` (GSAP 3.12.5 로컬).
  - `node video/render/render.mjs sync <주제> <영상ID>` — 문장 시각(`tts_narration.json`)·자막(SRT)·길이를 데이터 칸에 (오디오·SRT가 바뀌면 다시)
  - `… check …` — 대표 장면(`K.cut`)마다 글자 36px 이상·자막 띠 겹침·화면 밖 · `… stills …`(저장소 밖 still) · `… extra … --times 12.5,40`
  - `… video … [--workers 3] [--from 0 --to 60]` → `<주제>/out/<영상ID>/final_1080p.mp4` (+ `tools/loudnorm.py` −14 LUFS). 속도: 3 workers 로 영상 1초에 약 0.8초
- **할 일:** `tools/publish.sh`(지금 Remotion용 v1.3)가 이 렌더기를 부르게 바꾼다 — 그 전에는 위 명령을 직접 쓴다. 옛 Remotion 코드(`video/src/`)는 지난 영상 기록으로만 둔다.
- 자막 맞추기는 지금 도구를 그대로 쓴다: `cd video && npm run align-audio -- <주제폴더> <영상ID>` (오디오의 쉼으로 SRT를 맞춤, 옛 SRT는 `.srt.bak-<시각>`).

## 7. 작업 순서 (오디오가 올라온 뒤)
1. `git pull` → `python tools/tts_narration.py check <주제> <영상ID>` (지금 대본·목소리로 만든 오디오인지)
2. `npm run align-audio -- <주제> <영상ID>` → SRT = 영상 시간. 보고의 '확인 필요' 문장은 들어 보고 고친다.
3. **숫자표:** 화면에 쓸 숫자를 대본 문장 번호와 계산 코드 값으로 정리 (index.html 맨 위 상수).
4. **컷 표:** 컷마다 시각(자막 번호)·내레이션·화면·장치(2번)를 index.html 데이터로 쓴다.
5. 장면 코드 → 대표 장면 still (저장소 밖) → 8번 검수표로 스스로 점검·수정 (승인을 기다리지 않는다).
6. 렌더 → 길이·오디오 트랙 확인 → 음량 맞춤 → **압축본을 저장소에** (`python tools/compress_video.py <주제> <영상ID>` → `source/<영상ID>/final_1080p.mp4`) + 업로드 시트 `upload.md` → 사용자가 **Colab 셀 하나**로 비공개 업로드 + 1시간 뒤 예약 공개 (`guides/upload_guide.md` 11번, 사용자 지시 2026-10-15).

## 8. 검수표 (still마다)
- [ ] 화면 숫자가 대본·계산 코드와 같은가. 아직 말하지 않은 숫자가 미리 보이지 않는가
- [ ] 요소가 그 말을 하는 순간에 나오는가 (자막 시각과 맞춤)
- [ ] 한 화면에 생각 하나인가. 지난 장면 요소가 남아 겹치지 않는가
- [ ] 색의 뜻이 맞는가 (빨강 손해 · 청록 아낌 · 노랑 기준)
- [ ] 기준은 노란 점선이고, 넘은 쪽만 빨강인가
- [ ] 글자 36px 이상인가. 그림·글자가 자막 띠(y 900~1040)와 겹치지 않는가
- [ ] 자막이 SRT와 글자 하나 다르지 않은가, 2줄을 넘지 않는가
- [ ] 같은 그림(우산·바구니·부부)이 같은 모양·색으로 다시 나오는가
- [ ] 글자가 잘리거나 겹치지 않는가 (특히 숫자 카운트 중 가장 긴 값)
