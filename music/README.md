# 음악 주제 폴더 (`music/`) — 클라우드에서 분석

VERSION: v1.0 — 2026-10-16 — 새로 만듦 (사용자 지시 2026-10-16: "이 환경은 이제 저장소에 있는 음악 주제 (music 경로 없으면 폴더 만들것)를 유튜브 분석 코드 실행해서 분석하는 환경이야 기존 분석 결과에 이어서 한번 해보고 사용량 초기화 될때마다 분석을 계속 이어서하면 돼 캐시를 저장소에 남겨서 분석 이어서 할 수 있게 하고")

- 목적: 작은 음악 채널의 성공 사례·시청자 니즈(댓글)로 음악 채널의 주제(장르·쓰임새)·제목·썸네일·구성 재료를 만든다 (`guides/pipeline.md` 1단계). 사용자의 작곡 도구(별도 저장소 [`yeomin1024/music-ytb`](https://github.com/yeomin1024/music-ytb) — YuE2 로 노래·연주곡)로 만들 곡을 어떤 채널에 올릴지 정하는 데 쓴다.
- **'기존 분석 결과에 이어서'** = `new/` 분야 탐색(2026-10-16)의 **'15. 수면·힐링 듣기'** — 그 검색 캐시('잠잘때 듣는'·'수면 명상' × 4~20분·20분 넘음 = 4개, 영상 195개, 채널 128곳)를 이 폴더 캐시로 옮겨 그대로 씀 (검색 열쇠가 주제와 상관없어 할당량 0). 그 분야 성공 영상 5개 중 4개가 음악·빗소리였음 (`new/result/niche/niche_scan.md`). 검색어 목록 끝에도 두 말을 남김. (`music-ytb` 저장소에는 유튜브 분석 결과가 없음 — 작곡 도구뿐. 예전 저장소 기록에도 음악 분석 폴더는 없었음.)
- 결과 숫자: `result/outliers/analysis.md` (숫자·원문만 — 해석·규칙 없음). 지시사항은 결과가 모인 뒤 `music/guides/` 에 따로 만든다 (CLAUDE.md — 다른 주제 결과를 빌리지 않음).
- ※ 연구·교육용 분석. 음악 저작권(다른 사람 곡을 모은 플레이리스트의 Content ID·수익 귀속)과 YouTube 수익 정책(반복·대량 생산 콘텐츠, AI 음성·음악 표시)은 채널을 정할 때 따로 확인한다 — 이 분석은 조회수·댓글 숫자만 본다.

## 클라우드에서 분석 (`tools/cloud_run.py`)

웹 화면(`tools/web_ui.py`)의 작업 함수를 그대로 부르므로 분석·추천(체크)·할당량 계산은 PC 와 같다. 명령 설명은 `stock/README.md` '클라우드에서 분석' (주제 이름만 `music`).

```bash
python3 tools/cloud_run.py music status                       # 할당량·탐색 목록·승인 수·남은 것
python3 tools/cloud_run.py music resume                       # 할당량·하루 검색 횟수 때문에 남은 탐색·댓글·채널 기준선
python3 tools/tag_keywords.py music                           # 남은 태그 씨앗 검색만 (2026-10-16 3개 남음 — 검색어 목록은 그대로)
python3 tools/tag_keywords.py music --no-seed-search --write-keywords   # 받은 영상 태그로 검색어 40개 다시 (할당량 0 — 끝의 '이어 받은 검색' 두 줄은 손으로 다시 붙임)
python3 tools/cloud_run.py music explore --weeks 26           # 롱폼 탐색 (검색어 42개 × 4~20분·20분 넘음 = 84번 ≈ 8,400단위 — 캐시된 것은 0)
python3 tools/cloud_run.py music explore --shorts --weeks 26  # 쇼츠 탐색 (롱폼 탐색이 끝난 뒤 — 42번 ≈ 4,200단위)
python3 tools/cloud_run.py music list --checked               # 새 추천 (이미 분석에 쓴 영상은 숨김)
python3 tools/cloud_run.py music uncheck ID …                 # 음악이 아닌 추천 풀기 (낭독·옛날이야기·최면·확언 명상 등)
python3 tools/cloud_run.py music approve                      # 추천 승인 → 설명·자막·썸네일·댓글 → 주별·성공 사례 분석
python3 tools/cloud_run.py music captions                     # 대본 없는 승인 영상의 자막만 다시 (할당량 0)
python3 tools/cloud_run.py music analyze                      # 롱폼·쇼츠 분석 다시 (할당량 0)
```

- **매일 이어서**: 예약 작업 **'음악 분석 이어서 (할당량 초기화 뒤 매일)'** `trig_01RWWyDUkoWgb2t4MEn6oSUR` — 태평양 자정 +25분(한국 16:25, 서머타임 끝나면 17:25)에 이 클라우드 세션(`session_01LPEQZuhdEvMip9o53nnSrK`)을 깨워 (남은 씨앗이 있으면 태그 다시 고르기) → resume → explore(롱폼, 끝나면 쇼츠) → 새 추천 훑기·승인 → captions → analyze → main (`guides/status.md` 2-6). 재테크(+15분)·역사(+20분) 예약 작업과 5분씩 띄움.
- **캐시**: `music/cloud_cache/cache.tgz` (+ 목록 `cache.json`) = `result/outliers/.cache`(검색·영상 정보·채널·업로드 목록·자동완성·쇼츠) + `result/web`(탐색 목록·체크·승인 목록). 명령 뒤 저절로 묶고 새 컨테이너에서 저절로 풂.
- **키**: 이 클라우드 환경 변수 `YOUTUBE_API_KEY` (지문 `616bf1e8`) — 역사·`new/` 키(`58333e86`)와 다른 키. ⚠️ 2026-10-16 첫 회차에서 **검색 6번 만에 '하루 검색 횟수 한도'(429)** — 이 키를 오늘 다른 곳(다른 클라우드 환경일 수 있음)이 먼저 많이 검색했다는 뜻. 단위(10,000)와 하루 검색 횟수(약 90~100번)는 같은 키를 쓰는 곳끼리 나눠 쓴다. 음악만 다른 키를 쓰려면 환경 변수 `YOUTUBE_API_KEY_MUSIC` (`outlier_research.load_api_key` 가 먼저 읽음).
- ⚠️ **PC 웹 화면에서 음악 탭을 켜지 않는다** — PC 가 자기 `music/result/outliers/` 로 GitHub 것을 통째로 바꿔 클라우드가 받은 사례 폴더(`W_…`)가 지워짐 (`guides/pc_analysis.md` '클라우드에서 돌리기'). 음성인식(PC 만)은 그래서 보류 — 연주곡은 말이 없어 음성인식이 있어도 대본이 거의 안 나온다.
- 자막은 클라우드에서 대부분 못 받는다 (YouTube 가 `www.google.com/sorry` 봇 확인으로 돌려보냄 → `ProxyError`, 또는 `RequestBlocked` → 연속 2번이면 6시간 쉼) — 영상 설명으로 대신 분석 (글 출처 '설명').

- **관련어**: 처음 규칙은 4,037개 중 558개를 '음악'으로 봤는데, 230개는 음악 영상이 아닌데 설명란의 배경음악 출처 줄('Music provided by 브금대통령' 등)만으로 걸렸음 → 출처 표현을 먼저 지움 (558 → 384). 약한 관련어에서 'ost'·'cover'(most·discover 에 걸림)·'asmr'(빗소리 캠핑 브이로그)·'듣기·듣는'(영어 듣기)·'라이브'를 빼고 'kpop' 류를 약한 관련어로 (→ 314). 남은 것 중 수면 검색 결과 195개는 음악 119(낭독·오디오북·명상 안내는 빠짐).
- **검색어**: 첫 고르기(씨앗 6개 중 3개만 검색 — 429)는 40개 중 19개가 수면·명상이고 '명상'·'meditation'·'sleep'·'힐링'·'수면유도'·'불면증'·'백색소음' 같은 음악 낱말 없는 말이 10개였음 → `TAG_REQUIRE` 를 음악 낱말로만 좁힘 (주식의 '검색어는 모두 주식 낱말' 규칙과 같은 방식). 지금 40개는 모두 음악 낱말이 들어 있다. ⚖️ 판단: 방송사 음악 프로그램·아이돌·시상식·직캠은 큰 회사 몫이라, 강좌·노래방 MR 은 다른 시장이라 검색어로 고르지 않음 (다른 검색에 걸려 들어오면 분석에는 그대로 셈).

## 한계

- 검색어 42개 중 아직 2개('잠잘때 듣는'·'수면 명상' — 이어 받은 캐시)만 탐색됨 → 첫 회차 추천·성공 사례 15개는 **수면·힐링·찬양·빗소리 쪽에 치우침**. 플레이리스트·카페·공부·가요·K팝 쪽 성공 사례는 남은 검색 80번이 끝나야 들어온다. 비교 집단의 성공 비율 49% 도 수면 검색(조회수 순) 몫이 커서 높게 나온 것 — 묶음 사이 상대 비교로만.
- 태그 씨앗 6개 중 3개(카페음악·피아노 연주·AI 음악)를 아직 검색 못 함 → 검색어 40개가 수면·힐링(12)·'기타 음악'(플레이리스트·BGM 등 20) 쪽으로 기움. 예약 작업 첫 회차(10-17)에 남은 씨앗을 검색하면 **탐색 검색을 하기 전에 한 번** 다시 고른다 (탐색 결과가 쌓인 뒤 고르면 그 검색어 쪽으로 더 기움).
- **3~4분짜리 노래 한 곡(뮤직비디오·음원·커버 한 곡)은 거의 안 들어온다** — 성공 기준이 4분 이상(CLAUDE.md)이고 탐색 검색도 4~20분·20분 넘음만. 세로가 아닌 3분 이하 영상은 쇼츠 분석에도 안 들어감. 이 시장을 보려면 기준·검색 길이를 바꿔야 하므로 사용자에게 먼저 묻는다.
- 외국 영상 꺼짐 — 영상 언어가 한국어가 아니거나 언어 표시 없이 제목에 한글이 없으면 뺌 (첫 탐색 147개 중 34개). 영어 제목만 쓰는 한국 음악 채널도 빠질 수 있다. 음악은 말이 없는 곡이 많아 세계 시장도 볼 만함 → 켤지는 사용자가 정한다.
- 자막·음성인식이 없다 → 대본 근거 없음 (설명으로 대신 — 연주곡은 원래 말이 없다). 승인 20개 중 6개는 연결 실패(`ProxyError`)라 `captions` 로 다시 시도, 14개는 자막 서버 차단(`IpBlocked` 12·`RequestBlocked` 2)이라 규칙상 음성인식 몫(보류).
- 분석 표의 일부 갈래(제목 특징 '손실 낱말'·댓글 '정치·사회' 등)는 재테크용으로 만든 코드 그대로라 음악에는 맞지 않는 칸이 있다 — 숫자로만 읽는다 (분석 로직은 바꾸지 않음 — 사용자 지시 2026-10-16 "분석 로직은 변경하지말고").
- 자료를 받지 않은 성공 후보 47개는 웹 화면처럼 **탐색 목록에 들어온 것만** 추천으로 체크된다 — 남은 검색을 탐색하면 들어올 수 있음. ID 로 바로 승인(`approve ID …`)은 사용자가 말하면.
