## v0.3.0 — 2026-11-26 — 속임수는 노예(암살자) 측만 (v0.2.0 → v0.3.0)

사용자 지시: "노예쪽이 너무 불리한데 속임수를 노예턴에서 사용할 수 있도록 해야될거 같아".

- **턴 종류 = 그 판 진영** (`core/match.gd` `_begin_turn`): 사람이 노예 측인 판 = 매 턴 속임수 턴(상대가 먼저 냄 → 잔 엿보기), 왕 측인 판 = 매 턴 감시 턴(내가 먼저 냄 → 상대 노예가 잔을 엿봄). 진영이 판마다 바뀌어 판 단위로 번갈아 옴 (v0.2.0 의 '전체 턴 번호 홀짝'을 바꿈).
- 까닭: v0.2.0 에서 엿보기는 왕 측에 더 유리 — 왕 측은 한 번 보면 그 턴에 이김(상대가 시민이면 왕, 암살자면 시민), 노예 측은 왕이 나오는 턴을 맞혀야 함.
- AI 엿보기 결정(`core/ai_brain.gd` `decide_peek`): 노예 측이 아니면 엿보지 않음 · 진영 배수 1.3 뺌 (늘 노예 측이라).
- AI 의심(판 결과)은 상대가 노예 측이었던 판에서만 고침 (`match.gd` `_reveal`) — 왕 측은 속일 수 없으니 왕 측 승리로 의심하지 않음.
- 화면 안내(`scenes/main.gd`): 판 시작마다 '속임수 판 / 감시 판' 안내.
- 시험(`tests/run_tests.gd`): `turn_roles` — 1판(왕 측) 모든 턴 = 감시 턴 · 왕 측은 잔을 봐도 엿보기 0 · 2판(노예 측) = 속임수 턴. 속임수 턴 시험은 `_start_cheat()`(2판에서 시작)로.
- 숫자 값(위험률·엿보기 시간 등)은 그대로. 결과: README 5번 (속이는 사람 → 정직 AI 44 → 51% · 노예 측 판 승률(둘 다 속일 때) 0.23 → 0.32).
- 확인: `gdparse` 9개 통과 · 파이썬 사본 시험 25개 통과 · 1,000 매치. Godot 실행은 PC 에서.

### 튜닝 (첫 초안 → v0.1.0) — 시뮬레이션 근거
⚠️ **위험·벌칙 규칙을 바꾼 것** (설계 때 말한 규칙과 다름):
- **들켰을 때 벌금 1점 추가** (`CheatRules.CAUGHT_FINE`, `match.gd` `accuse()`): 설계는 '그 판 몰수 + 경고'만이었음. 벌금이 없으면 속임수형이 정직형을 80 대 20으로 이김(연장·문턱 바꾼 뒤 기준) → 벌금 1점이면 61 대 39. 2점이어도 거의 같아서 1점.
- **뒷면 표시는 다음 턴부터, 턴마다 60%만 보임** (`CheatRules.MARK_READ_CHANCE`, `match.gd` `_begin_turn()`): 100% 면 속임수 1회당 적발률이 0.47로 너무 높고(다 알고 두니 결과가 티 남), 0.6 이면 0.36 (설계 목표 0.25~0.35 근처).

그 밖:
- **동점이면 연장 최대 2판, 진영은 동전 던지기** (`match.gd` `EXTRA_ROUNDS`, `_begin_round()`): 정직 대 정직 무승부 40% → 0%. 처음엔 연장 판을 자리 0 왕 측으로 고정했더니 정직 대 정직이 62 대 38로 기울어서 동전으로 바꿈 → 49 대 51.
- **AI 고발 문턱 기본값 1.0 → 0.0** (`AiBrain.ACCUSE_THRESHOLD_BASE`): 문턱이 높으면 AI 가 거의 고발하지 않아 속임수가 공짜였음. 0.0 에서 정직 대 정직 헛고발은 자리마다 매치당 0.11번.
- **AI 가 손을 볼 기본 확률 0.35 → 0.45** (`AiBrain.GAZE_HANDS_BASE`).
