## 공개 저장소에도 사례 폴더까지 올림 (2026-10-14부터)

사용자 지시 2026-10-14 "그냥 공개에서 다 올리도록 해": 다른 채널의 설명·자막 전문·댓글 전부·썸네일(사례 폴더 `01_…`·`P01_…`·`W_…`)은 **저장소가 공개여도** GitHub 에 올라갑니다 (분석기 v2.9.3 `UPLOAD_CASES_TO_PUBLIC_REPO = true` — 끄려면 `economic/analyzer_config.toml` 에 `UPLOAD_CASES_TO_PUBLIC_REPO = false`). 댓글 파일에는 작성자 이름·채널 ID 가 없습니다 (본문·좋아요·답글 여부·채널 주인 여부만). 영상 파일은 받지 않으므로 올라가지 않습니다 (`ALLOW_VIDEO_UPLOAD_TO_PUBLIC_REPO = false` 그대로).
⚠️ 공개 저장소면 누구나 이 원문을 볼 수 있습니다 — 저작권자가 GitHub 에 삭제 요청(DMCA)을 하면 그 파일이나 저장소가 막힐 수 있습니다. 그럴 때는 아래처럼 비공개로 바꾸면 됩니다.

### 저장소를 비공개로 바꾸기 (선택)
1. GitHub 저장소 화면 → **Settings** → General 맨 아래 **Danger Zone** → **Change repository visibility** → **Make private** → 확인 문구 입력
2. 비공개가 되면 **토큰 없이는 코드를 받을 수 없습니다.** 그래서:
   - PC: `.env`의 `GITHUB_TOKEN`이 꼭 있어야 합니다 (아래 5번). 실행기 v2.1이 그 토큰으로 GitHub API 에서 코드를 받습니다.
   - Kaggle(내레이션): `guides/tts_guide.md` 3번 셀(v1.8)을 그대로 쓰면 Secrets 의 토큰으로 받습니다. 예전 셀은 `git clone`이 실패합니다.
   - Claude Code(클라우드): 세션에 연결된 GitHub 앱으로 받으므로 그대로 됩니다.
3. 비공개여도 올라가는 것은 같습니다 (사례 폴더는 공개일 때도 올라감). 분석기가 영상 파일을 받도록 켜 둔 경우에만 그 영상(49MB 이하로 줄임)이 비공개일 때 추가로 올라갑니다.
(클라우드에서 받으려면 환경 설정 → 네트워크 접근 → 허용 도메인에 `www.youtube.com`·`i.ytimg.com`을 넣어야 합니다. YouTube가 클라우드 IP를 막을 수도 있어 PC가 더 확실합니다.)

## 처음 한 번 (Windows)

1. **Python 3.10 이상** 설치 — [python.org](https://www.python.org/downloads/) 설치 첫 화면에서 **"Add python.exe to PATH"** 체크
2. **Git** 설치 — https://git-scm.com/downloads (결과를 GitHub에 올릴 때 필요. 기본 설정 그대로 "Next")
3. 작업할 폴더를 만듭니다. 예: `문서\ytb`
4. 그 폴더에서 PowerShell을 엽니다 (탐색기 주소창에 `powershell` 입력 후 Enter) → 실행기를 받아 실행합니다.
   - **저장소가 공개일 때:**
     ```powershell
     curl.exe -L -o run_analyzer.ps1 https://raw.githubusercontent.com/yeomin1024/yeomin1024-ytb/main/run_analyzer.ps1
     powershell -ExecutionPolicy Bypass -File run_analyzer.ps1
     ```
     (`curl.exe`는 Windows 10·11 에 들어 있고 PowerShell·명령 프롬프트·Git Bash 어디서나 됩니다. 예전 안내의 `wget … -OutFile`은 PowerShell 에서만 됨)
   - **저장소가 비공개일 때** (첫 줄이 토큰을 물어봄 — 5번의 GITHUB_TOKEN 값을 붙여넣고 Enter):
     ```powershell
     $t = Read-Host "GitHub 토큰"; $r = Invoke-RestMethod -Headers @{Authorization="Bearer $t"} -Uri "https://api.github.com/repos/yeomin1024/yeomin1024-ytb/contents/run_analyzer.ps1?ref=main"; [IO.File]::WriteAllBytes("$PWD\run_analyzer.ps1", [Convert]::FromBase64String($r.content)); Remove-Variable t
     powershell -ExecutionPolicy Bypass -File run_analyzer.ps1
     ```

### 분석 대상 세 묶음 고침 — 구독자당 하루 조회수 · 쇼츠 ② · 기간 없는 검색 ③ (2026-10-28 — success_analysis v1.6 · shorts_analysis v1.3 · web_ui v2.5 · outlier_research v2.7)
사용자 지시: "1은 그렇게하고 최근에 조회수가 높을수록 더 많이 반영되도록 해야해 3은 할당량 남으면 진행하도록 해 나머지는 너가 추천하는 방향으로 하고" (위 확인 결과의 (가)~(라))

- **하루 조회수 = 받은 때 조회수 ÷ 올린 날부터 받은 때까지 날수** (최소 1일 — `orr.views_per_day`). 예전엔 오늘까지 날수로 나눠, 자료가 오래되면 최근 영상이 낮게 셈.
- **① 성공 사례 (롱폼·쇼츠 같음)**: `[success] MIN_VPD_SUBS`(쇼츠 `[shorts]`)가 0 보다 크면 **구독자당 하루 조회수 = 하루 조회수 ÷ 구독자(최소 100) ≥ 그 값** — 주식 0.1 (= 30일에 구독자 × 3, 예전 ×3 을 한 달로 옮긴 값). 롱폼은 올린 지 `MIN_AGE_DAYS`(주식 7)일 뒤부터. 구독자 5만 이하·조회수 1만 이상·180일 안·4분 이상은 그대로. 0 이면 예전 규칙(조회수 ÷ 구독자 ≥ `MIN_RATIO`). 판정은 한 곳 `orr.success_core` — 분석·탐색 추천·주별 분석·확인 엑셀이 같이 씀.
  - **'최근 조회수가 높을수록 더 반영'** = `WEIGHT = "score"`: 성공 사례마다 무게 **1 + log2(점수 ÷ 기준)** (기준의 2배면 2, 4배면 3, 최대 10) → `analysis.md` 2·5번(주제·형식·제목 특징) 에 '성공 사례 몫 · 가중' 칸 (예: "50% · 가중 75%"). 1번 표는 점수 큰 순 + '구독자당 하루 조회수' 칸. 무게를 그대로(점수 ÷ 기준) 쓰면 주식 116개 중 48개가 최대값에 붙어 log2 로. 비교 집단을 하루 조회수로 가중하는 안은 어느 묶음이나 80~90% 로 같아져 버림.
  - 기준 고르기 (2026-10-28 주식, 기준 통과 롱폼·쇼츠): 예전 ×3 = 505·400 · 0.05 = 722·400 · **0.1 = 539·316** · 0.2 = 388·241.
- **② 하루 조회수 상위**: 롱폼 `[vpd_top] MAX_AGE_DAYS`(주식 182 = 탐색 26주) 안만 — 기간 없는 검색의 옛 영상이 '최근 트렌드'에 섞이지 않게. **쇼츠 새로** `[shorts_vpd_top]` (상위 10%, 채널당 2개) → 탐색 추천 '하루 조회수 상위' + `shorts/analysis.md` **1-4번**.
- **③ 조회수 상위 (올린 날짜·구독자 상관없이)**: `[views_top]`·`[shorts_views_top]` `TOP_PCT`(주식 10) → 탐색 추천 '조회수 상위 N%' + `analysis.md` **1-4번** · `shorts/analysis.md` **1-5번** (채널당 2개·그 묶음 니즈·자료 안 받은 후보). 모집단 = 검색에서 찾은 영상 + **기간 없는 검색**.
  - **기간 없는 검색** = 같은 검색어를 `publishedAfter` 없이 (검색어마다 롱폼 2길이 + 쇼츠 1, 캐시 30일 `orr.ALLTIME_TTL_HOURS`). **할당량이 2,000단위(`orr.ALLTIME_RESERVE`) 넘게 남을 때만** — 탐색 마지막 단계에서, 모자라면 남겨 두고 explore.json `pending_alltime` 에 셈. 이어서: `cloud_run.py <주제> resume` (남은 것이 기간 없는 검색뿐이면 2,100단위 넘게 남을 때만) 또는 `explore --alltime-only` (일반 검색은 캐시 그대로 — 만료돼도 다시 안 함, 기간 없는 검색만). 기간 없는 검색 캐시는 시장(3번)·비교 집단·② 에 섞지 않음 (`sa.is_alltime_search`).
- 확인: `python3 tools/target_check.py <주제>` — 판정 '✅ 들어감 (구독자당 하루 조회수)' · ③ '⚠️ 들어감 · 기간 없는 검색 일부만'(남은 검색 있음).
- ⚠️ ③ 은 큰 채널·옛 영상이라 댓글이 많음 (2026-10-28 주식 롱폼 추천 346 — 댓글 약 33만 · 쇼츠 87 — 약 6만) → 승인 댓글은 며칠에 나눠 `comments`/`resume`. 주제 밖 옛 인기 영상(드라마·영화·찬양 '주가'·'국장' 직함·금·환율)은 `[exclude] OFF_TOPIC` · `keywords.toml EXCLUDE_KEYWORDS` · `[shorts_exclude_videos]` 로 뺌.

## 자동 실행 (`-Auto`)에서 일어나는 일

`run_analyzer.ps1 -Auto`(또는 `-Once`·작업 스케줄러)면 실행기가 코드를 최신으로 받고, 설정·검색어 파일은 없을 때 또는 **GitHub 쪽이 새 판(파일 머리 `VERSION`이 더 높음)일 때** 받은 뒤 (예전 파일은 `.bak`) `tools/pc_analysis.py economic`을 실행합니다. 한 **회차**는:

| 순서 | 하는 일 | 할당량 (하루 10,000단위) |
|---|---|---|
| ① 성공 사례 + 조회수 상위 | `tools/outlier_research.py` v1.8 — **`economic/keywords.txt`의 검색어 전부**(지금 36개) × 길이 2(4~20분·20분 넘음) = 검색 72번 → 두 묶음을 골라 **자막·썸네일·설명·댓글**:<br>· **성공 사례 20개** — 최근 180일·구독자 5만 이하·조회수 ≥ 구독자×3·4분 이상 (폴더 `01_<영상ID>`…)<br>· **조회수 상위 20개 — 구독자 수 상관없음**, 주제 관련·4분 이상·최근 365일, 조회수 순 (폴더 `P01_<영상ID>`…)<br>· 댓글은 **1단계 인기 댓글 100개**(모든 사례 먼저) → **2단계 전부**(시간순 + 답글) · **받은 자료 표 `downloads.md`** (영상마다 **업로드 날짜**·자막·댓글·썸네일) | **자동: 검색 수 × 100 + 여유** (재테크 36개 = 7,490) — 첫날 검색·인기 댓글까지 끝 (`ready`). 분석기가 끝난 다음 날부터 9,500 |
| ② 결과 먼저 올리기 | 성공 사례 결과(요약·받은 자료 표·status·사례 폴더 — 공개 저장소에도)를 **분석기보다 먼저** GitHub 에 | 0 |
| ③ 주제 분석 | `youtube_topic_analyzer.py --no-video --defer-whisper` — 같은 검색어로 주제 전체 분석. **영상 파일은 받지 않고**, 자막 없는 성공사례의 음성인식은 ⑥으로 미룸. 이월 검색어 없이 끝나면 다음 회차부터 건너뜀 (7일 안, `--rerun-analyzer`) — **검색어를 바꾸면 다시 돌림** | 오늘 남은 만큼 (최대 `QUOTA_BUDGET` 6,000). **1,000단위가 안 남으면 다음 회차로** (몇백 단위로는 검색 0~1개짜리 빈 결과만 나옴) |
| ④ 보충 | 오늘 할당량이 남았으면 성공 사례 수집을 한 번 더 — 검색은 캐시라 남은 단위가 댓글(2단계)·태그 검색에 감 | 오늘 남은 전부 (10,000 − 200 − 오늘 쓴 양) |
| ⑤ 올리기 | 진행 상태 `pc_progress.json`과 이번 회차 결과를 GitHub `economic/result/`에 (아무것도 안 돌았으면 건너뜀) | 0 |
| ⑥ 음성인식 대기열 | `youtube_topic_analyzer.py --whisper-queue` — 자막이 없는 영상(성공 사례 01 → 조회수 상위 P01 → 분석기 성공사례 순)을 **하나씩**: 소리만 받아 Whisper → 대본 저장(소리 파일은 지움) → 요약·`downloads.md` 다시 → **바로 GitHub 에 올리고 다음 영상**. 실패는 3번까지 다음 회차에 다시. 뒤에서 도니까 길이 제한 없음 | 0 |
| ⑦ 남은 일이 있으면 | **할당량이 초기화될 때까지 기다렸다가 다음 회차** | — |

**댓글은 싸다 (2026-10-13 실측):** 댓글 100개에 1단위, 답글이 5개 넘는 댓글은 1단위씩 더. 조회수 355만 영상의 댓글 **583개 전부(답글 218 포함) = 약 11단위**, 작은 채널 사례 44개 전부 = 3단위. 40개 영상이면 보통 몇백 단위입니다. 하루 할당량의 대부분은 **검색**(1번 100단위 — 검색어 36개면 성공 사례 72번 + 분석기 36번 ≈ 10,800)입니다. 그래서 재테크는 **첫날에 성공 사례 검색·자막·인기 댓글까지 끝나 분석을 시작할 수 있고(`ready`), 둘째 날 분석기와 댓글 전부가 끝납니다** (약 이틀). 쓴 양은 `.yt_work/quota_<주제>.json`(태평양 날짜별)에 적혀, 같은 날 다시 돌려도 남은 만큼만 씁니다. 받기 시작한 뒤 새로 달린 댓글은 빠질 수 있습니다 (시간 순으로 내려가며 받음).

**이어서 돌리기:** 두 도구 모두 받은 검색 결과(7일)·영상 정보·자막·댓글을 PC에 저장해 둡니다. 다음 회차는 받은 것은 할당량 0으로 다시 쓰고 **못 한 부분만 새로 받아** 결과에 더합니다.
- 남은 일 = 할당량 때문에 못 한 검색·영상 정보·댓글 (`economic/result/outliers/status.json`의 `pending`), 분석기의 이월 검색어 (`run_info.json`의 `keywords.deferred`), 네트워크 때문에 못 받은 자막
- **할당량 초기화 = 미국 태평양 시간 자정** → 한국 시간 **오후 4시**(3월 둘째 일요일 ~ 11월 첫 일요일, 서머타임) / **오후 5시**(그 밖). 실행기는 그 **10분 뒤**(16:10 / 17:10)에 다음 회차를 시작합니다.
- 화면 로그 예: `[ROUND] … round=1 complete=False left="성공 사례: 남은 검색 2·… / 분석기: 이월된 검색어 3개" next_round=2026-10-14T16:10+09:00`
- 남은 일에는 **댓글을 아직 다 못 받은 영상**도 들어갑니다 (`status.json`의 `pending.comments`).
- 최대 10회차(10일). 끝나면 `[DONE] … note="못 한 일 없음 — 끝"`.

## 기다리는 방법 둘 중 하나

**A. 창을 열어 두기 (기본)** — 위 명령을 실행해 두고 PowerShell 창을 닫지 않습니다. 남은 일이 있으면 알아서 다음 날 이어서 돌고, 다 끝나면 멈춥니다.
- PC가 **절전 모드**로 들어가면 그동안은 멈춥니다 (깨어나면 바로 이어서). 설정 → 시스템 → 전원 → "절전 모드 전환"을 **안 함**으로 두면 확실합니다.

**B. 작업 스케줄러에 맡기기 (창을 닫아도 됨)**
```powershell
powershell -ExecutionPolicy Bypass -File run_analyzer.ps1 -RegisterTask     # 매일 17:15 에 한 회차씩 (-Once)
powershell -ExecutionPolicy Bypass -File run_analyzer.ps1 -UnregisterTask   # 끄기
```
- 17:15면 서머타임이든 아니든 초기화가 지난 시각입니다. PC가 켜져 있고 로그인돼 있어야 돕니다.
- A와 B를 함께 해도 같은 주제가 두 번 동시에 돌지 않습니다 (잠금 파일 `.yt_work/pc_analysis_economic.lock`).
- macOS/Linux: `bash run_analyzer.sh --print-cron`이 보여 주는 줄을 `crontab -e`에 붙여넣기.

## 검색어 바꾸기

- 검색어는 **`economic/keywords.txt`** 에 **한 줄에 하나씩** 적습니다. 그룹은 필요 없습니다. `#`으로 시작하는 줄은 메모, 빈 줄은 무시, 같은 검색어(띄어쓰기만 다름)는 한 번만 검색합니다. (2026-10-13 사용자 지시 "꼭 그룹을 지정해야하나 검색어만 넣어도 되잖아")
  ```
  # 내 검색어
  재테크
  미국주식
  연금저축
  ```
- **GitHub 에서 고치면 됩니다** (저장소 → `economic/keywords.txt` → 연필 아이콘 → 고치고 Commit). PC 는 **회차를 시작할 때마다** GitHub 에서 설정·검색어를 받아 씁니다 (`tools/pc_analysis.py` v1.7 — 로그 `[SYNC] file=economic/keywords.txt result="GitHub 새 판으로 바꿈"`). `VERSION`을 올릴 필요 없습니다. 지금 돌고 있으면 다음 회차(할당량 초기화 뒤)부터, 바로 쓰려면 창을 닫고 다시 실행.
  - PC 에서 메모장으로 고쳐도 됩니다 — GitHub 쪽이 그대로면 PC 것을 지킵니다 (`result="PC 에서 고친 것 지킴"`). GitHub 쪽도 바뀌면 GitHub 것을 쓰고 PC 것은 `keywords.txt.bak`.
  - 검색어가 바뀌면 분석기도 다시 돕니다 (받은 검색은 캐시 — 새 검색어만 할당량을 씀). 지운 검색어는 더는 검색하지 않습니다.
  - 받지 않게 하려면 `--no-sync`.
- 주제 관련 영상을 가르는 **관련어·제외어**는 `economic/keywords.toml` (`[relevance]`). 이 파일의 `[KEYWORD_GROUPS]`는 `keywords.txt`가 없을 때만 씁니다.
- 할당량: 검색어 1개 = 성공 사례 검색 2번 + 분석기 1번 = 300단위. 하루 10,000이 넘으면 다음 날 자동으로 이어서.
- 태그로 다시 고르기 (Claude 에게 "태그로 검색어 다시 골라줘"): `python tools/tag_keywords.py economic --write-keywords` — 재테크 영상의 태그 중 채널 5곳 이상이 쓴 것을 채널 수 순으로 40개 → `keywords.txt` (있던 것은 `.bak`). 규칙 `economic/tag_rules.toml`(빼는 말 — 경제·뉴스·금리·종목 이름, 사용자가 지운 부동산·코인), 고른 표 [`economic/tag_candidates.md`](../economic/tag_candidates.md).
- 잘된 영상 태그로 검색어를 더 찾는 기능(`--tag-keywords`)은 기본 꺼짐 — 적은 검색어만 검색합니다 (지운 검색어가 태그로 되살아나지 않게).

## 여러 주제를 동시에

주제 폴더마다 **검색어 설정 파일**과 **키 설정 파일**이 따로 있고, 실행기가 주제마다 따로 돌립니다 (`tools/pc_analysis.py` v1.2).

| 파일 (주제마다) | 무엇 | 어디에 |
|---|---|---|
| `<주제>/keywords.txt` | **검색어** — 한 줄에 하나 (분석기·성공 사례 수집이 같이 씀) | GitHub (사용자·Claude 가 고침) → PC 가 **회차마다** 받음 (PC 에서 고친 것은 GitHub 이 그대로면 지킴) |
| `<주제>/keywords.toml` | 주제 관련어·제외어 (`keywords.txt`가 없을 때만 그 안의 검색어 묶음) | 〃 |
| `<주제>/tag_rules.toml` | 태그 → 검색어 규칙 (씨앗·빼는 말·묶음) | 〃 |
| `<주제>/analyzer_config.toml` | 주제 이름·저장 폴더·할당량 `QUOTA_BUDGET`·**외국 영상 `INCLUDE_FOREIGN`(기본 false — v3.1)** 등 | 〃 |
| `<주제>/.env` | 이 주제 키 (`YOUTUBE_API_KEY`·`GITHUB_TOKEN`) — **v3.0: 주제마다 따로** (처음 켤 때 맨 위 `.env` 를 복사해 만듦, 웹 화면 탭의 키 저장은 이 파일만) · **v3.1: 주제마다 다른 키를 넣어도 됨 — 다르면 할당량도 따로** | **PC에만** (git 에 올라가지 않음) |

키를 찾는 순서: `<주제>/.env` → 환경 변수 `YOUTUBE_API_KEY_<주제>`(예: `YOUTUBE_API_KEY_ECONOMIC`) → 맨 위 `.env` → 환경 변수 `YOUTUBE_API_KEY`.

```powershell
powershell -ExecutionPolicy Bypass -File run_analyzer.ps1 -Folder economic,health                 # 두 주제를 동시에
powershell -ExecutionPolicy Bypass -File run_analyzer.ps1 -Folder economic,health -RegisterTask   # 매일 17:15 에 두 주제 한 회차씩
```
macOS/Linux: `bash run_analyzer.sh --folder economic,health`

- 화면 줄 앞에 `[economic]`·`[health]`가 붙습니다. 주제마다 로그 `.yt_work/pc_analysis_<주제>.log`, 진행 `pc_progress_<주제>.json`, 잠금 파일이 따로라 서로 기다리지 않습니다.
- 패키지 준비(설치·yt-dlp 업데이트)는 처음에 한 번만 하고 주제마다 프로세스를 띄웁니다. 분석기의 git 작업 폴더·임시 폴더도 주제마다 따로입니다 (분석기 v2.6.0).
- **할당량:** YouTube 할당량은 Google Cloud **프로젝트**마다 하루 10,000단위입니다. 같은 키(같은 프로젝트)를 쓰는 주제가 N개면 실행기가 **하루 할당량을 N등분**합니다 (성공 사례·분석기 `QUOTA_BUDGET` 모두). 주제마다 다른 키면 나누지 않고 키마다 따로 셉니다 (v3.1 — 위 '주제마다 다른 키'). 남은 부분은 매일 자동으로 이어서 받습니다.
- ⚠️ YouTube API 개발자 정책은 **같은 도구의 할당량을 늘리려고** 프로젝트를 여러 개 만들어 나눠 쓰는 것('sharding')을 금지합니다 — 어기면 할당량 축소·키 회수·계정 정지가 될 수 있습니다 ([정책 안내](https://developers.google.com/youtube/terms/developer-policies-guide)). 할당량이 더 필요하면 Google Cloud 콘솔의 **할당량 증가 신청**(YouTube API 준수 감사)이 정식 방법입니다.

## 문제 해결

- **`git add 실패 (code=128): fatal: detected dubious ownership in repository at '…/.yt_work/_github_clone_<주제>'`** (2026-10-15) → git 이 '이 폴더 주인이 지금 사용자가 아니다'라며 거부한 것입니다. Windows 에서 **관리자 권한으로 연 PowerShell**·드라이브 설정 때문에 새 폴더의 주인이 사용자 대신 'Administrators' 그룹이 되면, 분석기가 방금 받은(clone) 작업 폴더조차 막힙니다. **분석기 v2.14.1 부터** 분석기 자신의 작업 폴더(`.yt_work` 아래)에만 git 에 '믿을 폴더'(`safe.directory`)를 알려 줘서 그대로 올라갑니다 (사용자 git 설정·다른 폴더는 안 건드림). → 창을 닫고 다시 켠 뒤 진행 칸의 **[다시 분석·올리기]**. 그래도 같은 오류면 git 이 아주 옛 판 — [git-scm.com](https://git-scm.com/downloads) 에서 새로 설치하거나 오류 끝에 적힌 `git config --global --add safe.directory "…"` 한 줄을 PowerShell 에 한 번.
- **`PermissionError: [WinError 5] 액세스가 거부되었습니다: …quota_key_….json.tmp -> …quota_key_….json`** (2026-10-15 승인 중) → Windows 는 다른 쪽(웹 화면이 몇 초마다 할당량 장부를 읽음·백신·검색 색인)이 파일을 잠깐 열고 있으면 바꿔치기를 거부합니다. 예전 판은 그 한 번으로 승인 작업이 멈췄습니다. **웹 화면 v2.3.1 · pc_analysis v1.18 부터** 조금씩 늘려 12번(약 4초)까지 다시 하고, 그래도 안 되면 경고(`[QUOTA] … 이번 한 번은 못 적음`)만 남기고 작업은 계속합니다. → 창을 닫고 다시 켠 뒤 **[승인]을 한 번 더** 누르면 이어서 합니다 (이미 받은 설명·자막·썸네일은 다시 받지 않음). 자주 나오면 백신 예외에 분석기 폴더(`.yt_work`)를 넣으세요.
- **`HTTP 429 search: Quota exceeded for quota metric 'Search Queries' and limit 'Search Queries per day'` — 남은 할당량이 3,000 인데?** (2026-10-15 사용자 PC) → Google 은 **단위(하루 10,000)와 따로 '하루 검색 횟수'** 를 셉니다. 단위가 남아도 검색 횟수 한도에 닿으면 **검색만** 막힙니다 (HTTP 429 — 영상 정보·댓글 같은 1단위 요청은 됨). 한도 값은 Google 이 문서에 적어 두지 않았고, 이 저장소 기록으로는 2026-10-09 에 검색 **40번째 뒤**로 막혔습니다 (같은 프로젝트를 쓰는 다른 PC·클라우드 검색도 함께 셈). 화면의 '남은 할당량'은 단위만 세므로 이 한도는 보이지 않았습니다.
  - **웹 화면 v2.3 부터:** 탐색이 오류로 멈추지 않고, 못 한 검색은 남겨 두었다가 **한국 시간 오후 4~5시(태평양 자정) 초기화 뒤 저절로 이어서** 합니다. 그사이 캐시된 검색·영상 정보·댓글·채널 기준선은 계속. 같은 키의 다른 탭도 그날은 검색을 보내지 않습니다.
  - 0번 칸 **'검색 오늘 N번 · 검색 횟수 한도에 닿음 (N번째)'**, 그다음부터는 **'알려진 검색 한도 약 N번/일'** (이 PC 에서 센 수 — 클라우드 등에서 쓴 검색은 몰라 실제보다 작을 수 있음). 4번 칸 예상에도 '검색 횟수 한도를 넘는 만큼은 초기화 뒤'.
  - 줄이는 법: 검색어 줄이기, 외국 영상 끄기(영어 검색어 15개 = 롱폼 30번), 쇼츠 탐색은 다른 날. 검색 캐시(적응형 7~21일)가 있어 다음 탐색은 새 검색이 적습니다. 한도를 늘리려면 Google Cloud 콘솔 → API 및 서비스 → YouTube Data API v3 → **할당량** 에서 확인·증가 신청 (프로젝트를 늘리는 것은 정책 위반).
- **`-File 매개 변수에 대한 인수 '.run_analyzer.ps1'이(가) 없습니다`** (2026-10-13 사용자 PC) → 경로의 `\`가 사라진 것입니다. **Git Bash**(또는 WSL·VS Code 의 bash 터미널)는 `\`를 지워 `.\run_analyzer.ps1`이 `.run_analyzer.ps1`이 됩니다. 그 창에서는 받기 줄(`wget … -OutFile`)도 PowerShell 문법이라 안 돼서 파일이 없을 수도 있습니다.
  1. 창이 **PowerShell**인지 확인 (프롬프트가 `PS C:\…>`로 시작). 아니면 시작 메뉴에서 "Windows PowerShell"을 열고 `cd` 로 작업 폴더로 이동
  2. 파일이 있는지: `dir run_analyzer.ps1` (Git Bash 면 `ls run_analyzer.ps1`). 없으면 `curl.exe -L -o run_analyzer.ps1 https://raw.githubusercontent.com/yeomin1024/yeomin1024-ytb/main/run_analyzer.ps1`
  3. 실행은 `\` 없이: `powershell -ExecutionPolicy Bypass -File run_analyzer.ps1` — PowerShell·명령 프롬프트·Git Bash 어디서나 됩니다
- **자막이 계속 `🔁 막힘`·`IpBlocked`·`HTTP Error 429: Too Many Requests`** (2026-10-14 사용자 PC 로그) → YouTube **자막 서버**가 이 PC 의 IP 에 "요청이 너무 많다(429)"고 답하는 것입니다 (자막 35개 중 26개, 분석기 yt-dlp 자막 8/8). **소리 받기는 됩니다**(음성인식 17/17 성공). 예전에는 이걸 '다음 회차에 다시'로 두어 매일 같은 자막을 또 요청해 차단이 이어졌고, 그 영상들은 음성인식에서도 빠져 대본이 없었습니다. **지금은 저절로**: ① 자막 서버가 막은 영상은 **음성인식 대기열**로 (대본은 Whisper 로) ② **연속 2번 막히면 6시간 동안 모든 도구가 자막 요청을 쉼** (`.yt_work/caption_block.json`, 화면 머리줄에 표시) ③ 자막 요청 사이 1.5~3초 쉼 ④ 분석기는 429 를 같은 클라이언트로 3번 다시 하지 않음. 할 일 없음 — VPN 은 끄세요. (연결 자체가 안 되는 `ProxyError` 등만 다음 회차에 다시)
- **`.venv\Scripts\python.exe: No module named pip`** · **`패키지 설치 실패`** (2026-10-13 사용자 PC) → 가상환경(`.venv`)을 처음 만들 때 끊겨서 `python.exe`만 있고 pip 이 없는 것입니다. **지금은 저절로 고칩니다**: 실행기 v2.4·`tools/pc_analysis.py` v1.6·분석기 v2.7.1이 pip 이 없으면 `python -m ensurepip`로 설치하고, 그래도 안 되면 공식 `get-pip.py`로 설치합니다 (로그 `[SETUP] note="pip 설치됨" how=ensurepip`). 그냥 다시 실행하세요.
  - 그래도 같은 오류면: 실행 폴더의 **`.venv` 폴더를 지우고** 다시 실행 (가상환경을 새로 만듦) — PowerShell: `Remove-Item -Recurse -Force .venv`
  - 그래도 안 되면 python.org 에서 Python 을 다시 설치 (설치 화면에서 **pip** 과 **Add python.exe to PATH** 체크)
- **`YOUTUBE_API_KEY 없음`** → `.env`를 메모장으로 열어 키를 넣고 저장 → 다시 실행
- **`같은 주제 분석이 이미 돌고 있음`** → 다른 창(또는 작업 스케줄러)에서 도는 중입니다. 확실히 멈춘 것이면 `--force`
- **자막이 `RequestBlocked`·`IpBlocked`** → 짧은 시간에 많이 받아 YouTube가 잠시 막은 것입니다. 남은 일로 세어 다음 회차에 다시 받습니다 (VPN은 끄세요).
- **`푸시 건너뜀 reason="GITHUB_TOKEN 없음"`** → `.env`에 토큰을 넣으면 다음 회차에 올라갑니다. 바로 올리려면 `python youtube_topic_analyzer.py --config economic/analyzer_config.toml --push-only`
- **실행기 `받기 실패 … 404`** → 저장소가 비공개인데 토큰이 없거나 그 저장소를 못 읽는 토큰입니다. `.env`의 `GITHUB_TOKEN`, 토큰의 Repository access(`yeomin1024-ytb`)·Contents 권한을 확인하세요.
- **`Permission … denied`** → 토큰의 Contents 권한이 Read and write인지, 저장소가 `yeomin1024-ytb`로 선택됐는지 확인 (`README.md` 문제 해결)
- **PowerShell "스크립트를 실행할 수 없습니다"** → 꼭 `powershell -ExecutionPolicy Bypass -File run_analyzer.ps1` 형태로 실행
